# AWP-03 战败后的重复与冲突结果通知

此夹具只用于隔离存档，不随正式 Mod 发布。将两份 `.txt` 临时复制到 `mod/` 的对应相对路径后冷启动；测试结束移除副本，再冷启动正式构建恢复原等待档。

前置为玩家原始主防、已登记且仍在进行的合格战争。先保护原档，建立独立副本。在游戏战争界面正常投降；夹具只监听真实 `on_war_lost`，本身不宣战、不结束战争、不写旗标。它要求正式 `.621` 已先记录唯一战败；若合并执行顺序不符合前提，日志报 `FAIL|native_defeat_not_recorded_first`，该轮不计通过。

随后通过三个自定义 on_action，直接引用正式 `.621`、`.620`、`.622`，依次注入重复战败、冲突胜利、冲突停战通知。后两者是明确的故障注入，不是实际获得胜利或达成停战。战争来源一直取自原版真实结果回调；三个不同正对照核验玩家、战争标记与主防身份，`always=no` 负对照必须保持未执行。

本机 4.5.1 依据为原版 `common/on_actions/00_on_actions.txt` 的结果作用域声明，以及游戏导出的 `script_documentation/effects.log` 的 `fire_on_action.scopes` 定义。战败／胜利处理器使用 `root` 与 `fromfrom`；停战处理器使用 `fromfromfrom` 与 `fromfromfromfrom`。后者通过独立正对照验证四层来源是否实际传入，不能只凭静态解析判通过。

每轮须保存：

- 原版战败结果窗口、实际过程及游戏日期。
- `native_defeat_callback`、`begin_after_recorded_defeat`、三个不同派发与正对照、`PASS|only_defeat_remains`、`end`，且任何 `FAIL` 为零。
- 前后只读审计；正式结果日志只出现战败，没有胜利或停战。
- 另存的结果档：相对战前基线，主线仅新增战争完成和战败旗标；章节、选择、原有旗标及目标不变。战争应真实结束；不以整个游戏状态不变为预期。

恢复结果档后另存并比较完整主线状态，不能把旧等待窗口自动恢复当作新的入口路由证据。该夹具只覆盖战败优先的结果顺序，其他初始结果、其他参与者及自然战争仍需独立验收。
