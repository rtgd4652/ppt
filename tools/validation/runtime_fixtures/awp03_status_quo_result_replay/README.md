# AWP-03 维持现状后的重复与冲突结果通知

本夹具只用于隔离存档，不随正式 Mod 发布。将两份 `.txt` 临时复制到 `mod/` 的对应相对路径后冷启动；测试结束移除副本，再冷启动正式构建并恢复原等待档。

前置为玩家原始主防、已登记且仍在进行的合格战争。保护原档并建立独立副本，通过原版议和界面使双方接受“维持现状”。夹具只监听真实 `on_status_quo`，本身不宣战、不议和、不写旗标。正式 `.622` 必须先记录唯一维持现状；否则记录 `FAIL|native_status_quo_not_recorded_first`，该轮不计通过。若实际仅触发 `on_status_quo_forced`，此夹具没有覆盖它，不能据缺少日志判游戏错误。

随后三个自定义 on_action 直接引用正式 `.622`、`.620`、`.621`，依次派发重复维持现状、冲突胜利和冲突战败通知。后两者为故障注入，不是真实获得其他结果。战争来源取自真实回调；三个正对照分别验证主防国家及同场战争，`always=no` 负对照不得执行。

本机 4.5.1 原版 `on_status_quo` 的作用域为 `root=提出方`、`from=接收方`、`fromfrom=原始主攻`、`fromfromfrom=原始主防`、`fromfromfromfrom=战争`；正式 `.622` 从主防和战争读取事实。冲突胜负通知在原始主防国家作用域派发，战争仍取自原版停战回调，并用独立正对照验证作用域，不能仅凭静态推断判通过。

预期保存原生维持现状过程、十个夹具标记各一次、前后审计、战后结果档及读档再保存档。正式结果日志仅有一次维持现状写入；所有 `FAIL/BLOCK` 为零。相对战前基线，主线仅新增战争完成及维持现状旗标，原有主线值和攻击者目标不变；战争须实际结束。读档后再次核对完整主线状态及战争块，不把旧等待窗口恢复当作新的章节入口证据。

此夹具仅覆盖维持现状优先且由双方接受的结果顺序，不代替强制维持现状、其他参与者或自然战争验收。当前状态：静态检查已通过；游戏内验证待完成。
