## 已识别的主要架构问题

1. 白夜馆、爱缪莎、赛斯、幽桐和拉比的部分业务仍集中在公共事件与效果文件中。
2. 单一本地化文件已经承载多个功能模块，后续多人协作时容易发生冲突。
3. 旧文件名大量使用 `aemusa_*`，但实际内容已经扩展到整个神器使文明。
4. 新角色、经济、成长、舰船与巨构需要稳定的依赖方向，避免互相反向调用。
5. 当前缺少统一的仓库级静态检查入口。

## 已建立的架构基线

- 使用 `core / white_night / leader_* / economy / progression / destiny_city / fate_observatory / destiny_lord / debug` 模块划分。
- Stellaris 运行目录继续保持扁平，通过 `aemod_<模块>_<对象类型>` 文件名表达所有权。
- 已发布或进入存档的旧 key、事件 ID、flag 和 event target 不做整洁性重命名。
- 白夜馆只承担招募、联络、档案与管理路由，不作为世界观组织。
- 所有 on_action 由单一集成文件统一转发。
- 美术源文件与运行时资源继续分离；图标等统一风格确定后再补齐。
- 迁移按“本地化 → scripted effect → 白夜馆事件 → on_action → 经济成长 → 舰船巨构”逐步进行。
