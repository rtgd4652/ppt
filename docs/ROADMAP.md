# 1.0 开发路线图

更新：2026-09-26。当前状态以 [PROJECT_STATUS](PROJECT_STATUS.md) 为准。以下 M0～M4 是内部交付阶段；对外版本目标为完整 1.0，不新增公开 v0.2／v0.3 承诺。

| 阶段 | 交付内容 | 退出条件 |
| --- | --- | --- |
| M0：可复现基线 | 保存现有工作、统一状态入口、清理失效引用、建立检查命令 | 来源可追溯，检查结果与明确提交或快照绑定；未提交项不得隐瞒 |
| M1：首段完整试玩 | AWP-02 序章至第三章，保留现有文明与四人底座 | AED-T001～004 通过；有正常推进、重复入口、等待和读档证据 |
| M2：银河参与与外部事件 | 依次推进 AWP-03 战争、AWP-04 原版天灾、AWP-05 战后调查 | 每包独立授权、实现、提交与定向测试；适配器读取真实事实 |
| M3：专属危机与结局 | 先 AWP-06 机制底座，再 AWP-07～09 剧情、决定与尾声 | 危机生命周期、不可逆损失、双方决定和结局唯一性通过测试 |
| M4：1.0 发布验收 | 十名角色、必要正式资产、AWP-10～12 全线整合与回归 | 完成发布范围、存档兼容说明和实际验收，再确认发布 |

## 工作包交付方式

- 保留已批准的 AWP-00～12 依赖关系与逐包授权，详见 [工作包基线](design/aemusa_main_story_implementation_work_packages_v1.0.md)。
- 每包提供一个可运行片段：事件／机制、入口、本地化、所需表现、只读审计和测试证据一起交付。
- AWP-10 的最终整合、AWP-11 的全线文本审计和 AWP-12 的最终回归仍保留；各包实现时就完成必要入口、本地化和读档检查，不把基本可用性推迟到最后。
- AWP-03 增加战争事实专项测试，AWP-04／06 增加外部危机适配与生命周期测试，见 [专项计划](../reports/aemusa_main_story_adapter_test_plan_v1.0.md)。
- 章节事实入口不足时明确显示阻断原因，不能通过测试命令伪造正常游玩已完成的历史。

## 角色与美术配套

- 十人名单不变。资料与基础设计已完成的部分不重复重做；新增采集必须对应具体阻塞。
- 角色按章节所需职责和技术风险安排；安托涅瓦、晏华等核心参与者先核对章节接口。叙事出场是否要求可招募领袖实体需逐项确认，不能默认强耦合。
- 新角色复用唯一招募、身份账本与共用入口，个人核心机制单独封装；每完成一名就进行专项验收。
- 按 [资产生产清单](art/ASSET_PRODUCTION_PLAN.md)关联工作包与需求，先验证代表性头像、图标和材质，再批量制作。
- 正式终局载体的名称、外观和实现另行审核；旧舰、旧塔和暂停的隔离原型不能自动恢复。

## 版本与提交

- 原型的十二项核心测试继续作为文明底座回归依据；历史旧舰／旧塔兼容测试与 1.0 正式资产验收分开记录。
- `mod/descriptor.mod` 暂保留 `0.1.0`；其值不能代替测试批次号、Git 提交或快照编号。
- 现有混合工作区先按来源和内容核对。经核对的知识、设计、工具、运行脚本按范围建立中文提交，不整体清理未知改动。
- 发布包仅包含已验收的 `mod/` 运行资产；开发源文件、参考图库、数据库、临时测试与工具不混入发布包。

历史路线图保存在 [原 v0.x 路线图](project/history/roadmap_v0x_before_2026-09-26.md)，不再作为当前执行顺序。
