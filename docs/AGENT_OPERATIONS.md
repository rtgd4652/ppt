## 使用顺序

1. 先确认用户本轮要求。源码或文档任务不需要启动游戏；已收工时不因读到操作命令而恢复测试。
2. 确实需要进游戏时，再检查实际工具、进程、播放集、真实画面和前台。已有群星进程不重复启动；只操作游戏所在屏幕。
3. 选择一个GUI后端。Computer Use可用且适合时使用插件；否则按当前环境和权限评估原生守卫脚本。同一回合不混用两个GUI后端，不能换后端绕过权限拒绝。
4. 脚本返回成功或“Input attempted”不等于游戏收到操作。看实际画面或相关日志后再继续；失焦、PID变化或用户输入干扰时停止发送。
5. 按[测试预算](DEVELOPMENT_WORKFLOW.md)执行。同一操作问题最多排障10分钟，随后记录并转回独立开发；历史help测试和准备命令不重放。

## 原生PowerShell入口

使用PowerShell 7直接调用；不要用Windows PowerShell 5的 `powershell -File`，它曾误读无BOM中文并在发送前解析失败。普通沙盒可能看不到真实桌面，使用当前执行器允许的桌面权限上下文；这不要求把游戏改为管理员运行，也不关闭系统保护。

仅在本轮获准操作游戏且实际选择了原生后端时执行：

```powershell
$ErrorActionPreference = 'Stop'
& '.\tools\desktop\Send-StellarisText.ps1' -Action Inspect
& '.\tools\desktop\Send-StellarisText.ps1' -Action Activate -Label game_current
```

`Inspect`读取真实进程和窗口；`Activate`尝试置前并生成截图，拒绝时不发送输入。`Capture`只截已识别的游戏窗口。查看返回PNG，再确定下一步，不只看退出码。

启动优先通过Steam的群星入口，已有进程不重复启动。先保存所需成果再正常请求关闭窗口；遇保存提示时处理，不能强杀未保存进程。启动器自动操作不可用时，只有确实需要该步才让用户点“开始”，不持续试旧坐标。

- 按本次已授权测试需要生成新的UTF-8命令文件。R3d使用两个ASCII空格前导成功，属于可复用条件，但仍须看实际输入，不把空格当作免检修复。

## 点击、滚轮与暂停

`Invoke-StellarisClick.ps1`要求 `-X`、`-Y`、`-ReferenceImage`、`-ExpectedGameProcessId`。坐标按整张实际游戏窗口截图归一化（含标题区）；脚本会拒绝客户区外、身份不符、失焦、尺寸变化或过期截图。

默认参考图120秒；明确观察为暂停且实时守卫确认时可显式使用 `-MaxReferenceAgeSeconds 600`。每次画面变化后重新观察，不以放宽时间来批量盲点。`-HoverOnly`只悬停，`-Scroll`滚动（负数向下）。

`-EnsurePaused`只适用于已经核实的暂停按钮布局，使用实时像素判断，已暂停不再点击；未知图标会停止。不能把历史按钮坐标当成所有窗口的固定位置。短段运行后确认暂停，原版弹窗也可能自动暂停。

历史成功入口是在插件要求的JavaScript环境中导入 `@oai/sky`，`list_windows`定位唯一群星，`get_window`取得返回对象，置前并 `get_window_state` 后观察／动作／刷新。另一AI没有该JavaScript环境时，不应凭空假设存在同名工具。

元数据写着群星但画面显示聊天或其他应用时立即停止。遇到用户输入干扰先重新观察；遇明确停止或权限拒绝不重复调用或改用原生后端绕过。插件使用回合内GUI只用插件；源码、日志、Git及存档文件读取不属于GUI混用。

## 常见失败的最短处理

| 情况 | 处理 |
| --- | --- |
| 置前失败 | 不发送按键；确需继续时请用户回复后点击群星，再重新观察 |
| 脚本成功但画面未变 | 记录“尝试未证实接收”，检查焦点和输入行；有副作用的命令不直接重发 |
| 名称输入失败 | 日期名未占用就正常另存；必须指定名称才请用户一次输入 |
| 保存位已满 | 不删除原档；仅无损归档已被结果取代的自建中间档，记录原／新位置 |
| 缺插件或GUI通道 | 先核对内置／已连接能力，确有需要则按用户授权查找并走安装连接流程；同时评估允许的已验证后备入口，继续独立的源码工作 |
| 自动审批拒绝 | 记录被拒动作和原因，使用已授权的安全替代或说明阻塞；不关闭守卫或换工具绕过 |
| 日志报错、崩溃或读取失败 | 保留具体错误和未完成状态；按严重性处理，不把干净日志或静态PASS当运行通过 |
