# 爱缪莎 1.0 主线实现接口契约

## 0. 文档职责

本文把已批准的 [`aemusa_main_story_event_decomposition_v1.0.md`](aemusa_main_story_event_decomposition_v1.0.md) 转换为未来代码阶段的接口边界。它只规定模块如何交换已经成立的事实，不定义 Stellaris 事件正文、触发器、效果、数值或本地化。

本文不授权：

- 在 `mod/` 下创建或修改脚本；
- 注册事件 namespace、on_action、局势、特殊项目或危机国家；
- 创建正式 flag、variable、event target 或 scripted trigger/effect；
- 恢复专属舰原型、旧命运观测塔或任何正式资产方案。

## 1. 接口设计原则

1. 主线编排器只能读取外部模块已经结算的事实，不能替外部模块制造胜利。
2. 外部模块只能回传最小结果，不得直接推进后续章节或授予终局权限。
3. 入口检查、剧情展示、玩家选择、机制执行、结算和审计分别承担职责。
4. 所有写接口必须声明状态所有者、前置、唯一结算保护和失败出口。
5. 所有读接口默认只读；名字中没有明确写入语义的接口不得改变状态。
6. 临时窗口、舰队、领袖对象和场景目标不能作为路线唯一权威来源。
7. 接口返回“条件不足”时必须携带可解释原因，不允许静默补条件。
8. 本文中的名称均为候选接口名，只有后续状态命名审核和代码授权后才能成为正式 key。

## 2. 模块边界

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| 主线编排器 | 章节顺序、事件簇入口、暂停、恢复、结局分流 | 直接制造战争或危机胜利 |
| 白夜馆入口 | 打开主线入口、回顾、状态提示 | 持有主线唯一进度、重复发放结算 |
| 角色通讯 | 角色叙事、私人选择、知情层展示 | 代替玩家决定、代替危机机制 |
| 历史账本 | 保存章节、战争、危机和结局事实 | 根据年份猜测历史 |
| 关系与责任账本 | 保存互信、分歧、牺牲、修复 | 用单一好感度决定爱缪莎选择 |
| 原版危机适配器 | 单局择一、读取原版危机开始／完成事实 | 改写原版危机身份、同时开启多种候选 |
| 专属危机适配器 | 连接危机状态机、锚点、巨构职责与最终结果 | 把危机写成人格敌国、自动生成终局权限 |
| 真相层级服务 | 控制不同主体能读取的信息层 | 自动让全体知道玩家层真相 |
| 双方决定服务 | 分别记录玩家决定与爱缪莎决定 | 单按钮写入双方同意 |
| 唯一结算服务 | 防止奖励、损失、身份和结局重复结算 | 猜测或修复缺失决定 |
| 一致性审计器 | 发现冲突、重建表现、硬阻断非法推进 | 自动选择“最合理”历史 |
| 资产解析层 | 根据已批准资产登记返回表现资源 | 把历史旧案当作正式资产 |

## 3. 通用接口返回结构

未来接口无论由 scripted trigger、scripted effect、事件或局势实现，都应在设计层等价返回以下信息：

| 字段 | 含义 |
| --- | --- |
| `result` | `allowed`、`paused`、`blocked`、`completed`、`conflict` 之一 |
| `reason` | 可本地化的最小原因类别，不直接写完整对白 |
| `owner` | 权威状态属于国家、角色、玩家决定、危机还是临时表现 |
| `current_state` | 当前合法状态快照 |
| `required_state` | 继续推进所需的最小条件 |
| `is_recoverable` | 是否允许通过真实条件恢复 |
| `is_irreversible` | 是否涉及永久拒绝、损失、失败、身份或结局 |
| `settlement_guard` | 是否已有唯一结算保护 |
| `visibility_tier` | 当前调用者允许读取的信息层级 |

Clausewitz 脚本不一定以对象形式返回这些字段，但实现和测试必须能逐项证明对应语义存在。

## 4. 主线编排接口

### 4.1 只读入口接口

| 候选接口 | 输入 | 输出职责 | 禁止副作用 |
| --- | --- | --- | --- |
| `can_enter_story_cluster` | 国家、规划编号 | 合法、暂停、已完成或冲突 | 不补前置、不写开始状态 |
| `get_nearest_legal_story_entry` | 国家 | 最近可继续事件簇 | 不倒退历史、不重置章节 |
| `get_story_block_reason` | 国家、规划编号 | 最小阻断原因与恢复类型 | 不把未知条件显示为剧透 |
| `has_completed_story_cluster` | 国家、规划编号 | 是否已完成／已结算 | 不根据窗口已读推断 |
| `can_replay_story_presentation` | 国家、规划编号 | 是否只允许表现性重放 | 不重放选择和结算 |

### 4.2 写入接口

| 候选接口 | 唯一职责 | 必须前置 | 必须保护 |
| --- | --- | --- | --- |
| `begin_story_cluster` | 从未开始进入进行中 | 入口只读检查通过 | 已开始／完成／结算拒绝重复 |
| `complete_story_cluster` | 记录叙事与选择步骤结束 | 所有必需子步骤完成 | 不发放最终结算 |
| `settle_story_cluster_once` | 执行一次不可逆写入 | 已完成且未结算 | 唯一结算标记 |
| `pause_story_cluster` | 写入可恢复暂停原因 | 允许暂停 | 不改写为拒绝或失败 |
| `resume_story_cluster` | 清除已满足的暂停原因 | 真实恢复条件成立 | 不删除损失和历史 |
| `close_story_route_irreversibly` | 写入永久拒绝／失败／结局 | 对应明确事实存在 | 二次确认和冲突审计 |

## 5. 白夜馆与通讯接口

白夜馆只作为功能入口，不持有世界观组织权力。

| 接口职责 | 行为 |
| --- | --- |
| 打开主线 | 读取最近合法入口并进入相应事件簇 |
| 查看进度 | 展示玩家当前允许知道的章节、暂停和历史摘要 |
| 回顾内容 | 只重放允许重放的叙事表现 |
| 查看资格 | 展示真实可见的等级、责任和历史缺口 |
| 恢复通讯 | 在角色或入口恢复后重新连接现有进度 |

白夜馆不得：

- 直接设置章节完成、危机胜利或双方决定；
- 在永久拒绝后重新提出同一授权；
- 通过列表刷新重复生成爱缪莎或主线对象；
- 把未公开的玩家层真相显示在公共档案中。

## 6. 原版危机适配接口

### 6.1 输入事实

- 原版危机身份属于四种获准候选之一；
- 本局尚未锁定其他原版危机模块；
- 原版系统已经提供可验证的开始、阶段和完成事实；
- 玩家文明现实贡献来自游戏内行动，不由主线文本伪造。

### 6.2 输出事实

- 本局唯一候选已锁定；
- 危机开始、参与、完成和战后复盘资格；
- 玩家与文明的现实贡献摘要；
- 允许进入首次主动干涉及后续章节的资格。

### 6.3 禁止行为

- 同一存档切换或完成多个候选模块；
- 主线自行杀死危机势力后宣称玩家完成；
- 只凭年份、科技或舰队规模写入危机完成；
- 把原版危机胜利直接转换为命运主宰权限。

## 7. 专属危机适配接口

| 接口方向 | 最小事实 |
| --- | --- |
| 主线 → 危机 | 第十章共同应对授权、准备状态、权利边界、每局未初始化 |
| 危机 → 主线 | 征兆阶段、锚点生命周期、无人格投影、局部结果、损失、弱点资料、危机唯一结算 |
| 巨构 → 危机 | 现实基线、观测协调、弱点解析可用／占领暂停／恢复 |
| 危机 → 巨构 | 新证据、已验证资料、公开状态、占领前后解析职责 |
| 局部恒定职责 → 危机 | 现场局部命运恒定和可处理窗口已经成立 |

适配器只接收“局部恒定职责已满足”，不得要求旧专属舰原型、唯一舰、独立编队、摧毁重现或旧模型存在。

危机结算输出只能是：

- 危机胜利／不可逆失败；
- 永久损失和被救目标；
- 已验证并公开的弱点资料；
- 第十四章真相调查与最终沟通资格。

不得输出完整命运权限、世界差异真相或双方同意。

## 8. 真相层级接口

| 层级 | 允许读取者 | 典型内容 | 接口约束 |
| --- | --- | --- | --- |
| 文明可验证层 | 中央庭与文明 | 危机事实、损失、弱点、命运去人格化规律 | 可公开但需记录范围 |
| 终局互认层 | 爱缪莎与玩家 | 世界差异、跨世界连续互认 | 危机后才可建立 |
| 角色知情层 | 各角色分别 | 与其证据、职责和经历相符的信息 | 不因国家权限自动同步 |
| 开放谜团层 | 设计账本 | 世界重构、连续机制、命运起源等 | 只能登记为未知 |

所有事件、本地化、日志、提示和 UI 在读取文本前都必须通过层级检查。表现层不得绕开真相服务直接读取高层内容。

## 9. 双方决定接口

### 9.1 玩家决定

- 输入：第十五章沟通资格、已读权限边界、当前决定状态。
- 合法写入：暂缓、玩家拒绝、授权待回应。
- 非法写入：爱缪莎拒绝、双方同意、命运主宰身份。

### 9.2 爱缪莎决定

- 输入：授权待回应、完整信息、自由判断条件、角色历史。
- 合法写入：爱缪莎拒绝、双方同意中的角色接受事实。
- 非法写入：玩家授权、玩家拒绝、系统默认同意。

### 9.3 双重确认

双重确认接口只验证两个独立事实是否同时存在。它不得：

- 创建缺失的玩家授权；
- 创建缺失的爱缪莎接受；
- 用等级、关系、资源或超时推断同意；
- 在确认时直接授予完整权限。

## 10. 唯一结算接口

任何一次性操作调用前必须依次通过：

1. 权威所有者存在；
2. 合法前置成立；
3. 不可逆结果尚未结算；
4. 互斥结果不存在；
5. 写入对象仍有效或存在批准的替代保存方式；
6. 写入后能够立即再次审计为一致。

结算完成后必须保留只读证据，至少能回答：何时结算、由哪个事件簇结算、结算了什么类别、为何不能重复。

## 11. 一致性审计接口

审计器至少提供：

- 全线账本一致性检查；
- 单章入口检查；
- 六种双方决定互斥检查；
- 四种原版天灾候选互斥检查；
- 专属危机单次初始化与结算检查；
- 真相层级泄露检查；
- 命运主宰权限起效时间检查；
- 结局与尾声合法性检查；
- 暂停旧资产引用检查。

审计输出只能分为：一致、可恢复表现问题、可恢复资格问题、不可逆状态冲突。最后一类必须硬阻断。

## 12. 资产解析接口

资产解析必须读取未来正式资产登记，而不是直接写死历史文件路径。

| 资产阶段 | 允许职责 | 当前状态 |
| --- | --- | --- |
| 爱缪莎基础形态 | 序章和日常通讯 | 已有资源仍需独立审核 |
| 30 级成熟形态 | 第十四、十五章成熟表现 | 不等于终局形态 |
| 命运主宰终局形态 | 第十六章合法转变后 | 正式设计待审 |
| 局部恒定载体 | 专属危机现场职责 | 形式待审，旧舰原型暂停 |
| 专属巨构 | 现实基线、协调、弱点解析 | 名称、造型、机制待审 |
| 危机投影 | 无人格规则投影 | 正式视觉待审 |

解析失败时使用不泄露信息的通用占位或硬阻断，不得自动回退到旧 Stage 9、隔离原型或旧命运观测塔。

## 13. 调试与迁移接口边界

未来调试接口只能：

- 读取并打印状态；
- 重建可从权威账本推导的窗口和表现；
- 清理不具权威性的临时对象；
- 在明确测试存档中注入单项测试前置，并留下测试标记。

未来调试接口不得：

- 在正式存档伪造玩家授权或爱缪莎接受／拒绝；
- 自动补齐战争、危机、真相或结局历史；
- 清除永久损失和拒绝；
- 将测试注入结果当作正常路线验收证据。

## 14. AII-R001 审核记录

请审核：

1. 是否批准十二个模块的职责边界，并禁止白夜馆、通讯、危机适配器或资产层持有路线唯一事实；
2. 是否批准通用接口返回结构必须表达结果、原因、所有者、可恢复性、不可逆性、唯一结算和信息层级；
3. 是否批准主线入口只读、写入接口分离，并禁止入口检查顺带补前置或结算；
4. 是否批准原版危机与专属危机只回传经验证事实，危机胜利不得直接输出终局权限和真相；
5. 是否批准真相层级检查覆盖事件、本地化、日志、提示和 UI；
6. 是否批准玩家决定、爱缪莎决定和双重确认使用三个独立接口边界；
7. 是否批准唯一结算、一致性审计、资产解析及调试迁移边界；
8. 是否确认本文仍不授权创建正式 key 或修改 `mod/`。

审核结果：2026-08-16 用户明确批准。十二个模块的职责边界、通用接口返回语义、只读入口与写入接口分离、原版／专属危机最小事实适配、四层真相读取、玩家与爱缪莎双向决定、唯一结算、一致性审计、资产解析和调试迁移边界正式锁定。

本文自此成为爱缪莎 1.0 主线实现接口基线。`implementation_authorized` 继续保持 `false`，本批准不创建正式 key、不修改 `mod/`，也不授权编写事件脚本。
