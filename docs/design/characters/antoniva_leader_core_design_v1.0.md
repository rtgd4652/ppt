# 安托涅瓦 1.0 领袖职业与核心机制设计

## 1. 文档目的

本文只确定安托涅瓦在 1.0 中的固定身份、领袖职业和唯一核心机制，作为后续脚本设计的输入。

本文不包含数值、事件脚本、界面实现、正式图标或最终美术资产。所有方案须经人工整体批准后，才能进入机制实现。

## 2. 证据与约束基线

- 安托涅瓦是中央庭核心领袖，也是《群星》开局国家的正式元首。
- 玩家承载指挥使身份和文明行动权，但不是取代安托涅瓦的国家元首。
- 晏华负责现实分析、战略判断和秩序辅助；爱缪莎负责未来趋势、概率和可能性观测辅助。
- 安托涅瓦的神器是“方舟・诺亚方舟”，核心意象是空间、庇护、收容、有限选择和灾后希望。
- 方舟能够跨越时间与空间，并能将敌人流放至无尽虚空。
- 安托涅瓦曾使用方舟进行空间传送，突袭希罗控制的区域并夺回黑核；因此战略机动与直接战斗介入都是她的原作能力，而不是 Mod 自行追加的职能。
- 她不是神、君主、中央庭所有者或能够独自拯救一切的万能角色。
- 方舟不能被解释为无限收容、无代价救援、全帝国瞬移或绝对安全。
- 1.0 每名神器使只保留一个核心机制，不使用多个松散加成堆出角色强度。

## 3. 固定身份

### 3.1 世界观身份

固定为：**中央庭核心领袖／国家元首**。

安托涅瓦代表的不是个人统治，而是中央庭制度在灾后重建与星际时代中的公共责任。她负责带领文明前进、协调制度并承担最终的政治责任；她的神器能力不能替代国家机构、科研体系和社会共同决策。

### 3.2 与玩家的关系

- 安托涅瓦在通讯中称玩家为“指挥使”。
- 指挥使负责作出游戏中的战略选择并承担结果。
- 安托涅瓦负责以国家元首身份说明中央庭立场、提出公共责任并组织执行。
- 二者是“文明领袖与行动决策者”的协作关系，不互相覆盖身份。

## 4. 领袖定位与职业边界

### 4.1 正式定位

- 对外显示身份：**中央庭领袖**。
- 国家职务：**统治者／国家元首**。
- 神器使身份：**能够直接运用方舟改变时空条件的强大神器使**。
- Stellaris 底层领袖职业：**暂不在叙事设计阶段固定，等待实现可行性验证**；按照 1.0 公共规则，指挥官形态必须可用，但不能成为定义她全部身份的唯一职业。

### 4.2 不固定单一原版职业的理由

1. 国家元首是安托涅瓦的制度身份，不代表她只是一名行政人员。
2. 她同时是能够亲自进入危机现场、以方舟控制空间并保护同伴的强大神器使。
3. 行政官只能覆盖文明治理，无法完整表现她的研究协调与时空战斗能力。
4. 科学家只能覆盖异常研究，无法完整表现她的国家责任与直接战斗介入。
5. 指挥官只能覆盖战场行动，无法完整表现她的治理职责与中央庭领袖身份。
6. 因此，原版 class 只能作为引擎兼容层；角色能力、通讯和机制必须围绕“中央庭领袖＋方舟神器使”设计，不能由 class 反向决定人物定位。

### 4.3 实现原则

- 安托涅瓦应始终保有国家元首身份，不因方舟进入战场而永久离开中央庭治理结构。
- 方舟机制可以由统治者、国家、殖民地与舰队作用域共同承载，不要求把她永久编入某一支舰队。
- 如果 Stellaris 必须选择一个底层 class，应在最小原型中比较行政官、科学家和指挥官的界面、议会、舰队及存读档行为，再选择技术风险最低的载体。
- 无论最终底层 class 是什么，都不得把她的可见名称、角色说明和全部效果写成该职业的普通强化版。
- 不采用为切换职业而反复销毁并重建安托涅瓦实体的高风险方案，除非后续原型证明唯一身份、元首席位和持久化引用均可稳定保存。

### 4.4 明确排除

- 不把安托涅瓦定义成普通行政官、普通科学家或普通指挥官。
- 不以单一职业的可用 modifier 范围删减她已经确认的原作能力。
- 不用三个独立 trait 分别制造“行政版、科研版、战斗版”安托涅瓦。
- 不因她亲自参加战斗而让她脱离国家元首席位。

## 5. 唯一核心机制：方舟时空支配

### 5.1 核心定义

**方舟时空支配**：安托涅瓦以方舟建立受她控制的时空通路与隔离空间。她可以借此跨越常规路线实施突袭、为友军建立庇护与撤离通道，或将敌人从当前战场放逐至无尽虚空。

战略传送、文明庇护和空间放逐不是三套互不相关的能力，而是同一个方舟权能对“通路、容纳与隔离”的不同运用。1.0 应使用同一套方舟状态、限制和持久化记录管理这些表现，避免拆成多个无关 trait。

### 5.2 第一版玩法结构

1. 安托涅瓦是方舟权能的唯一人物核心；国家、殖民地和受指定舰队可以成为其作用目标，但不要求她永久担任普通舰队指挥官。
2. **战略穿界**：在满足目标情报、通路校准和使用条件时，方舟可以绕过常规超空间航道，把安托涅瓦的行动力量传送到指定区域，表现原作中的空间突袭能力。
3. **方舟庇护**：方舟可以为遭遇战争、灾害或其他严重危机的有限目标建立隔离空间、撤离通道或临时安全余地。
4. **虚空放逐**：战斗中可以把敌方目标从当前空间隔离或放逐。永久消灭、暂时移出战斗或对特殊目标失效等实现边界，留到机制可行性与平衡审核决定。
5. 三种表现共享同一套方舟使用状态，不能同时无限发动；发动其中一种会影响其他用途的可用性。
6. 方舟权能不消除已经发生的损失，也不保证殖民地或舰队绝对不会失败。
7. 使用目标、范围、准备、消耗和再次发动条件必须受到明确限制，不能退化为无成本的全图按钮。

具体触发条件、效果类型、持续时间、冷却和成本留到 Stellaris 4.4.3 可行性设计阶段决定。

### 5.3 叙事意义

- “方舟”保存的不是抽象数值，而是文明继续作出选择的资格。
- 只能指定有限目标，使“保护谁、何时保护、如何承担未被保护区域的责任”成为真实决策。
- 安托涅瓦提供空间庇护，但庇护后的救援、重建和制度恢复仍由中央庭与玩家文明共同完成。
- 当她亲自进入战场时，方舟时空支配应成为足以改变局部战局的强大能力，而不是普通舰队加成换名。
- 她的强大主要表现为空间规则控制、友军保护和战场条件改写，不等于单纯追求最高武器伤害。
- 该机制表现希望，但不把灾难和牺牲轻易浪漫化。

### 5.4 明确能力边界

方舟庇护不能：

- 让所有殖民地永久免疫损失。
- 复活已经死亡的人口或撤销已经发生的历史。
- 无条件阻止星球陷落、毁灭或占领。
- 在没有目标信息、校准、准备或代价的情况下无限进行全银河传送。
- 因“跨越时间”而自由改写已经发生的历史、复活所有死者或任意重置时间线。
- 取代运输、救援、医疗、军事防御和灾后重建系统。
- 证明方舟空间与黑门、箱庭或世界之主具有同一来源。
- 让安托涅瓦独自决定谁值得被拯救。

## 6. 1.0 实装边界

### 进入 1.0

- 安托涅瓦作为中央庭国家元首和独特领袖出现。
- 固定“中央庭领袖／国家元首／强大神器使”三重定位；底层 class 在原型测试后确定。
- 一个统一表现战略穿界、方舟庇护与虚空放逐的“方舟时空支配”核心机制。
- 白夜馆中的档案、联络与状态展示。
- 唯一身份、持久化引用、读档和死亡边界处理。

### 暂不进入 1.0

- 多职业切换。
- 全帝国空间传送网络。
- 完整方舟巨构或建筑链。
- 以安托涅瓦为主角的另一条大型个人主线。
- 对方舟本质、跨世界关系或箱庭结构作最终解释。
- 额外的科研、舰队撤离、异常调查等第二套独立机制。

## 7. 与其他核心角色的区分

| 角色 | 制度位置 | 信息／能力方向 | 1.0 核心区别 |
| --- | --- | --- | --- |
| 安托涅瓦 | 中央庭核心领袖、国家元首 | 时空穿越、空间放逐、文明庇护、公共责任 | 以方舟时空支配改变局部现实并为文明保留未来 |
| 晏华 | 战略与秩序辅助者 | 现实分析、局势判断、规划 | 帮助中央庭在有限信息下作出可承担的判断 |
| 爱缪莎 | 未来观测辅助者、个人主线主角 | 可能性、概率、命运观测 | 从观察未来逐步成长到主线终局的命运主宰 |

三者不能共享同一种 trait 模板，也不能写成平级统治三角。
