# AWP-03 失落帝国战争事实适配与资格判定方案

## 1. 本轮依据与范围

AWP-02 的 AED-T001～T004 已通过，见 [验收报告](../../reports/aemusa_main_story_awp_02_validation_report.md)。用户于 2026-09-27 选择先推进 AWP-03，并批准本文件的保守参战与结果资格口径。第四章的真实干预来源和运行验证仍待证明，不把未证实来源当作既定叙事。

已批准的[第四至第六章制作卡](aemusa_main_story_production_matrix_v1.0.md)规定：某个失落帝国按自身立场干预玩家；第五章位于其觉醒并向玩家文明宣战后的战争主体阶段；第六章保留伤亡、制度责任与恢复期。主线不得制造战争或胜利。现有[专项测试计划](../../reports/aemusa_main_story_adapter_test_plan_v1.0.md)明确要求 FEA-02 的参战资格和 FEA-03 的结果资格先由适配设计批准，缺失时保持阻断。

## 2. 已核实的 4.5.1 脚本入口

以下来自本机 Stellaris 4.5.1 原版 `F:/steam/steamapps/common/Stellaris/common/on_actions/00_on_actions.txt`，只是脚本声明的作用域，尚未通过本 Mod 的运行测试：

| 回调 | 原版注释中的作用域 | 本包可记录的事实 |
| --- | --- | --- |
| `on_war_beginning`（2595～2621 行） | 每个参战国家执行；`Root` 为国家，`From` 为战争 | 真实开战；同一战争会对多个国家触发，必须限定玩家与唯一写入 |
| `on_entering_war`（2017～2024 行） | `This` 为晚加入的国家，`From` 为敌方战争领袖 | 晚加入事实；不能直接推断玩家是原始防守方 |
| `on_war_won`（3112～3146 行） | `Root` 为胜方战争领袖，`From` 为败方领袖，`FromFrom` 为战争 | 可候选为“玩家以战争领袖身份获胜” |
| `on_war_lost`（3147～3161 行） | `Root` 为败方战争领袖，`From` 为胜方领袖，`FromFrom` 为战争 | 战败事实；不能写入胜利 |
| `on_status_quo`／`on_status_quo_forced`（3163～3199 行） | 包含主攻、防双方及战争作用域 | 维持现状事实；不等于获胜 |
| `on_war_ended`（2623～2646 行） | `Root` 为败方，`From` 为主要胜方；此回调未声明战争作用域 | 结束可作辅助审计，不作为唯一胜利或战争身份来源 |

原版 `common/scripted_triggers/00_scripted_triggers.txt` 分开识别 `fallen_empire` 与 `awakened_fallen_empire`；不能仅凭泛称“失落帝国”推断两者均满足第五章。原版存在战争对象标记的使用例（`set_war_flag`、`has_war_flag`），但本包还需在目标回调中实测标记能否随存档和结束回调正确匹配。

第四章的干预事实可参考原版 `events/fallen_empire_tasks_events.txt`：`fallen_empires_tasks.3` 在玩家国家写 `fe_xenophile_asked_pop`，选择符合条件的亲外失落帝国作为 `FallenEmpireTaskOrigin` 并打开要求事件 `.4`（704～807 行）。这证明存在具体要求与主体，但该例只覆盖一个事件；临时事件目标能否在关闭窗口及读档后可靠锁定、其他意识形态有何等价来源，都还未证明。不能把这一例推广为全部失落帝国的通用前置。

另一组候选位于原版 `events/fallen_empire_events.txt`：`fallen_empires.3` 会按失落帝国自身条件向玩家派发 `.4`～`.8` 要求事件，事件携带 `from = root.owner`（90～181 行）。`fe_demand_made` 与拒绝要求的意见修正也出现在该流程中。它们提供可调查的具体外交来源，但通用 `on_action` 清单未给出“玩家收到任一此类要求”的直接回调；仅看到旗标或敌意不能保证恢复具体发起者。因此先验证非侵入式读取路径，再决定第四章如何自动启动，不能覆盖原版事件来换取一个方便的入口。

现已核对原版 `.4`～`.8` 的拒绝选项会对发起者写 `opinion_refused_fallen_empire_demand`；部分原版任务请求会对发起者写 `opinion_refused_fallen_empire_request` 或 `opinion_accepted_fallen_empire_request`。本包逐月仅从这些修正反查失落帝国和玩家；候选主体唯一时锁定，多个失落帝国同时留下修正时只记录歧义。同一主体若同时有多种修正，来源枚举记为“混合”，不把其中一种冒充唯一回应。**这些修正由多个原版事件共用，不能从修正本身恢复具体事件 ID 或要求正文**；因此这只是第四章来源的一部分，不足以结算 AED-04-00，也不应在剧情里编造要求类型。

另有覆盖缺口：原版 `fallen_empires.4`～`.8` 的接受分支调用 `fallen_empire_humiliate_effect` 并清除通用 `fe_demand_made`，没有写入上述三种关系修正；虽然 `opinion_accepted_fallen_empire_demand` 在原版修正表中定义，本机 4.5.1 脚本未见其被调用。`humiliated` 也会来自战争等其他来源，不能据此反推具体发起者或要求。因此当前适配器**不能捕获这组一般要求的接受回应**；即使改用笼统呈现，也必须另行处理这一分支的来源缺失，不可把“未捕获”写成“玩家拒绝”。

## 3. 已批准的保守资格口径

| 事实或场景 | 已批准处理 | 理由与后续状态 |
| --- | --- | --- |
| 第四章前置 | 只接受能定位到具体失落帝国、对玩家发生的真实干预或外交要求；锁定该主体与事实来源 | 仅通讯、年份、国力或“附近存在失落帝国”不能充当政治干预。可用的原版事件／外交事实入口尚需逐项验证；入口缺失时显示待观察并保持章节索引 |
| 第五章开战资格 | 已锁定主体成为 `awakened_fallen_empire`，由其向玩家直接宣战；玩家是原始防守战争领袖，第四章已结算 | 与已批准“失落帝国觉醒并向玩家文明宣战”的章节位置逐项对应；同盟晚加入、玩家主动宣战、普通帝国战争只记外部事实，不自动写入本条主线开始标记 |
| 战争实例 | 开战时在当前战争对象设置本包唯一标记，并为国家保留被锁定主体与开战事实；结束时只读对应战争标记 | 多场战争或重复回调不能互相代领结果。若作用域或存档复测无法证明实例关联，则阻断结果写入，不按日期或当前无战事推断 |
| 结果事实 | 合格战争的结束、玩家胜利、玩家战败、维持现状分别记录；只有玩家在对应战争的 `on_war_won` 中成为胜方战争领袖时，才写入“已克服”资格 | `on_war_ended`、签署停战、敌国提前消失均不能自动等同胜利。战败及维持现状保留已发生历史，向玩家解释阻断或后续恢复路径 |
| 第六章资格 | 战争开始事实、对应实例的胜利事实、第五章决定及损失记录均成立后，才能进入战后复盘；复盘完成再唯一结算 | 已发生损失不因胜利清除；不能由事件窗口或只读入口补齐战争结果 |

这里的“失落帝国政治干预”与“觉醒后宣战”是先后两种事实，不要求第四章在宣战回调中临时倒放。若原版外交入口无法可靠识别具体干预，本章须保持阻断，不能改用战争爆发来倒填前置章节。玩家作为盟友、主动进攻者或以维持现状和平进入第五／六章均不符合本次批准口径，扩展须另行明确。

## 4. 实施顺序与证明方式

1. 已实现一条可反查发起者的原版外交回应记录；下一步仍需证明具体要求内容如何保存，或由用户批准对第四章呈现口径的调整。证明前保留 AED-04-00 阻断，不补写第四章账本。
2. 已实现独立战争适配脚本记录合格战争开始、锁定战争实例，并分别处理胜利、战败、维持现状与晚加入回调；外部适配器不直接推进章节。当前只有静态检查通过，尚无回调运行证据。
3. 实现第五章有限观测与中央庭决定，以及第六章战后损失、审查、恢复期；每章独立提交并针对读档、重复窗口和跳章做回归。
4. 用真实战争存档执行 FEA-01～06。测试命令可检查接口，不代替自然流程；正常链与测试注入档分开。特别核对多战争并发、战前／战中／战后读档、目标消失、战败与停战后不误写胜利。

## 5. 判定批准记录

2026-09-27，用户对“第五章只接受已锁定的觉醒失落帝国向玩家直接宣战、玩家为原始防守战争领袖；第六章只接受该战争中的玩家领袖胜利；其余场景只记录事实”的问题明确回复“批准建议口径（建议）”。该批准只覆盖 FEA-02／03 的资格定义，不等于第四章外交入口已证明或运行测试已通过。

如果要将盟友参战、未觉醒失落帝国、玩家主动开战、维持现状或战败后的恢复路径也纳入“合格推进”，需分别明确条件与叙事后果，再更新本设计及 FEA-02／03。当前运行状态仍为 `not_tested`。

## 6. 第一批适配实现后的第四章边界

新增的 `aemusa_ms.600` 只读取原版要求回应关系修正，且候选主体唯一时才保存玩家专属的失落帝国事件目标和来源类型枚举；`.601` 仅记录多主体歧义。`aemusa_ms.610` 只在第四章已完成、发起者已经觉醒、该主体是原始攻击领袖且玩家是原始防守领袖时给战争实例打标。`aemusa_ms.620`～`.622` 只对同一战争分别写胜利、战败或维持现状。项目静态检查和既有工具测试通过；原版 4.5.1 回调形状已核对，游戏运行结果仍未测试。

**未解决的具体问题**：原版多个外交事件共用同一关系修正。要保持 AED-04-00“保存具体要求”的已批准设计，仍需找到可无歧义提取具体事件 ID／正文的非侵入式来源。若改为只记录“某次原版要求及回应”，将削弱第四章的具体政治辨析，应先明确是否接受这一设计变更。两种路径都不能把战争发生倒填为第四章干预。
