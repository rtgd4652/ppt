# 爱缪莎 1.0 主线事件拆分设计

## 0. 文档职责

本文把已批准的 [`aemusa_main_story_production_matrix_v1.0.md`](aemusa_main_story_production_matrix_v1.0.md) 转换为事件实现设计输入，回答：

- 哪些叙事功能应组成同一个事件簇；
- 事件簇读取哪些已成立事实；
- 事件簇可以写入哪些状态；
- 玩家选择、暂停、拒绝、失败与恢复如何进入下一簇；
- 哪些信息只对爱缪莎、玩家、中央庭或文明公开；
- 如何证明重复触发、读档和中断不会复制内容或越过剧情。

本文仍不授权：

- 编写 Stellaris `.txt`、事件 ID、本地化 key、触发器、效果或数值；
- 撰写完整对白；
- 创建危机国家、舰队、局势、特殊项目或生成逻辑；
- 恢复已经暂停的专属舰原型与正式实现；
- 确定正式舰船、巨构、终局形态、危机投影或 UI 美术；
- 修改现有 Mod 代码、模型、贴图或本地化。

## 2. 事件簇而非事件窗口

### 2.1 定义

“事件簇”是完成一个稳定叙事转场所需的一组功能单元。一个事件簇可以在未来由多个事件、通讯、局势更新、特殊项目或系统提示实现，也可以在技术可行时合并；本文不预先决定窗口数量。

### 2.2 拆分原则

1. 每个事件簇只负责一个可验证的主状态转场。
2. 叙事展示、玩家选择、机制执行和状态审计必须分清职责，不能靠同一按钮暗中补齐所有条件。
3. 只有完成写入与审计后，事件簇才可标记完成。
4. 重复进入只能重放允许重放的表现，不能重复奖励、损失、授权或角色决定。
5. 任何事件簇都不能通过未显示条件推断玩家已经同意。
6. 专属终局天灾内部机制沿用既有状态机与锚点生命周期，本文只定义章节桥接和叙事交接。

## 3. 统一事件簇卡字段

每个事件簇使用以下字段：

| 字段 | 必须回答的问题 | 禁止替代 |
| --- | --- | --- |
| 规划编号 | 本簇在设计文档中的唯一引用是什么 | 直接当作正式事件 ID |
| 来源制作卡 | 对应哪个 `APM-*` 制作卡 | 脱离已批准章节自行扩写 |
| 功能类型 | 入口、叙事、选择、行动、结算、恢复还是审计 | 用剧情标题代替功能 |
| 状态所有者 | 哪个叙事主体持有权威事实 | 直接写 Stellaris scope 语法 |
| 进入契约 | 哪些事实必须已经成立 | 用年份或等级替代全部历史 |
| 阻断条件 | 哪些状态必须拒绝进入 | 静默忽略冲突 |
| 读取状态 | 本簇只读哪些历史、关系、损失与真相 | 顺手读取所有全局数据 |
| 场景职责 | 本簇必须表达什么 | 完整对白 |
| 玩家交互 | 玩家可以决定什么、不能决定什么 | 把确认按钮写成授权 |
| 写入状态 | 完成后新增或改变哪些事实 | 未展示的隐藏立场 |
| 不可逆写入 | 哪些拒绝、损失或决定不能回滚 | 普通表现状态 |
| 后继出口 | 成功、暂缓、拒绝、失败与恢复分别去哪里 | 无条件跳到下一章 |
| 重复策略 | 再次触发时重放、提示、忽略还是审计 | 重复发放与重复决定 |
| 中断与读档 | 中断后从何种事实恢复 | 依赖窗口是否仍打开 |
| 信息可见性 | 爱缪莎、玩家、中央庭、文明各自知道什么 | 自动公开玩家层真相 |
| 资产职责 | 需要哪类立绘、界面、音效或场景占位 | 批准具体美术方案 |
| 验收证据 | 测试时必须观察到什么 | 只写“正常运行” |
| 明确排除 | 本簇绝不能完成什么 | 依赖开发者自行记忆 |
| 审核状态 | 草案、待审、已批准或需重开 | 未经人工批准自动升级 |

规划编号统一采用 `AED-*`，仅用于文档引用；正式脚本命名在代码阶段另行建立。

## 4. 功能类型

| 类型 | 职责 | 典型输出 |
| --- | --- | --- |
| `gate` | 检查并开放章节入口 | 可进入、暂停或拒绝原因 |
| `narrative` | 展示已经成立的事实与角色反应 | 已读记录，不改变关键选择 |
| `choice` | 接收玩家真实决定 | 可追溯选择状态 |
| `operation` | 连接现实行动或外部机制 | 行动开始、完成、中断 |
| `settlement` | 结算后果与永久记录 | 损失、里程碑、关系后果 |
| `recovery` | 修复允许修复的进入条件 | 恢复资格，不抹除历史 |
| `audit` | 核验对象和账本一致性 | 一致、可修复冲突或硬阻断 |
| `adapter` | 接入原版危机或既有专属天灾蓝图 | 外部事实映射，不改写其身份 |

单个事件簇可以有一个主类型和一个辅助类型，但不能同时承担所有类型。

## 5. 状态所有权原则

1. 国家／路线账本持有章节进度、危机路线、永久损失、真相层级和结局状态。
2. 爱缪莎角色账本持有等级资格、角色判断、关系记忆与自主接受／拒绝。
3. 玩家决定账本持有暂缓、拒绝或授权，不得由角色账本代写。
4. 原版危机和专属天灾蓝图持有自身运行事实；主线只通过适配簇读取经验证结果。
5. 临时窗口、目标对象和表现状态不能成为唯一权威账本。
6. 正式 Stellaris scope、flag、变量和保存对象仍待代码设计，不在本文命名。

## 6. 六种双方决定状态

| 状态 | 含义 | 可恢复性 | 允许后继 |
| --- | --- | --- | --- |
| 未决定 | 尚未进入最终决定 | 可继续推进 | 最终沟通入口 |
| 暂缓 | 玩家要求以后再谈 | 可恢复 | 返回最终沟通 |
| 玩家拒绝 | 玩家明确拒绝授权 | 永久 | 玩家拒绝非转变结局 |
| 授权待回应 | 玩家已授权，爱缪莎尚未决定 | 只能等待角色决定 | 爱缪莎接受或拒绝 |
| 爱缪莎拒绝 | 她自主拒绝承担完整权限 | 永久 | 爱缪莎拒绝非转变结局 |
| 双方同意 | 玩家授权且她自主接受 | 永久 | 第十六章完整成功 |

不得设置“系统默认同意”“超时同意”“等级 30 自动同意”或“中央庭代替授权”。

## 7. 事件流分层

事件拆分按六条职责线组织：

1. **主线编排线**：控制章节入口、顺序、暂停与结算。
2. **角色通讯线**：承载爱缪莎、安托涅瓦、晏华和玩家之间的信息与关系变化。
3. **原版危机适配线**：四种危机单局择一，读取完成与现实贡献，不改写危机身份。
4. **专属危机桥接线**：把第十一至第十三章接入既有危机状态机与锚点生命周期。
5. **真相与终局线**：分层揭示世界更替，分别记录玩家授权与爱缪莎决定。
6. **审计恢复线**：处理重复触发、读档、中断、对象缺失和矛盾状态，不制造缺失剧情事实。

## 8. 事件簇粒度规则

以下情况必须拆成不同事件簇：

- 入口资格检查与正式剧情展示；
- 玩家选择与选择后果结算；
- 原版危机结果读取与角色战后反思；
- 专属天灾状态推进与章节叙事通知；
- 玩家授权与爱缪莎自主接受；
- 完整成功结算与尾声表现；
- 正常推进与故障审计。

以下情况允许合并：

- 同一场景内连续展示、没有独立状态写入的角色反应；
- 只改变文本重点、不改变事实或奖励的尾声语气；
- 同一恢复流程中的说明与重新开放入口。

## 9. 审核与制作顺序

1. `AED-R001`：事件簇字段、功能类型、状态所有权、决定状态与粒度规则（已批准）；
2. `AED-R002`：序章至第三章；
3. `AED-R003`：第四至第七章及四种原版天灾适配；
4. `AED-R004`：第八至第十章；
5. `AED-R005`：第十一至第十三章及专属危机桥接；
6. `AED-R006`：第十四至第十六章、两种非转变结局与尾声；
7. `AED-R007`：全线审计、读档恢复、幂等性与测试证据终审。

前一批未经人工批准，不进入后一批。任何批次发现与制作矩阵冲突时，必须停止并明确重开上游审核，不能在事件拆分中自行修订正史。

## 10. AED-R001 审核记录

请审核：

1. 是否批准以“稳定叙事转场”为单位建立事件簇，而不预先绑定事件窗口数量；
2. 是否批准统一事件簇卡的十九项字段；
3. 是否批准八种功能类型，并限制每簇只能有一个主类型和最多一个辅助类型；
4. 是否批准路线、角色、玩家决定、危机蓝图和临时表现之间的状态所有权边界；
5. 是否批准六种双方决定状态，禁止默认同意、等级自动同意或中央庭代替授权；
6. 是否批准六条事件职责线及必须拆分／允许合并规则；
7. 是否批准按 `AED-R002` 至 `AED-R007` 分批人工审核；
8. 是否确认本阶段仍不编写代码、完整对白、数值或正式资产。

审核结果：2026-08-16 用户指示继续。事件簇定义、十九项字段、八种功能类型、状态所有权、六种双方决定状态、六条职责线与分批审核顺序获准继续使用。本批准不授权编写代码、完整对白、数值或正式资产。

## 11. AED-R002：序章至第三章事件簇

本批只拆分 `APM-PRO`、`APM-01`、`APM-02` 与 `APM-03`。所有规划编号仅用于文档引用。

### 11.1 序章：未翻开的牌

#### AED-PRO-00｜序章入口审计

- **来源制作卡／功能类型**：`APM-PRO`；`gate + audit`。
- **状态所有者**：路线账本。
- **进入契约**：玩家文明进入 Stellaris 开局时代；白夜馆能够联系爱缪莎。
- **阻断条件**：序章已结算；爱缪莎不存在或白夜馆入口处于可修复异常。
- **读取状态**：爱缪莎可用状态、白夜馆入口、序章完成与恢复标记。
- **场景职责**：只决定能否开始，不展示牌局或写入玩家立场。
- **玩家交互**：无关键选择；可以退出并稍后返回。
- **写入状态／不可逆写入**：只写临时“序章已开启”；无不可逆写入。
- **后继出口**：合格进入 `AED-PRO-10`；可修复异常进入入口恢复；已完成只给提示。
- **重复策略／中断读档**：幂等检查；重新读取权威账本，不依赖窗口状态。
- **信息可见性**：只显示当前可进入或阻断原因，不泄露终局条件。
- **资产职责**：白夜馆既有入口或通用通讯框架。
- **验收证据**：新开局可进入一次；重复点击不复制章节；异常修复后可继续。
- **明确排除**：国力、等级 30、失落帝国或天灾门槛。
- **审核状态**：`pending_human_review`。

#### AED-PRO-10｜牌局与有限观测

- **来源制作卡／功能类型**：`APM-PRO`；`narrative`。
- **状态所有者**：爱缪莎角色账本与路线临时进度。
- **进入契约**：`AED-PRO-00` 合格；本场尚未完成。
- **阻断条件**：序章已结算或牌局段已经确认读完。
- **读取状态**：爱缪莎基础关系语气；不得读取后期危机和终局真相。
- **场景职责**：表现爱缪莎主动增加限制、维护公平、保留最后一张未翻之牌；随后展示互相冲突且置信度不足的早期征兆。
- **玩家交互**：可接受多个不确定方案，或要求确定答案；选择只记录态度，不改变观测可靠性。
- **写入状态／不可逆写入**：记录是否尊重有限观测；牌局段已读。无永久结局写入。
- **后继出口**：进入 `AED-PRO-20`。
- **重复策略／中断读档**：允许从本段开头重放，但态度只在首次有效选择时登记一次。
- **信息可见性**：玩家和爱缪莎知道观测冲突；中央庭尚未形成正式复盘。
- **资产职责**：基础立绘、牌局器物和低强度观测界面。
- **验收证据**：未翻之牌不被解释为唯一结局；要求神谕不会获得更可靠答案。
- **明确排除**：主动命运干涉、终局光效、玩家层真相。
- **审核状态**：`pending_human_review`。

#### AED-PRO-20｜低置信度征兆与现实代价

- **来源制作卡／功能类型**：`APM-PRO`；`operation + settlement`。
- **状态所有者**：路线账本与损失账本。
- **进入契约**：`AED-PRO-10` 完成；早期征兆仍可被现实验证。
- **阻断条件**：本次小规模后果已经结算。
- **读取状态**：序章观测记录与玩家最初态度。
- **场景职责**：让一项被搁置的低置信度征兆对应可避免但范围有限的现实代价，并让受影响者被看见。
- **玩家交互**：只处理即时应对与是否诚实登记，不提供无成本撤销。
- **写入状态／不可逆写入**：写入小规模后果、受影响者和信息遗漏；实际损失不可逆。
- **后继出口**：进入 `AED-PRO-30`；中断时先完成结算再展示复盘。
- **重复策略／中断读档**：结算严格一次；重复触发只显示既有记录。
- **信息可见性**：现实后果可被中央庭验证；原因仍不能被写成命运惩罚。
- **资产职责**：通用科研资料和小规模后果表现。
- **验收证据**：只生成一份损失记录；读档不重复扣除或重复生成受影响对象。
- **明确排除**：无预警重大灾难、人格化命运、用损失强迫唯一答案。
- **审核状态**：`pending_human_review`。

#### AED-PRO-30｜制度复盘与信息治理选择

- **来源制作卡／功能类型**：`APM-PRO`；`choice + narrative`。
- **状态所有者**：玩家决定账本与路线账本。
- **进入契约**：`AED-PRO-20` 已完成唯一结算。
- **阻断条件**：有效信息治理选择已经登记。
- **读取状态**：观测态度、小规模代价、是否诚实登记。
- **场景职责**：由晏华要求依据、反例和遗漏记录；安托涅瓦规定观测只能作为公共决策参考。
- **玩家交互**：选择有限保密并建立监督，或分阶段公开并承担误读风险；永久秘密集中只能形成待修复问题。
- **写入状态／不可逆写入**：写入初始信息治理倾向、监督承诺和需修复问题；既有现实损失保持不可逆。
- **后继出口**：有效选择进入 `AED-PRO-90`；拒绝监督进入可恢复暂停。
- **重复策略／中断读档**：未确认选择可重开；确认后只允许进入后续修复，不允许重选抹除历史。
- **信息可见性**：公开范围由选择决定；玩家层与银河命运本体保持未知。
- **资产职责**：中央庭决策／审查界面和三人通讯表现。
- **验收证据**：两种有效治理路线均可推进；工具化倾向不会立即永久失败。
- **明确排除**：安托涅瓦替爱缪莎决定人格选择、晏华否认神器事实。
- **审核状态**：`pending_human_review`。

#### AED-PRO-90｜序章结算

- **来源制作卡／功能类型**：`APM-PRO`；`settlement + audit`。
- **状态所有者**：路线账本。

### 19.2 第十二章：终局天灾展开

- **读取状态**：宿主现实、最后窗口、撤离保护、局部恒定准备和收敛指标。
- **场景职责**：确认当地未来被压缩到只剩毁灭结果，常规手段无法直接接触正在兑现的过程。

- **写入状态／不可逆写入**：正式锚点唯一编号、宿主、公开压力和局部风险。

- **重复策略／中断读档**：锚点状态只前进不倒退；同一宿主不重复生成。
- **信息可见性**：公开宿主与风险，不伪造人格化敌意。
- **资产职责**：形状缺失、重复轮廓、断裂连接和层次压平。
- **验收证据**：成锚前已有预警；单个失败不直接全局判负。

- **资产职责**：只定义可读范围和职责，不批准载体模型。

| 角色暂时不可用 | 恢复、休整或通讯中断 | 按已批准角色恢复条件处理 | 章节进度与危机历史 | 普通死亡永久删除爱缪莎 |

恢复流程只负责重新满足合法入口条件，不负责提供“更优历史”。

### 23.5 重复触发与幂等性规则

每个未来事件簇至少要有四个独立状态：`未开始`、`进行中`、`已完成`、`已结算`。具体技术命名后定，但语义不得省略。

- **未开始**：允许入口检查，不得存在本簇奖励、损失或决定。
- **进行中**：记录已完成的子步骤和外部行动；读档后从权威账本恢复。
- **已完成**：叙事与选择已经结束，等待唯一结算；不得重新询问关键选择。
- **已结算**：所有不可逆写入完成；重复触发只能提示、重放允许的表现或执行只读审计。

以下操作必须具有唯一结算标记：

1. 章节完成和幕完成；
2. 失落帝国战争主线结果映射；
3. 唯一原版天灾候选锁定与完成；
4. 专属危机初始化、锚点结果汇总、危机胜利／失败；
5. 永久损失和不可逆救援结果；
6. 玩家授权、玩家拒绝、爱缪莎接受、爱缪莎拒绝；
7. 命运主宰身份和完整权限成立；
8. 两种非转变结局、完整成功结局及尾声语气；
9. 任何一次性奖励、资产解锁或公开信息升级。

月结、年度轮询、通讯重开、事件重复触发、特殊项目重检和读档恢复均不得绕过唯一结算标记。

### 23.6 状态矛盾的诊断优先级

发现矛盾时按以下顺序处理，不进行猜测性修复：

1. **冻结不可逆推进**：终局、危机结算、永久拒绝和身份授予立即停止。
2. **保护已有历史**：先保留真实损失、已完成危机、明确决定和已公开资料。
3. **定位所有者**：确认冲突属于历史、角色、玩家决定、危机或临时表现中的哪一账本。
4. **删除临时假象**：临时窗口、目标对象或表现标记不能覆盖权威账本。
5. **只修可推导的表现状态**：可以从权威事实重建窗口和进度显示，不能从结果反推玩家或角色意图。
6. **无法确定则硬阻断**：输出缺失条件和冲突状态，等待人工或专项迁移方案。

典型硬阻断包括：

- 玩家拒绝与双方同意同时存在；
- 爱缪莎拒绝与命运主宰身份同时存在；
- 第十六章完成但专属危机未结算；
- 两种原版天灾候选同时被记录为本局已完成；
- 世界更替真相在专属危机前已向中央庭全体公开；
- 完整权限成立时间早于第十六章；
- 尾声已结算但没有合法最终决定。
