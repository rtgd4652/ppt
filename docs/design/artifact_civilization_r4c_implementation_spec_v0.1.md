# R4c 分段大型工程

2026-10-31，基线`d35ac20`。按E09／BL30已定路线，交付B14的第一个真实消费者：分阶段建成可运行的大型工程营建场，增加1个巨型结构同时建造名额。

## 设定与引擎依据

写前只读查询七都数据库的中央庭、神器科学、神器三项术语，阅读[组织圣经](../../knowledge/organizations/organization_bible_v0.1.md)的资源统筹／科研协作及[神器圣经](../../knowledge/artifacts/artifact_bible_v0.1.md)的普通科技支撑。采用灾后重建经验延伸到星际工程的语气；阶段制与并行营建能力均为`mod_design_decision`，来源审核状态不变。

本机原版`common/ascension_perks/00_ascension_perks.txt`的`ap_master_builders`使用`country_megastructure_build_cap_add = 1`。建筑的`triggered_country_modifier`由原版建筑样例和既有观测阵列确认。复用这些接口；不授予任何具体巨构的研究资格，不解锁个人舰船或替代新巨构责任卡。

2026-10-31补充对照Gigastructural Engineering及ACOT，见[源码参考与取舍](artifact_large_engineering_mod_reference_2026-10-31.md)。E09首版保留为营建基础，不继续为额外名额增加管理环节；后续空间巨构优先使用原生升级链、费用和工期，特殊投入及能力再用脚本衔接。这次仅补设计依据，以下参数、运行脚本和待验状态保持。

## 正常流程与初始参数

1. 研究E09（E08＋B14，工程T5／工业，22000研究，权重60）。
2. 在有集成场、配给仓和联运站的殖民地建设BL30大型工程营建场。建筑全国1处、每殖民地1处；720日，1500矿物／800合金，维护20能源／4消费品。
3. 保持有效联运接收端及B14备料，在行星决议开始场地准备；同一守卫块确认目标后消费一份备料。3次有效月度完成准备，等待玩家决定下一阶段。
4. 玩家另付1000矿物／1500合金，启动结构装配；4次有效月度完成，再次等待确认。
5. 玩家另付1000能源／300消费品，启动联合试运行；2次有效月度后营建场投入运行。

每次有效月度只推进当前已付阶段。阶段之间不自动扣费，查看进度不推进。全国同时只有一个营建项目，完成态继续占位。B14的备料位在交付时释放，可为其他工程重新备料；本项目的国家名额独立管理。

场地准备至试运行都要求原拥有者、控制权、无轰炸、有效接收端、集成场、营建场及研究。失效时保存已付阶段与工作量，不补跑停工月份。完成后只要求营建场本身有效、原拥有者控制、无轰炸及E09研究；可将接收端调往其他工程。

完成效果由建筑实时提供`country_megastructure_build_cap_add = 1`，失效时不再提供额外容量；不直接修改现有巨构的队列或进度。实际容量对不同原生巨构的适用范围及失效时在建项目的引擎行为留待运行确认，不宣称“所有巨构都受益”或“已开工项目必然停工”。

## 清理与可见信息

- 复用`acs_managed`、`acs_owner@this`及原月度／转让／毁灭回调，无新增扫描或订阅。
- `acs_segmented_project`记录国家唯一占位；五个阶段标记和`acs_segmented_operational`表示当前状态；`acs_segmented_work`保存当前阶段有效月度。
- 占领不清账；转让、失去拥有者或毁灭清除项目与收益，无退款、无继承。新国不能凭旧状态取得容量。
- “撤销营建项目”在原拥有者控制且无轰炸时可用，不要求设施仍存在；清除本项目、不退款。普通库存、重新准备的B14备料及其他项目保留。
- “查看大型营建进度”只打开只读页面，明确当前工作量、下一次投入或停工原因；无自动弹窗和窗口付费选项，旧页面不会操作新拥有者资源。
