# 神器文明1.0范围确认与终局边界

日期：2026-10-08。

状态：用户已确认1.0交付范围与内容结束位置；具体机制、数值、资产数量、外观和剧情细节尚待设计。本次只保存设计决定，未修改运行脚本、制作资产或操作游戏。

依据：用户确认“1.0就完整体现这套文明体系，即使延后交付”；专属危机是游戏的最终Boss，结束后获得更强的科技、更炫酷的舰船和巨构，以及结尾剧情，至此结束Mod内容。基础方向见[无限可能性](artifact_civilization_infinite_possibilities_direction_v0.1.md)，实施现状见[项目进度](../PROJECT_STATUS.md)。

## 一、1.0必须体现的文明体系

1. 十名神器使具有差异化成长与作用领域，职业、等级、神器能力和人物组合能够影响文明的发展方式。
2. 神器科技、传统、专属飞升和工程能力与人物成长相互支撑，形成从前期到终局的完整发展过程。沿用现有30级上限；阶段划分、系数和最终公式另行设计。
3. 后期允许明显超越普通文明的力量尺度；新能力与组合是成长的重要表现。独立“可能性乘区”仍是待验证的实现方向，不把范围确认记为技术可行性通过。
4. 舰船和巨构承接文明成长，优先提供以前无法开展的行动、实验、工程或战略选择，同时具备必要产能和战斗收益。
5. 专属危机成为最终考验；机制难度与数值倍率分开设计，具体档位、反制路线、指标和数值尚未确定。
6. 最终Boss之后交付终局科技、舰船、巨构奖励和结尾剧情，完整1.0的主要内容在这里收束。

“完整体现”要求这些系统相互贯通；不表示必须实现所有现实工程案例、改造所有原版巨构或穷尽所有资产类型。

## 二、最终Boss与内容结束位置

整体节奏：文明成长与工程准备 → 最终专属危机 → 胜利与代价结算 → 终局奖励及结尾剧情 → Mod内容结束。

- 战前与危机中的成长、研究、舰船和巨构用于应对最终考验。
- 更强科技、更炫酷的舰船与巨构可以作为胜利后的奖励，不要求再增加一轮Boss来验证这些奖励。
- 危机后的内容承担奖励与叙事收束，不继续展开新的长期项目链或无尽危机循环；获得的设施和能力仍可用于后续普通游玩。
- 当前第十一至十三章危机、第十四至十六章与三结局作为现有基础保留。本次不直接重排章节或修改转变条件；奖励与三种结局的对应关系另行设计，三结局的合法地位保持。
- 先前讨论中的“危机后持续扩展平台项目”不作为新1.0要求；平台型巨构的长期用途主要服务文明成长与最终危机，终局奖励则承担完成感。

## 三、巨构能力设计依据

现实人造奇观作为设计参考时，记录建造代价、社会动机、新增能力及其长期影响。三峡工程、三角洲防洪体系、巴拿马运河、LHC、阿波罗计划和国际空间站属于用户提供的参考方向，本次未开展独立资料核验。

暂用连接型、开发型、防御型、突破型、平台型描述能力，同一座巨构可以跨类型。原版巨构用于理解文明能力层级，不自动成为原版系统改造清单。

每项方案分别记录：

- Lore Design：世界观中的能力。
- Player Experience：玩家获得的新行动或选择。
- Stellaris Implementation：拟用现有系统及其验证状态。
- Technical Difficulty：实现难度与依赖。
- Compatibility / Performance Risk：兼容性与性能风险。

建造理由、代价、运行和失效条件随方案说明。世界观可以大胆；脚本以现有系统制造相应体验，未验证能力保持未验证状态。

## 四、共同视觉语言与资产生产

建立“神器文明3D Visual Language”，核心是“被工程化的奇迹”：可识别的人类工业骨架、具备明确用途的超常结构，以及逐渐发展的工程连接方式。

- 共同中央庭工程语言优先；人物视觉方言在其上发展。爱缪莎参考可能性的分支、运行、汇聚与重新选择；安托涅瓦参考空间的折叠、收纳、展开与保护，具体造型尚未定稿。
- 建立原版视觉撞车库，对照灰模、轮廓和结构关系，检查辨识度。
- 优先建立可复用3D Kit及其组合规则；普通设施和原型可采用原版资产，主要内容可采用基础资产加原创核心部件，关键唯一舰与核心巨构按实际需要制作完整原创模型。
- 原版或公开资产按实际允许使用的范围选择。来源方式与最终视觉身份分别记录。
- 现有旗舰三段与枢纽两阶段样品保留为制作、导出和显示验证基础，不因文件完成就视为新视觉规范的正式外观。

## 五、后续设计与实现顺序

1. 在现有十人身份、职业和核心机制上，梳理分级成长、组合关系及文明系统接口；保留既有批准基线和运行证据。
2. 明确科技、传统、飞升与能力型工程的发展路线，针对选定领域验证可能性乘区或其他合适实现，再确定数值模型。
3. 建立共同视觉规范和代表Kit，使正式舰船、巨构造型与能力设计对应。
4. 分批实现文明体系与最终Boss，随后补齐终局奖励、结尾剧情和所需正式资产。
5. 每批检查新增正常流程、关键读档和本次严重失败点；发布前完成一次整体衔接回归，形成安装包与存档说明。

本节记录推进依赖，不表示本次已批准具体能力、公式、外观或额外隐藏结局。继续复用现有章节路由、身份记录和状态接口；不恢复历史任务，不重新逐窗验收或例行计算哈希。
