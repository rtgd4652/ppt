# 爱缪莎 1.0 主线实现任务分批清单

## 0. 目的

本文把已批准设计拆成可实现、测试和回退的内部工作包。用户后续继续指令按已确认的可玩里程碑执行，同一范围不重复确认。里程碑1授权见第41节，第40节的代理提案已被替代；里程碑2实施与运行结果见第46、47节。AWP-06至09现已达到轻量可玩标准，后续为十人与文明整合。验收采用第35节及第41节轻量口径，历史完整测试门槛不再阻塞内容续作。

## 1. 通用交付门禁

每个已确认的可玩里程碑必须遵守以下规则；AWP 编号只作内部拆分：

1. 开始前确认权威输入和文件归属；
2. 单次只处理约定的脚本类型与章节范围；
3. 新增代码带中文注释；
4. 不覆盖原版文件，不接入未批准资产；
5. 完成静态检查、定向测试和 error.log 归因；
6. 使用中文提交信息独立提交；
7. 尚未验证部分如实标注；同一授权里程碑可继续完成依赖实现，不逐包重复申请许可；
8. 遵守当次有效时间要求，并预留 token 用于保存文件、状态、未完成项与下一步。用户本晚明确取消时间限制，不取消保存义务。

## 3. AWP-00：状态登记展开与基础审计

**范围**

- 把批准的模式状态展开为显式、机器可审查的正式状态清单；
- 对每个 key 验证作用域、数据类型、默认值、写入接口和测试映射；
- 建立只读一致性审计和测试环境诊断输出；
- 不创建章节事件正文。

**允许文件类型**

- 状态登记数据；
- 未来经授权的 scripted trigger／scripted effect 基础审计文件；
- 调试本地化和测试文档。

**禁止**

- 自动修复玩家决定；
- 编写序章或后续剧情；
- 迁移旧舰船／巨构状态；
- 将候选 key 未经审核直接全部落地。

**完成门禁**

- 所有正式状态均有登记；
- 六态、三结局、四危机候选互斥可静态验证；
- 审计只读，不产生剧情事实；
- T002、T003、T017 的测试前置可建立。

## 4. AWP-01：主线最小运行骨架

**范围**

- 建立独立主线 namespace 和事件入口；
- 实现事件簇“未开始／进行中／已完成／已结算”生命周期；
- 建立白夜馆到最近合法入口的最小只读连接；
- 使用无剧情占位验证幂等性。

**禁止**

- 一次性填入全部章节；
- 使用正式奖励、危机、终局权限或未批准资产；
- 用临时窗口状态代替路线账本。

**完成门禁**

- 新开局初始化一次；
- 重复入口不重复结算；
- 选择前后读档能恢复正确状态；
- error.log 无本包关键红字。

## 5. AWP-02 至 AWP-05：前四幕内容

### AWP-02｜序章至第三章

- 只实现有限观测、现实代价、信息治理、责任半径与第一次现实选择；
- 不提前出现失落帝国、天灾、世界更替和完整权限；
- 每章独立提交并回归 T001-T004。

### AWP-03｜第四至第六章

- 接入失落帝国战争的真实开始与结束事实；
- 主线不替玩家赢得战争；
- 战后损失、恢复和安托涅瓦公共责任必须保留。

### AWP-04｜原版天灾与第七章

- 四个候选模块共用骨架、单局择一；
- 完成一种后其他模块永久关闭；
- 原版危机完成只进入局部主动干涉和战后复盘，不授予终局权限。

### AWP-05｜第八至第十章

- 建立毁灭收敛工作模型、受限埃索林通讯、权利保障与共同应对授权；
- 埃索林不成为全知说明者；
- 里见茜不出场，塞拉菲姆身份链不揭示；
- 30 级只登记为最终沟通必要条件之一。

## 6. AWP-06：专属危机机制底座

本包与 AWP-07 合并为“专属危机可玩”里程碑。第 41 节记录的用户明确授权已完成本轮机制取舍与实施许可，不再等待旧代理提案确认。

**范围**

- 非人格危机状态机；
- 锚点生命周期；
- 无人格投影生成职责；
- 局部恒定职责接口；
- 新作战旗舰与现场恒定，同一时间一艘，免费自动恢复默认 90 游戏日；
- 新巨构基址到运行态两阶段建设与正常入口；
- 专属巨构的现实基线、协调、弱点解析、占领暂停与恢复职责；
- 永久损失和资料保留。

**资产边界**

- 使用核实存在的原版模型验证玩法，1.0 发布前换新的正式模型；
- 不恢复旧 Stage 9、隔离验证原型或旧命运观测塔；
- 实现新舰船和巨构定义，不定稿正式外观；显示名与首版数值随功能交付，最终平衡后置。

**完成门禁**

- 危机只初始化和结算一次；
- 锚点状态不倒退；
- 巨构被占领时只暂停新解析，资料永久保留；
- 局部损失在胜利后仍存在；
- 新增正常闭环与关键读档通过；舰船恢复、巨构暂停／恢复、真实锚点损失作必要定向检查。T006～008／T020 保留为需求索引，不恢复穷举门槛。

## 7. AWP-07：第十一至第十三章

**范围**

- 把三线验证、锚定前兆、救援、局部恒定、巨构解析和双钥匙胜利接入 AWP-06；
- 首个锚点闭环后接最多两个后续核心节点，逐个活动，与 AWP-06 在同一里程碑内交付；
- 危机胜利只授予真相调查和最终沟通资格；
- 保存代价、资料、盟友贡献和开放问题。

**禁止**

- 人格化危机；
- 恢复全部损失；
- 危机胜利直接揭示世界差异；
- 授予命运主宰身份或完整权限。

## 8. AWP-08：第十四至第十六章与非转变结局

**范围**

- 四层真相与危机后互认；
- 第十五章六种决定状态；
- 玩家拒绝和爱缪莎拒绝两种正式非转变结局；
- 双方同意后的第十六章唯一权限成立。

**强制拆分**

1. 玩家选择；
2. 玩家授权结算；
3. 爱缪莎自主决定；
4. 双重确认；
5. 权限唯一成立；
6. 结局唯一结算。

任何一步都不能由同一确认按钮暗中补齐。

## 9. AWP-09：尾声

- 根据真实历史生成一种主要叙事语气；
- 三种语气的权能、奖励和正史地位相同；
- 保留永久损失、开放谜团和其他角色主体性；
- 不创建新的战争、危机或必须由完整权限解决的任务。

## 10. AWP-10：白夜馆整合

白夜馆提供：

- 最近合法入口；
- 当前进度与可见资格；
- 已批准内容回顾；
- 暂缓恢复；
- 永久结局提示。

白夜馆不提供：

- 危机胜利按钮；
- 章节跳过；
- 永久拒绝重问；
- 玩家层真相公共档案；
- 重复角色或路线对象生成。

## 11. AWP-11：本地化与信息层审计

本包可随各章节增量执行，最终进行全线审计。

- 中文本地化使用正确编码；
- 每个阻断原因可解释但不剧透；
- 所有代码新增中文注释；
- 事件、本地化、日志、提示和 UI 采用同一信息层级；
- 未批准完整对白继续使用结构化占位，直到对白专项审核。

## 12. AWP-12：回归、迁移与发布门禁

**回归**

- 使用批准的测试模板执行 T001-T020；
- 至少覆盖新开局、事件中读档、危机中读档、六态决定存档和三种结局；
- 所有本 Mod 关键 error.log 红字归零。

**迁移**

- 只恢复旧存档能够证明的事实；
- 不能推断玩家授权、爱缪莎决定、危机完成或世界真相；
- 无法证明时给出明确阻断和新开局建议。

**发布门禁**

- 关键测试全部通过；
- 不可逆状态无冲突；
- 一次性结算不重复；
- 信息层级无泄露；
- 暂停旧资产未被误接入；
- 用户明确批准发布范围。
