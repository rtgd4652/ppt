# 神器使文明后续设计方向：无限可能性

- 适用范围：后续角色数值、神器使成长、神器科技、传统、专属飞升、巨构、军事体系与专属终局危机设计的统一参考。

## 1. 核心概念与设计哲学

神器使文明的核心设计概念是“无限可能性”。

按照本次提供的原作背景理解，《永远的七日之都》的世界结构已经濒临崩溃：黑门既是最终导致世界毁灭的重要因素，其力量又维持着已经破碎的世界。指挥使通过不断重复七日轮回，在无数可能性中寻找能够真正延续世界的道路。

本 MOD 希望将“可能性”同时落实为剧情概念与实际数值规则。无限可能性不要求无限数量的神器使；有限的神器使通过职业、等级、能力、神器解放与组合，产生大量不同的发展可能。

整体设计哲学暂定为：

> 前期遵守 Stellaris 的规则，中期利用 Stellaris 的规则，后期逐渐超越 Stellaris 的规则。

神器文明最终的强大，应来自神器研究、神器使成长、专属飞升和巨构逐渐形成的自身游戏规则，而不仅是更大的 modifier 数字。

## 2. 神器使成长曲线

神器使随领袖等级提升逐渐增强；目前等级上限计划为 **30 级**。成长阶段的具体等级分界、成长系数与解锁条件尚未确定。

| 阶段 | 预期力量与体验 |
| --- | --- |
| 前期 | 神器使是明显优秀于普通领袖的特殊领袖，但总体仍遵循原版 Stellaris 的力量尺度。 |
| 中期 | 随着等级提升、神器科技、传统和专属飞升逐渐完成，多名神器使开始形成明显的组合与乘算收益；其中乘算的技术实现仍待验证。 |
| 后期 | 高等级神器使完成完整体系后，允许数值明显突破普通 Stellaris 文明的成长尺度，成为神器文明完成成长后的特色。 |

后期高强度本身不是必须完全避免的问题。需要避免的是过早失控、无成本变强，以及数值增长使游戏机制失去意义。

## 3. 独立“可能性乘区”的研究方向

普通 Stellaris 中大量同类产出修正采用加算逻辑。神器使相关的特定核心加成，希望研究建立独立的“可能性乘区”。此处是概念目标，不是已经验证的引擎规则或最终计算公式。

概念上的处理方式为：

1. 普通修正仍按原版规则计算。
2. MOD 内符合条件的神器使修正，先按独立规则进行乘算。
3. 再与普通游戏修正共同作用于最终结果。

适用修正范围、具体计算顺序、脚本实现方式，以及 Stellaris 是否允许建立真正独立的乘区，均尚未验证，必须通过后续技术可行性测试确定。

如果原版 modifier 系统无法直接实现，应研究 variable、event、dynamic modifier 或其他脚本模拟方案。这些仅为候选研究路径，不表示已经确认可行或选定方案。

兼容性是研究边界：不要为了实现乘算而破坏兼容性或大量硬改原版系统。

## 4. 角色差异与爱缪莎定位

神器使设计不应退化为十个简单的“+X%”领袖。不同神器使应根据人物、神器与职业，拥有不同作用领域；即使属于同一种职业，也应尽量避免完全相同的数值模板。

本阶段不锁定十名神器使的具体职业分配。

爱缪莎的定位尤其特殊：普通神器使代表不同的“可能性”，而她最终的“命运主宰”形态，可以考虑拥有干涉、选择或重新组织这些可能性的能力。

因此，爱缪莎未来应优先与“可能性体系本身”发生交互，而非简单成为数值最大的神器使。具体交互、解锁条件、成本和限制均留待后续设计。

## 5. 后期力量承接、巨构与性能

后期神器使文明可能拥有非常高的经济、科研和军事效率，必须有相应后期内容承接这些力量。巨构应纳入这一统一方向，但本文不锁定具体巨构名单、能力或数值。

即使经济极高，也不应主要通过无限增加舰船数量释放力量，否则可能首先造成游戏性能问题。后期军事成长应逐渐转向：

- 高质量舰船。
- 神器专属组件。
- 特殊舰船。
- 唯一舰船。
- 巨构能力。
- 特殊战略机制。

后续评估军事成长时，应同时考虑力量表达、游戏机制意义和性能成本。

## 6. 专属终局危机：机制难度与数值倍率

专属终局危机未来应支持玩家自行选择难度。建议将“机制难度”与“纯数值倍率”分开设计，使两者能够独立组合。

### 6.1 暂定机制难度

| 难度 | 设计方向 |
| --- | --- |
| 故事 | 主要用于体验完整剧情，对神器使体系要求较低。 |
| 标准 | 按正常神器使成长路线设计，作为默认体验。 |
| 困难 | 要求玩家已经形成较完整的神器使体系。 |
| 灾厄 | 默认玩家拥有多名高等级神器使、专属科技与巨构。 |
| 无限 | 用于测试完整神器文明的力量上限，不要求严格公平；可以加入完整危机特殊机制及针对神器体系的反制能力。 |

### 6.2 独立数值倍率

可考虑允许玩家独立选择 ×0.5、×1、×2、×5、×10、×25、×50、×100 等倍率。最终档位、倍率及其作用对象以后根据实际测试决定；当前仅记录方向。

组合示例：

- **标准 ×25**：机制正常，但舰队数值极高。
- **无限 ×5**：数值未必达到极端，但拥有完整特殊机制。
- **无限 + 极高倍率**：供极限玩家自行选择。

以上示例不构成最终平衡承诺。

## 7. 阶段式危机与适应机制

高难度危机不应仅通过增加舰船生命、伤害和舰队数量实现。可以研究以下阶段结构：

> 入侵 → 扩张 → 学习 → 适应 → 反制／最终阶段

“学习”与“适应”不要求真正的动态 AI。可以检测玩家若干关键指标、神器使体系发展程度和主要优势方向，由事件系统选择不同强化路线，模拟危机正在适应神器文明。检测指标、强化路线、触发时机和频率尚未确定。

高难度危机可以拥有针对“可能性”的特殊机制，但原则上不要简单粗暴地让神器使能力全部失效。优先考虑局部压制、降低效率、改变战场条件，或迫使玩家调整构筑，使玩家仍能感受到长期培养神器使获得的力量。

## 8. 当前范围与禁止提前实现的事项

当前阶段只记录上述原则，不直接实现代码。暂时不要：

1. 直接实现最终乘算公式。
2. 锁定十名神器使的具体职业分配。
3. 锁定终局危机最终数值。
4. 提前实现“第七日”等尚未正式确定的隐藏终局内容。
5. 为实现这些概念大规模修改原版底层系统。

本文中的计划、建议、候选方案和示例均保留为后续研究方向，不应被当作已实现功能、已验证技术或已锁定数值。

## 9. 后续工作顺序

1. 先完成十名神器使的角色定位与职业设计，明确差异化作用领域。
2. 再进行“可能性乘区”的技术可行性验证。
3. 根据验证结果开展数值模型测试，评估成长曲线、组合收益、成本与机制意义。

后续角色数值、成长、巨构及终局危机设计，统一以本文原则为参考；具体实现与最终参数需另行设计、验证和确定。
