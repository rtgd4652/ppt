# 里程碑一：专属危机可玩

## 1. 已确认范围与当前状态

用户明确批准并要求实施“主线先贯通、机制精简、保留新专属舰与新巨构、按可玩里程碑推进”的计划。本次合并 AWP-06／07：**新的作战旗舰与现场恒定、新的两阶段巨构、有限锚点危机、第十一至十三章及危机唯一结算**。先接通一个真实锚点闭环，再接有限核心目标；最后停在第十四章资格与战后恢复入口。

本授权取代 AWP06-R001 的“科研船恒定＋空间站解析代理、仅隔离样例”方案，并满足该范围的机制审核与实施授权。不再逐包重复请求批准；AWP 编号继续用于内部拆分。旧 Stage 9、旧命运观测塔和旧隔离舰船原型仍不恢复。

当前为 `implementation_in_progress`。本文件记录已授权目标，**不表示下列功能已经实现或游戏验证通过**；实际交付以[项目状态](../PROJECT_STATUS.md)为准。新外观定稿、第十四章以后、其他角色扩展与发布不属于本轮。

## 3. 新专属舰：作战旗舰与现场恒定

- 新增独立舰种、区段与首版固定设计，使用原版模型占位。能够真实战斗，但不能替代普通舰队、现场科研、巨构解析和文明行动。
- 正常剧情准备阶段提供获取入口；同一时间只有一艘。唯一性以路线国家记录与实际实例共同核对，不能仅凭临时目标失效补发。
- 现场恒定要求旗舰实际在目标星系、角色可用及本锚点校准成立；拥有旗舰不能让全部锚点同时稳定。舰船失效或离场时停止现场支撑，显示恢复要求。
- **免费、自动、无限恢复，默认冷却 90 游戏日**。优先采用摧毁后在有效首都重新出现；不重置危机、锚点、已有资料或损失。
- 一次定向游戏验证若表明重现方式不稳定，再用原生失能、冷却、修复恢复。两者都保留唯一实例与剧情进度，不让爱缪莎随舰永久消失。
- 爱缪莎身份与舰船寿命分开，不强制任命她为舰队指挥官。首都或部署条件暂失时保留待恢复状态，条件恢复后继续。
- 首版固定配置不承诺保存任意改装，也不承诺引擎没有可靠接口支持的“绝对禁止合并编队”。

## 4. 新巨构：基址到运行态

新巨构采用独立定义和获取入口，仅**基址 → 运行态**两阶段，使用原版模型占位。它提供现实基线、资料汇总、多区域关联和弱点解析；建成不自动产生战果或结束危机。

运行态可用且真实资料满足时按月累计解析。被占领或失去实际控制时暂停新增解析，已有资料、进度和弱点保留；恢复控制后续接，不重复取证。必须核对原版实际控制关系，不能把科研船项目或空间站代理测试写成真实巨构占领通过。

旗舰与巨构的建设要求先行展示。不可逆锚点预警须明确确认，不能在玩家尚不知建设要求时偷偷消耗最后窗口。无有效建造位置时说明缺口，正常入口可返回准备。

旧塔与旧舰只保留旧档兼容所需定义；新路线获取入口不发放它们，也不把已有旧资产计作新方案已满足。

## 5. 首个锚点与有限终局

首个宿主先采用可观察、可定向损失的工程资源节点：玩家控制的非首都星系中，已有普通能源或矿物矿藏的无人天体。天体负责定位，宿主是锁定的资源节点。排除殖民地、居住站、考古／异常／特殊剧情目标、稀有与特殊矿藏以及已归档目标。

无合格宿主则说明原因并等待，不凭空生成星球或把首都改为测试场。确认页公开宿主、时间与损失；重开和读档不能重置预警。

正常闭环必须包含：

1. 当前危机三线验证、公开预警和唯一宿主。
2. 新旗舰实际部署与本锚点的现场恒定、校准。
3. 当地材料形成绑定本锚点的无人格敌对投影，普通舰队真实作战；有限生成，不自动补兵、不追踪最后一击。
4. 分别记录现场基线、恒定观测、真实战斗与战后勘查；清除投影不能填满全部资料。
5. 新巨构根据真实资料解析弱点，中断保留累计成果。
6. 文明完成现实解除工程，另行核对爱缪莎局部干涉与未来重开。两项成立才解放并归档。

彻底毁灭只移除预先锁定且仍存在的普通矿藏，记录真实损失；不清空整颗星球矿藏、不删除殖民地。若外部事件改变目标，先核对事实，不伪造本危机损失。剩余投影仍须通过实际作战清理，不能以宿主损失暗中删除敌舰或补记现实战果；清理后才完成归档。后续胜利不恢复矿藏，也不把毁灭改写为解放。

首版为**首个锚点＋最多两个后续核心节点**，逐个活动，不无限刷新。首个闭环后，第十二章结算并开放后续目标；复用弱点与锚点实现，各目标仍需现场校准、实际行动和独立结果。一个样例不能冒充全场危机胜利，也不扩展全银河持续扫描。

只有核心目标都已处理、全部现实载体实际清除、投影停止生成，且爱缪莎独立重开未来，才唯一结算危机。可以取得保留宿主永久损失的胜利；文明清除载体与爱缪莎行动必须分开，毁灭不算解放。局部失败留下损失和压力，单次舰船损失或单锚点失败不直接全局判负。

新状态按实际使用登记，选项执行前重核前置、费用和完成仅一次、读档可续接。不重写已验证的前十章。危机完成不能写玩家最终授权、爱缪莎接受最终身份、30 级达标或完整命运权限。

## 7. 参数与引擎核对

恢复默认 90 游戏日、免费自动；其余数值以真实闭环与可读风险为目标，在实现和界面中一致。预警、恒定窗口、月度压力、项目费用／时长和解析月数须显示或说明，运行后再调平衡，不把旧代理样例参数当发布定值。

使用本机 `F:/steam/steamapps/common/Stellaris/` 的 4.5.1 原版定义核对舰种、区段、设计、巨构阶段、控制关系、舰船摧毁／失能、项目与月度入口。旧版技能样例只供结构参考；原版依据和静态检查不等于运行通过。

先实现新舰／设计、巨构、接口，再接危机对象、项目、章节、本地化与状态表。按依赖分批写入，不同步扩大旧章节和角色成长系统改动。

## 8. 实施顺序与轻量验收

1. 更新授权与状态登记，实现新舰、新巨构及正常获取入口。
2. 接通第十一章和一个真实锚点闭环，确认资产、战斗与资料接口协作。
3. 复用闭环接有限核心目标、第十二至十三章和危机唯一结算。
4. 检查新增正常流程及一次关键处理中读档；针对风险检查舰船恢复、巨构暂停／恢复、锚点真实损失。
5. 保存验证、未完成项与续接入口，建立中文提交。不能用静态通过或干净日志代替运行证据。

本批优先保存可通过正常入口进入的完整单锚点闭环。若剩余预算不足，后续核心节点和章节继续标记未完成，保留唯一续接入口，不把单锚点片段记成整个里程碑通过。

前十章和既有证据直接复用，相关代码改变才扩大回归。不每窗另存、逐窗审计或例行计算哈希。控制台建立的战争、天灾或故障场景标为受控来源，不称为自然游玩。

保护 `2217.01.30.sav` 及更早基线，另存分支测试。游戏操作只限群星所在屏幕。用户本晚取消时间限制，但要求注意 token 余量：耗尽前保存有效文件、当前状态、未完成项与下一步，不启动无法安全收尾的扩展。
