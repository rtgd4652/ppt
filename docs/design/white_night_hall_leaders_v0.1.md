# 白夜馆角色实装设计对齐 v0.1

> 本文档只基于 `knowledge/mod_ready/characters/*.mod.md` 的结构化摘要整理，不读取 raw wiki，不作为脚本实现文件。

## 1. 总体设计原则

### 1.1 不做数值膨胀

白夜馆角色第一版不追求“每个角色都强到改变整个帝国曲线”。角色强度应主要来自玩法差异，而不是简单叠加产出、伤害、科研、海军容量等大额修正。

v0.1 的推荐方向：

- 每名角色只给 1 个主要 trait。
- trait 以小幅、清晰、可验证的修正为主。
- 如果角色需要“特殊感”，优先用一次性事件、冷却型法令、通讯选项或条件触发效果体现，而不是永久高额 modifier。
- 所有数值先用保守值占位，实测后再调。

### 1.2 每个角色只保留 1 个核心机制

`mod_ready` 文件中每个角色都能抽出多个方向，例如治疗、输出、控制、空间机动、命运概率、庇护设施等。v0.1 不全部实现，只为每名角色选一个最能代表其神器与能力的机制。

这样做的好处：

- 降低脚本复杂度。
- 避免 7 名角色功能互相重叠。
- 方便后续通过事件链、羁绊等级、神器觉醒再逐步扩展。

### 1.3 第一版优先可实现，不追求完整复刻原作

v0.1 目标是让白夜馆招募池真正跑通：

- 白夜馆通讯中可以招募角色。
- 每名角色只招募一次。
- 每名角色有明确职业与核心 trait。
- trait 效果能在 Stellaris 4.4.3 中稳定生效。
- 不直接复刻原作长篇文本、技能倍率、冷却时间和战斗循环。

原作剧情、羁绊、神器故事、同伴评价先作为后续事件素材，不在 v0.1 一次性展开。

## 3. 单角色设计

### 3.1 安托涅瓦

#### 原作核心要素

- 原作定位：S级 / 巧属性 / 法师 / 法术攻击。
- 神器：方舟・诺亚方舟。
- 能力：自由来往任意空间。
- 摘要中可转化方向包括空间机动、跃迁、闪避、紧急撤离、庇护、人口保护、危机生存机制。

#### Stellaris 转化方向

安托涅瓦不应只是科研加成角色。她的核心应是“方舟式空间庇护”：在探索、危机和舰队撤离中提供安全感。

v0.1 先把她定位为科学家，承载空间理论、异常研究、神器解析与特殊撤离能力。完整的“方舟避难所”建筑或危机生存系统放到后续版本。

#### 推荐领袖职业

科学家。

#### 推荐 trait 名称

`trait_leader_aemod_antoneva_ark_pathfinder`

中文名建议：`方舟领航者`。

#### 第一版效果草案

作为科学家时：

- 小幅提高异常现象研究速度。
- 小幅提高考古或星系调查相关效率。
- 所在舰队获得更可靠的撤离/生存倾向，表现为闪避、紧急撤离或舰船脱战相关的小幅修正，具体可按脚本可用 modifier 确认。

可选轻量事件：

- 首次招募后触发“方舟坐标校准”通讯，给予一次短期探索修正。

#### 暂不实现内容

- 不做全帝国瞬移。
- 不做无条件舰队保命。
- 不做完整方舟避难所建筑链。
- 不做长篇回忆或神器故事事件链。

#### 人工确认事项

- 科学家 trait 是否能稳定影响舰队撤离类效果。
- 如果撤离类 modifier 不稳定，是否改为调查速度、异常研究速度、考古速度三件套。
- 后续“方舟庇护”是建筑、法令还是危机事件。

### 3.2 爱缪莎

#### 原作核心要素

- 原作定位：S级 / 巧属性 / 法师 / 法术攻击。
- 神器：卡牌・塔罗牌。
- 能力：计算内的运气。
- 摘要中可转化方向包括命运、概率、随机事件、抽牌式国家修正、议程或法令。

#### Stellaris 转化方向

爱缪莎的核心不是“更高输出”，而是“可被计算的随机性”。她适合成为白夜馆的命运接口：通过通讯、法令或事件抽取一个短期修正，让玩家感到她在拨动概率。

v0.1 先保留她作为科学家的命运概率机制；已存在的职业切换和高级立绘系统可作为独立线继续维护，不在本文档展开。

#### 推荐领袖职业

科学家。

#### 推荐 trait 名称

`trait_leader_aemod_aemusa_tarot_calculator`

中文名建议：`塔罗演算者`。

#### 第一版效果草案

作为科学家时：

- 小幅提高研究速度或异常研究速度。
- 白夜馆通讯中可触发一次“命运抽牌”短事件，从少量结果中获得一个短期国家修正。

命运抽牌 v0.1 建议只做 3 类结果：

- 星币 / 凝聚力 / 研究三选一短期增益。
- 舰队命中或闪避短期增益。
- 星球稳定度或岗位产出短期增益。

所有结果都应为轻量、可过期效果，避免永久堆叠。

#### 暂不实现内容

- 不做复杂塔罗牌牌库。
- 不做负面抽牌惩罚。
- 不做概率操控全系统。
- 不直接复刻原作技能数值。

#### 人工确认事项

- 命运抽牌入口放在白夜馆通讯，还是保留一个法令快捷入口。
- 抽牌冷却周期。
- 结果是否允许玩家预览。

### 3.3 晏华

#### 原作核心要素

- 原作定位：A级 / 巧属性 / 射手 / 物理攻击。
- 神器：眼睛・荷鲁斯之眼。
- 能力：看穿弱点。
- 摘要中可转化方向包括穿透、伤害、敌方弱点、舰队火力修正。

#### Stellaris 转化方向

晏华适合做“精准打击型指挥官”。他的机制不应是泛用增伤，而应集中在弱点识破：让舰队更擅长命中、破甲或打击关键目标。

v0.1 只做一个稳定的舰队 trait，不额外做事件。

#### 推荐领袖职业

指挥官。

#### 推荐 trait 名称

`trait_leader_aemod_yan_hua_eye_of_horus`

中文名建议：`荷鲁斯之眼`。

#### 第一版效果草案

作为指挥官时：

- 小幅提高舰队命中。
- 小幅提高武器穿透、追踪或暴击感对应效果，具体取决于 Stellaris 可用 modifier。
- 若穿透类 modifier 不易兼容，则改为命中与武器伤害的小幅组合。

#### 暂不实现内容

- 不做单体点杀事件。
- 不做侦察全图。
- 不做永久敌方弱点 debuff。

#### 人工确认事项

- 当前版本可用的舰队命中、追踪、穿透 modifier 名称。
- 是否让晏华成为白夜馆首批偏军事角色之一。

### 3.4 赛斯

#### 原作核心要素

- 原作定位：C级 / 刚属性 / 辅助 / 法术攻击。
- 神器：权杖・羽蛇神杖。
- 能力：实现微小愿望。
- 摘要中可转化方向包括治疗、回复、护盾、防御与支援中枢。

#### Stellaris 转化方向

赛斯的核心是“微小愿望”与稳定支援，不适合做爆发型角色。他可以成为行政官，提供星球层面的温和维护、恢复和秩序支援。

v0.1 让他承担“低强度但很稳”的治理辅助。

#### 推荐领袖职业

行政官。

#### 推荐 trait 名称

`trait_leader_aemod_seth_small_wish`

中文名建议：`微小愿望`。

#### 第一版效果草案

作为行政官时：

- 小幅降低星球维护压力。
- 小幅提高舒适度、稳定度或人口增长相关表现中的一个，不建议三者全给。
- 若要贴近护盾支援，可改为星球防御军或护盾类建筑效果，但 v0.1 建议先走治理稳定路线。

#### 暂不实现内容

- 不做许愿系统。
- 不做复活或大规模治疗。
- 不做复杂支援建筑链。

#### 人工确认事项

- 赛斯作为行政官是否比科学家/指挥官更符合当前白夜馆阵容平衡。
- “微小愿望”是 trait 常驻，还是后续做成通讯小事件。

### 3.5 幽桐

#### 原作核心要素

- 原作定位：A级 / 巧属性 / 射手 / 物理攻击。
- 神器：神弓・甘狄拔。
- 能力：束缚自身。
- 摘要中可转化方向包括输出、舰队火力修正、法令方向。

#### Stellaris 转化方向

幽桐的关键词“束缚自身”很适合转成“以机动性换取精准火力”的舰队风格。这样能和晏华区分：晏华是看穿弱点，幽桐是稳定蓄势射击。

v0.1 只做一个带轻微代价的指挥官 trait。

#### 推荐领袖职业

指挥官。

#### 推荐 trait 名称

`trait_leader_aemod_yuutou_bound_bow`

中文名建议：`自缚神弓`。

#### 第一版效果草案

作为指挥官时：

- 小幅提高舰队武器伤害或射程。
- 小幅降低亚光速速度或闪避，体现“束缚自身”的代价。

如果玩家反馈代价不好用，可在后续改为进入战斗后获得短期火力修正。

#### 暂不实现内容

- 不做复杂蓄力层数。
- 不做战斗中动态切换姿态。
- 不做专属武器部件。

#### 人工确认事项

- 是否接受 v0.1 中出现带负面项的角色 trait。
- 使用“射程”还是“伤害”作为主要正面效果。

### 3.6 拉比

#### 原作核心要素

- 原作定位：A级 / 刚属性 / 战士 / 物理攻击。
- 神器：怪兽・阿米特。
- 能力：分辨善恶。
- 摘要中可转化方向包括治疗、回复、眩晕、控制、输出、空间机动。

#### Stellaris 转化方向

拉比的方向容易发散，所以 v0.1 要抓住“分辨善恶”这一点：将其设计成战场压制与审判型指挥官，而不是治疗、输出、机动全都要。

他的机制可以是对敌方造成轻微控制压制，例如降低敌舰射速、闪避或撤离效率。

#### 推荐领袖职业

指挥官。

#### 推荐 trait 名称

`trait_leader_aemod_rabi_judgement_of_amit`

中文名建议：`阿米特的审判`。

#### 第一版效果草案

作为指挥官时：

- 小幅降低敌方舰队闪避、射速或脱战机会中的一个。
- 可选轻量事件：首次招募后触发“善恶判别”通讯，只给角色设定展示，不给强数值奖励。

#### 暂不实现内容

- 不做道德审判系统。
- 不做复杂敌我识别事件。
- 不同时实现治疗、输出、控制三套能力。

#### 人工确认事项

- 敌方 debuff 用舰队光环、领袖 trait，还是战斗开始事件表达。
- 拉比是否需要专属事件文本强化角色气质。

### 3.7 格蕾莎

#### 原作核心要素

- 原作定位：A级 / 巧属性 / 射手 / 法术攻击。
- 神器：神符・安卡。
- 能力：唤起生命的力量。
- 摘要中可转化方向包括回复、伤害、友方、护盾、庇护与生命力。

#### Stellaris 转化方向

格蕾莎适合作为生命支援型行政官。她与赛斯同样有回复倾向，但赛斯是“微小愿望”的低强度治理支援，格蕾莎应更偏生命维持与人口/岗位恢复。

v0.1 先让她服务于星球民生，而不是舰队治疗。

#### 推荐领袖职业

行政官。

#### 推荐 trait 名称

`trait_leader_aemod_gresa_ankh_lifebringer`

中文名建议：`安卡生命符`。

#### 第一版效果草案

作为行政官时：

- 小幅提高人口增长、宜居度或岗位产出恢复倾向中的一个。
- 可与医疗、生命维持、避难所类建筑在后续版本联动。

v0.1 建议优先选“人口增长或宜居度小幅修正”，避免和赛斯的稳定/舒适度重叠。

#### 暂不实现内容

- 不做星球复活机制。
- 不做死亡人口返还。
- 不做完整生命神符建筑链。

#### 人工确认事项

- 格蕾莎是否定位为行政官，还是保留射手身份改为指挥官。
- “生命力”优先表达为人口增长、宜居度、稳定度，还是舰队恢复。

## 4. 第一版实装范围

### 4.1 进入 v0.1 的内容

v0.1 建议只实现以下内容：

- 白夜馆通讯招募池。
- 7 名角色全部进入白夜馆招募池。
- 每名角色只允许招募一次。
- 每名角色固定一个推荐领袖职业。
- 每名角色 1 个专属 trait。
- 爱缪莎保留一个轻量“命运抽牌”事件或通讯选项。
- 安托涅瓦保留一个轻量“方舟坐标校准”事件或通讯选项。
- 拉比可选一个轻量“善恶判别”展示事件。
- 所有本地化使用中文，并保留中文注释。

### 4.2 暂不进入 v0.1 的内容

以下内容进入后续版本：

- 角色羁绊阶段系统。
- 神器觉醒等级。
- 每名角色多职业切换。
- 多 trait 成长树。
- 长篇剧情事件链。
- 同伴评价驱动的角色关系系统。
- 原作技能循环复刻。
- 图片资源下载与自动处理。
- 专属建筑链、法令链、科技链的深度联动。

### 4.3 后续版本建议

v0.2 可以扩展为：

- 每名角色增加 1 个羁绊事件。
- 爱缪莎塔罗抽牌扩展为小牌库。
- 安托涅瓦方舟机制扩展为星球避难所或危机保护事件。
- 赛斯与格蕾莎分化为“愿望支援”和“生命支援”两条建筑/岗位联动。
- 晏华、幽桐、拉比分化为“弱点识破 / 自缚神弓 / 审判压制”三类舰队风格。

v0.3 以后再考虑：

- 白夜馆声望或好感度。
- 中央庭、神器使组织、黑门相关主线。
- 命运观测塔与角色机制联动。
- 领袖 30 级立绘、神器觉醒立绘和事件演出。
