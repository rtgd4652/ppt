# 《神器使》Stellaris Mod 美术审核清单 v0.1

> 适用范围：立绘、剧情 CG、舰船、巨构、建筑、区划、UI、图标、遗珍、展品、武器与粒子特效。
>
> 审核目标：确认资产既属于同一个“灾后现代幻想星海文明”，又保留角色或功能差异，并能合法、稳定地进入实际游戏制作。

## 1. 审核状态

每轮审核只能使用以下结论：

- **通过**：当前阶段所有必选项通过，可以进入下一阶段；
- **条件通过**：只有不影响下一阶段的明确小项待修，必须记录责任人和截止节点；
- **退回修改**：存在风格、角色识别、可读性或实现问题，退回当前阶段；
- **暂停待证据**：原作事实、参考来源、权利或技术条件不足，不允许模型／画师自行补全；
- **拒绝**：方向违反核心美术定位、存在无法接受的复制／权利风险，或与用途根本不符。

“看起来漂亮”不是通过条件。任何硬性退回项不能用平均分抵消。

## 3. 分级审核流程

### R0｜立项与证据审核

产出：用途说明、资产层级、强度等级、参考 ID、权利边界和制作规格。

- [ ] 资产在游戏中的使用位置和画面尺寸明确；
- [ ] 已确定属于公共文明、神器科技或具体角色层；
- [ ] 已确定 L0–L4 视觉强度，没有默认做成终局；
- [ ] 角色、剧情、神器和组织事实均可追溯到现有知识库或已审核参考；
- [ ] 未确认的角色配色、服装、神器或剧情状态明确标为待核验；
- [ ] 所有参考已登记 `reference_id`，没有使用搜索缩略图代替来源；
- [ ] 输入图、生成服务、第三方素材和输出用途不超出已知许可；
- [ ] 已写出目标资产与参考图之间的创作边界；
- [ ] 已检查废弃／重新分配清单：命运观测塔旧案不得复用，旧 Stage 9 不得以命运之主或爱缪莎专属舰名义进入新方案；
- [ ] 最终格式、分辨率、画幅、透明通道、模型／LOD 或动画需求明确。

**硬性退回**：用途不明；把待审核候选当原作事实；参考来源或 AI 输入权利不明却准备公开生产；没有最终游戏规格。

### R1｜方向、识别与剪影审核

产出：灰度草图、剪影、构图、三视图草案或图标缩略图。

- [ ] 不看颜色和特效仍能判断主体、朝向、功能或角色；
- [ ] 角色脸、发型、体态和核心饰件与已确认锚点一致；
- [ ] 舰船可辨舰首、舰艉、推进端、核心和主要功能块；
- [ ] 巨构有主功能、尺度参照、交通／维护逻辑；
- [ ] 建筑可读入口、服务对象和功能分区；
- [ ] 图标只有一个主语义，缩小后轮廓仍成立；
- [ ] CG 的人物关系、选择因果和视觉焦点先于装饰成立；
- [ ] 没有直接复用《群星》或外部作品的独特轮廓；
- [ ] 个人符号没有越界成为全文明公共装饰；
- [ ] 负形和留白足够，没有依赖碎片数量制造复杂。

**硬性退回**：角色已认不出；删除特效后没有主体；舰船／巨构无法判断朝向或功能；与外部作品独特轮廓高度重合。

### R2｜颜色、材质与光效审核

产出：色稿、材质球／贴图草案、发光分层和效果关键帧。

- [ ] 配色来自 `COLOR_SYSTEM.md` 或角色风格页，并说明每种颜色用途；
- [ ] 中央庭公共色没有被角色签名色吞没；
- [ ] 神器统一来自结构逻辑，不是默认紫色／水晶／圆阵；
- [ ] 金色、白光、玫红和紫色面积符合资产层级；
- [ ] 陶瓷、金属、玻璃、规则核心与旧物材质能被区分；
- [ ] 表面磨损符合使用和维护位置，不是随机噪声；
- [ ] 光源能解释，发光会影响相邻材质，而不是独立贴亮；
- [ ] 常态、警戒、充能、觉醒和终局状态有强度差；
- [ ] UI／图标的类别色、状态色和警戒色不互相冲突；
- [ ] 黑门／异界没有被简化成默认高饱和紫色漩涡。

**硬性退回**：全文明金白神圣化；所有神器紫晶化；普通资产终局化；发光遮掉角色、舰体或 UI 信息。

### R3｜制作可行性审核

产出：生产拆分、模型块、贴图计划、动画／粒子分镜或正式 2D 分层。

- [ ] 已明确实体模型、贴图、着色器、粒子和 UI 分别承担什么；
- [ ] 舰船／巨构有合理主骨架、连接、炮位、推进、碰撞和动画轴；
- [ ] 分离部件数量、功能和锚点明确，不是随机碎片；
- [ ] 能建立 LOD，远景版本不依赖透明小片和微小几何；
- [ ] 贴图尺寸、通道、材质数量和发光面积有预算；
- [ ] 动画周期、旋转轴和展开逻辑可在游戏引擎中实现；
- [ ] 粒子生命周期包含充能、发射、命中、持续、结束；
- [ ] 角色／CG 已为窗口裁切、按钮和文本留出安全区；
- [ ] 图标能转换为目标 DDS／透明规格，边缘和 alpha 可控；
- [ ] 正式制作不会要求复制参考图的受保护主体或纹样。

**硬性退回**：没有实体主结构；无法制作 LOD；炮位／推进／动画逻辑缺失；透明层或粒子必须无限叠加；只能直接使用参考图本体才能完成。

### R4｜游戏内审核

产出：实际游戏截图、不同缩放／分辨率对比、动画录屏和性能记录。

- [ ] 在 Stellaris 常用缩放下仍能识别舰种、朝向、阵营或设施功能；
- [ ] 图标在实际 UI 尺寸下可辨，不依赖提示文字才知道主体；
- [ ] 角色头像裁切不截断眼睛、脸、发型核心或神器媒介；
- [ ] 事件图关键人物和动作不被文本框／按钮遮挡；
- [ ] 特效不长期遮挡目标、舰体、血条、轨道或交互点；
- [ ] 普通、神器、觉醒和终局资产在同屏时仍有清楚层级；
- [ ] 发光在暗／亮星系背景上都不过曝、不消失；
- [ ] 动画速度、环体方向和循环接缝稳定；
- [ ] LOD 切换不突兀，没有明显消失、闪烁或透明排序错误；
- [ ] 帧率、显存、粒子和 draw call 成本符合目标场景；
- [ ] 路径、文件名、DDS、模型、定位器和脚本引用一致；
- [ ] 没有占位图、参考图或未审核文件被意外打包。

**硬性退回**：实际尺度不可读；特效遮屏；LOD／alpha／动画严重错误；未授权参考图进入运行时目录。

### R5｜发布与资产登记审核

产出：正式文件、登记记录、来源链、授权记录和发布包复核。

- [ ] 正式资产已在 `docs/art/ASSET_REGISTRY.csv` 使用唯一 `asset_id` 登记；
- [ ] `source_path`、`mod_path`、制作方式和衍生参考 ID 完整；
- [ ] 原创重绘、重新建模、抽象规律提取和人工修改已说明；
- [ ] 第三方底图、纹理、字体、模型、笔刷、音效和 AI 服务均已记录；
- [ ] 权利状态、公开提交、修改、署名和再分发范围有证据；
- [ ] `art_review_status` 与实际审核结论一致；
- [ ] `game_spec_status` 与实际游戏验证一致；
- [ ] 来源或许可为 `unknown` 的图片本体只在 Git 忽略目录；
- [ ] 发布包不包含 reference library 的本地二进制缓存；
- [ ] 资产预览、说明和生成记录没有把候选图标成原作官方素材；
- [ ] 最终 Git 变更只包含获准提交的正式资产和文档。

**硬性退回**：未登记；权利状态不明；参考图直接进入正式目录；许可或署名义务未落实；审核状态被人为写成通过但无证据。

## 4. 世界观审核

- [ ] 第一印象符合“灾后现代幻想星海文明”，而非纯魔法、宗教神国或普通科幻换皮；
- [ ] 现代城市文明、工程逻辑和人类尺度仍然存在；
- [ ] 灾后痕迹体现修复、连续生活和制度记忆，不是永久废墟滤镜；
- [ ] 神器被表现为可观测、可约束但未被完全理解的规则现象；
- [ ] 神器科技不是传统魔法、灵能或统一水晶矿物；
- [ ] 中央庭公共资产体现治理、救灾、科研、维护与公共责任；
- [ ] 白夜馆只作为功能系统入口，不被画成世界观政治组织；
- [ ] 旧世界回声保留生活性证据、档案感与不确定性；
- [ ] 黑门／异界表现规则不兼容，不与中央庭稳定设备混为一体；
- [ ] 人类仍是刚进入银河的年轻文明，不默认拥有全知或无代价的神级技术。

## 5. 角色审核

- [ ] 角色资料引用对应 `characters/*_STYLE.md` 和已审核原作锚点；
- [ ] 60% 原角色识别／25% 星海升级／15%剧情阶段的优先级成立；
- [ ] 脸型、发型、发色、服装核心、饰件和体态没有被重做；
- [ ] 人物原本气质仍可读，不因飞升而变成泛用神明；
- [ ] 神器媒介和个人符号来源明确，只用于本人；
- [ ] 星海升级是接口、环境、材料和尺度扩展，不是机械化换人设；
- [ ] 主线特殊状态有剧情证据，没有被固定为常态形象；
- [ ] 角色光效没有覆盖面部、手势、神器或情绪；
- [ ] 尚无已审核锚点的角色没有被擅自确定个人配色和符号；
- [ ] 团队画面共享公共背景，但人物签名层彼此可区分。

## 6. 视觉一致性审核

- [ ] 公共工程骨架、接口、信息层级和材质职责与其他项目资产一致；
- [ ] 资产具有自身功能和角色差异，不是机械复制同一模板；
- [ ] 一级剪影、二级功能块、三级贴图细节层级清楚；
- [ ] 色彩承担主体、功能、能源、警戒和角色签名等明确职责；
- [ ] 圆环、悬浮、空间错位和规则核心均有功能，不是统一装饰；
- [ ] 光效密度符合 L0–L4 等级，同屏不会所有物体一样亮；
- [ ] 外部作品只影响抽象结构、材质、构图或技术尺度；
- [ ] 资产放入现有中央庭场景、舰队或 UI 后像同一个 Mod 的内容。

## 7. 缩放与可读性审核

### 角色／CG

- [ ] 缩略图能先看到脸和核心轮廓；
- [ ] 头像裁切能识别发型与关键饰件；
- [ ] 背景不会在小尺寸与人物竞争；
- [ ] 明暗关系在不同界面底色上稳定。

### 舰船／巨构／建筑

- [ ] 远景能用一级轮廓识别；
- [ ] 中景能读功能区和主要发光点；
- [ ] 近景才出现面板线、磨损和小符号；
- [ ] 缩小后粒子不替代实体，透明结构不消失。

### UI／图标

- [ ] 在最终像素尺寸和 100% UI 缩放下可辨；
- [ ] 灰度剪影仍能区分同组图标；
- [ ] 色盲或低饱和情况下不只靠红绿差异；
- [ ] 无微型文字、Logo、过细边线和密集人物群像。

## 8. 制作与性能审核

- [ ] 模型面数、材质槽、贴图和骨骼数量符合资产等级；
- [ ] 可实例化重复模块，没有把重复结构全部做成独立高模；
- [ ] 透明材质和叠层有数量上限及排序方案；
- [ ] 环体与悬浮部件有明确轴、父子层级和停止状态；
- [ ] 炮塔、引擎、灯光、特效与 section 定位点可对应；
- [ ] LOD 保留一级轮廓和核心发光，优先删除三级细节；
- [ ] 粒子有生成率、最大数量、消散和镜头距离降级；
- [ ] 终局资产即使更复杂，也有多人／多舰同屏的性能上限；
- [ ] 2D 资产保留可编辑源文件、分层和导出记录；
- [ ] 正式导出不会覆盖未确认的源文件或把本地参考缓存混入。

## 9. 权利与来源审核

- [ ] 每个参考均有可定位来源和 `reference_id`；
- [ ] `copyright_or_license_status` 没有凭猜测从 `unknown` 改成 `licensed`；
- [ ] `allowed_usage` 与实际查看、上传、改编、提交、发布行为一致；
- [ ] 原作截图和《群星》截图默认只作本地分析与技术参考；
- [ ] 网络图片和外部作品没有被直接复制主体、轮廓、标志和纹样；
- [ ] AI 输入图拥有上传到相应服务的权限；
- [ ] AI 输出服务和模型的使用／再分发条件已记录；
- [ ] 用户提供文件没有仅因“用户提供”就标成 `user_owned`；
- [ ] 所有正式资产拥有独立的 `ASSET_REGISTRY.csv` 记录；
- [ ] 发布前已复核二进制文件、许可文本和署名义务。

## 10. 专项审核补充

### 10.1 舰船

- [ ] 工业与维护逻辑先于角色装饰；
- [ ] 角色符号被转译为一至两个有功能结构；
- [ ] 实体、贴图、粒子分工符合 `CENTRAL_COURT_SHIPS.md`；
- [ ] 武器挂点和推进端不会被个人特效遮挡；
- [ ] 不属于“原版舰换色”或“漂浮碎片集合”。

### 10.2 巨构

- [ ] 主功能从星系视距可辨；
- [ ] 行星、恒星、舰船或交通节点提供尺度参照；
- [ ] 施工、维护、人员和交通逻辑可解释；
- [ ] 动画低频、少轴、可降级；
- [ ] 方舟、命运、异界稳定、博物天枢各自语义没有混用。

### 10.3 武器与特效

- [ ] 充能、发射、命中、持续、结束五阶段完整；
- [ ] 每阶段只有一个主要信息焦点；
- [ ] 普通、神器与终局武器的范围和亮度有明显层级；
- [ ] 颜色由来源和功能决定，不默认紫色；
- [ ] 最长遮挡、残留时间和性能预算已测试。

### 10.4 旧世界／考古／博物天枢

- [ ] 展品仍可看出原用途、年代和生活痕迹；
- [ ] 中央庭框架负责保存与说明，没有把旧物重做成新式装饰；
- [ ] 档案明确标注缺失、冲突和不确定，而不是伪造完整历史；
- [ ] 遗珍不统一成金色宝箱、王冠或通用远古神物；
- [ ] 记忆失真特效不持续破坏文本和 UI 可读性。

## 11. 退回意见写法

退回意见必须指向可执行修改，不写“感觉不对”“不够高级”。推荐格式：

```text
违反规则：A3 个人符号有边界／R1 剪影审核
观察事实：普通中央庭巡洋舰的一级轮廓由三张巨大卡牌组成，删除卡牌后没有主舰体。
影响：把爱缪莎媒介扩大为公共风格，且远景工程结构不可读。
必须修改：恢复连续实体主舰体；卡牌只保留为专属版本充能阶段的短时投影；重新提交灰度远景剪影。
复审材料：正侧顶三视图 + 25% 缩放剪影 + 粒子关闭状态。
```

## 12. 最终发布签核

```text
世界观审核：通过／条件通过／退回／暂停
角色审核：通过／不适用／条件通过／退回／暂停
视觉一致性：通过／条件通过／退回
缩放与游戏内可读性：通过／条件通过／退回
制作与性能：通过／条件通过／退回
来源与权利：通过／退回／暂停
ASSET_REGISTRY 登记：完成／未完成
发布结论：允许提交／仅限本地测试／退回修改／停止使用
审核人：
日期：
备注：
```

只有六项审核均通过、资产登记完成，才能把文件称为“正式可发布资产”。
