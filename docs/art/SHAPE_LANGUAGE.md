# 《神器使》Mod 形状语言规范 v0.1

> 本文从现有参考图库与 Moodboard 中提炼可执行的造型规则。它不授权复制任何参考图，也不把尚未核验的角色外观写成既定事实。总原则见 [ART_BIBLE.md](ART_BIBLE.md)。

## 1. 核心原则

本项目的形状语言服务于“灾后现代幻想星海文明”这一定位。所有资产都应先说明功能、尺度与使用者，再表现神器带来的异常规则。

形状阅读顺序固定为：

1. **一级轮廓**：在缩略图、战略视角或背光剪影中仍能认出资产类别和朝向。
2. **二级功能块**：推进、武器、承重、入口、维护、观测、隔离等功能可以被理解。
3. **三级表面细节**：接缝、纹路、标签、小型传感器和装饰只负责近景信息。

任何三级细节都不得破坏一级轮廓。任何异常结构都必须与可见的工程框架、投射器、稳定器或规则核心建立关系。

## 2. 三层形状体系

### 2.1 中央庭公共工程层

公共资产使用可制造、可维护、可扩建的现代工程形状：

- 长方体、梯形、钝角楔形、分层板件与有限倒角构成主结构。
- 承重骨架、桥接梁、模块接口、检修面和撤离路径清楚可读。
- 大型设施优先使用“中枢体 + 功能支臂 + 外围防护框”，表达协调和治理，不表达礼拜。
- 普通舰船需要明确舰首、舰艉、推进端、主模块区与火力方向。
- 建筑需要让入口、交通、人员尺度、能源供应与维护空间可以被推断。
- 设备重复来自标准模块与装配逻辑，不来自随机复制装饰。

公共工程允许局部不对称，以体现扩建、维修和功能分区；整体重心仍须稳定。

### 2.2 神器工程接口层

神器科技采用三层结构：

1. **外部工程框架**：夹持、供能、屏蔽、观测、隔离和紧急断开。
2. **悬浮或错位接口**：少量偏轴环、稳定片、传感器、薄膜或不共面构件。
3. **规则核心**：面积最小、视觉权重最高、不能被完全解释的对象或空间状态。

推荐体量关系：公共机械结构约 60%–75%，异常承载结构约 15%–30%，纯规则核心约 5%–10%。唯一或终局资产可以提高异常层比例，但不得失去主体结构。

神器异常可通过以下方式表现：

- 构件彼此不完全共面，但仍围绕明确核心。
- 环体不闭合、轴线轻微偏移、镜像关系局部失配。
- 距离、透视或连接关系出现受控的不连续。
- 能量路径沿可读轨道运行，失控时才偏离轨道。
- 核心形状因神器个体而异，不使用一套通用“神器法阵”。

### 2.3 神器使个人签名层

角色和专属资产采用“60% 原角色识别 + 25% 星海文明升级 + 15% 剧情阶段变化”的基准。这里的比例是设计权重，不是像素或面积硬指标。

- 原角色识别层决定外貌、发型、核心服装节奏、神器媒介与气质。
- 星海文明层提供中央庭结构、接口、材料、信息界面与尺度升级。
- 剧情层只改变展开程度、损伤、共鸣状态或特殊道具，不抹除人物。

个人符号只能出现在角色、其神器核心、专属舰、专属科技或对应事件中。它不能反向变成中央庭公共纹样。

## 3. 中央庭公共形状词典

### 3.1 推荐形状

| 形状 | 主要含义 | 推荐用法 |
| --- | --- | --- |
| 钝角楔形 | 前进、方向、护导 | 舰首、运输流线、防护分区 |
| 梯形与阶梯面 | 承重、层级、扩建 | 舰体装甲、建筑基座、区划平台 |
| 框架与桥接梁 | 连接、协作、可维护 | 空间站、科研设施、巨构支臂 |
| 包覆壳体 | 防护、隔离、生命支持 | 医疗、避难、危险研究设施 |
| 模块矩形 | 标准化、可替换 | 工业设备、舱体、仓储、UI 卡片 |
| 少量圆角 | 人体接触、安全、公共服务 | 舱门、室内设备、医疗与民用界面 |

### 3.2 圆与环的使用边界

圆环不是本项目的默认高级装饰。它只在下列功能中使用：

- 观测与标定；
- 对接与旋转；
- 隔离与稳定；
- 空间边界或投射；
- 明确属于个人神器的规则接口。

普通住宅、仓库、农场、运输船和基础武器不得无理由增加大型悬浮环。一个资产若移除环体仍不影响功能表达，则应优先移除。

### 3.3 尖角与尖塔的边界

- 尖角用于方向、危险、切入或短暂的规则扰动。
- 普通公共建筑以钝角和稳定基座为主。
- 尖塔不得成为中央庭建筑群的统一天际线。
- 终局资产可以使用少量高耸构件，但必须有观测、通信、投射或结构用途。

## 4. 角色与主题专属形状

### 4.1 爱缪莎

- 主要符号：月牙、稀疏星点、细而有方向的命运轨迹、不完全闭合的环、离散卡牌。
- 人物剪影：金色超长单马尾形成主弧线；轻盈、不对称的礼装形成次轮廓。
- 星海转译：月牙变为翼缘或投射框，轨迹变为粒子路径，卡牌变为有限数量的运算界面。
- 卡牌必须可数、可辨方向，并与手势、核心或目标存在因果关系。
- 禁止把卡牌拼成装甲、把月牙复制到每个部件、或用星月铺满公共设施。

### 4.2 安托涅瓦

- 主要主题：包覆、容纳、安全空腔、缓冲层、门槛与连续空间。
- 结构倾向：外壳保护内部、人类尺度入口、生命支持节点、层层减压或隔离。
- 星海转译：方舟不是一块巨大水晶，而是拥有可进入空间、庇护边界和清楚承载关系的系统。
- 异常表现：空间被柔和折叠、容量超出外形、边界错位但仍保持保护方向。
- 在原作图像核验完成前，不从主题反推具体发型、服装、面部或神器外形。

### 4.3 旧世界回声

- 使用被覆盖标记、重复但略有偏差的框、档案页边、修补结构和生活器物轮廓。
- “历史”由时间层叠与使用痕迹表达，不由统一碎裂、齿轮或金色古董框表达。
- 考古遗物首先是曾被人使用的具体物件，其次才是展品。

### 4.4 黑门、异界与星界间隙

- 重点是规则不兼容：透视失配、边缘不连续、尺度跳变、局部镜像错误和非闭合空间。
- 黑门不固定为圆形紫色虫洞；其外形应由场景中的结构受异常规则影响而产生。
- 异界生态可以破坏中央庭几何秩序，但要保留一处可供玩家比较的正常尺度锚点。

## 5. 按资产类型应用

### 5.1 角色立绘与剧情 CG

- 头部、发型、手势和神器媒介构成第一阅读层。
- 服装大色块和主轮廓先于首饰、纹样和粒子。
- 背景结构负责说明地点与时代，不在人物背后形成同色、同方向的轮廓干扰。
- 普通形态保持完整人物轮廓；觉醒和终局形态通过外层结构、构件展开与背景尺度升级，不重塑基本人体。
- 群像 CG 要用视线、站位和空间层级表达关系，不用统一光圈把所有人神化。

### 5.2 舰船

- LOD2 或战略视角仍须识别舰首、舰艉和一个独特主特征。
- 舰体大板、主脊柱、左右功能区与推进组由真实几何承担。
- 炮塔和定位器服从火力方向，不为凑数均匀铺满舰缘。
- 个人符号只能占据一至两个主焦点；其他区域回到中央庭工程语言。
- 漂浮构件必须有控制来源和稳定关系，不能用碎片替代船体。

### 5.3 建筑与区划

- 建筑图先读出用途，再读出文明风格。
- 入口、道路、能源、物流和人员尺度至少保留两项可见依据。
- 区划强调重复生产或公共空间的规模；唯一神器核心不应复制成整片城市。
- 低级建筑采用 L0–L1 视觉强度，高级研究设施最多 L2；只有唯一建筑或剧情状态进入 L3–L4。

### 5.4 巨构

- 先建立主天体、轨道、核心设施或星系之间的比例，再添加环体与装饰。
- 一级结构负责远景识别，二级模块说明建造与维护，三级特效表现运行状态。
- 方舟类强调内部容量与保护边界；命运类强调观测环、轨迹与判定节点；异界稳定类强调正常框架压制不兼容空间；博物天枢强调档案、展示、交通与公共访问。
- 巨构不能只靠“更大、更亮、更多环”表达高级。

### 5.5 UI 与图标

- 图标采用“一个主轮廓 + 一个功能焦点 + 一个状态强调”。
- 负形必须在 64 px 尺寸可读；16–32 px 只要求保留类别与焦点。
- 线条粗细和圆角半径在同一图标族中保持一致。
- 个人符号只用于对应角色条目，公共 UI 使用中央庭框架与功能符号。

### 5.6 武器与粒子

- 粒子轨迹必须从发射器、规则核心或命中点产生。
- 普通武器使用直线、锥形喷射、短尾迹和清楚命中点。
- 神器武器可引入分叉、折返、错位或延迟残影，但一次只突出一种异常规律。
- 终局特效可扩大空间范围，实体发射者和目标仍须可见。

## 6. 命运之主专属形状边界

命运之主已经进入**从零重设计**状态，本版不批准任何固定远景识别式。旧 Stage 9 的宽阔舰体、中央分段环和双侧月弧不再属于命运之主规范。

新方案只受以下通用边界约束：

- 舰首、舰艉、推进、武器与功能模块必须可读；
- 实体模型承担体量和一级轮廓，贴图承担小型表面信息，粒子只承担短时命运现象；
- 关闭发光后仍须存在稳定剪影；
- 远景至少保留三个清楚大形状，但具体形状必须由全新灰模比较确定；
- 展开状态（如有）必须改变功能或结构，不能只增加亮度；
- LOD 保留顺序必须在新方案批准后重新编制，不能沿用旧 Stage 9。

旧舰体只作为 Blender、LOD、PDX 导出和游戏内尺度的技术样本，等待改作其他舰种。

## 7. 建模与 LOD 规则

### 7.1 模型、贴图与粒子分工

- **模型**：一级轮廓、承重、厚度、主模块、可动件、炮塔座、环体骨架。
- **贴图/法线**：面板接缝、刻度、微型接口、小型纹路、表面方向。
- **发光/粒子**：短时能量、星轨、扫描、开火、命中、相位错位和展开状态。

不得用法线假装关键轮廓，也不得把静态装饰都做成持续粒子。

### 7.2 LOD 保留顺序

1. 主剪影和朝向；
2. 唯一主特征；
3. 主要功能模块；
4. 大色块和发光节点；
5. 二级面板；
6. 微小纹样与装饰。

### 7.3 可实现性检查

- 可动构件必须有轴心、行程、锁定与安全间隙。
- 悬浮构件必须有父节点、动画逻辑和远景简化方案。
- 重复模块优先使用镜像、阵列、实例或共用贴图。
- 不制作依赖大量透明面层叠才能成立的主轮廓。
- 若概念图无法拆为实体、贴图、粒子三部分，应退回重新设计。

## 8. 反向形状规范

以下造型不能作为项目公共语言：

- 所有资产默认使用巨大圆环、尖塔和漂浮碎片。
- 用塔罗牌、月牙或某一神器的符号覆盖公共舰船和建筑。
- 把普通《群星》人类舰船换色后增加几条发光线。
- 每个面都切碎，战略缩放后只剩噪声。
- 没有入口、推进、承重、维护和人员尺度的概念雕塑。
- 把所有高阶结构做成金白宗教神殿。
- 用透明层和粒子代替应该由实体模型承担的体量。

## 9. 当前待确认

- 司篁原作视觉锚点按计划延后；埃索林与塞拉菲姆正在建立独立锚点；里见茜等待剧情梳理后另行核验。
- 中央庭公共舰船家族仍需一张经过审核的正交比例校准板。
- 黑门与异界已建立第一版正式对照组，但各剧情规模、各异界生态与动态仍需逐图补充。
- 命运观测塔旧“太阳冠/神圣未来科技”方案已经废弃；未来必须从零建立新概念，不能继续校准旧案。
- 命运之主没有批准的新版剪影，旧 Stage 9 不得作为造型锚点。
