# 《群星》UI 与图标实现参考

## 文档用途

本页学习《群星》事件、科技、飞升、遗珍、特质、决议和舰船部件图标的游戏内构图、尺寸与状态表现。它负责回答“如何在《群星》中读得清”，不负责决定本 Mod 的最终视觉主题。

## 当前仓库审计

- `mod/gfx/interface/icons/` 已包含科技、飞升、传统、建筑、区划、陆军、法令、起源、决议和舰船部件等正式 PNG/DDS。
- 本地审计到的 PNG 目标尺寸以 128×128 与 58×58 为主，另有 32、48、64 像素输出；这说明必须按实际使用位置分别检查，而不能假设单一母版自动适配。
- `tools/build/icon_generation/generate_artifact_icons.py` 通过高对比剪影、有限调色板与统一几何语言生成图标，是当前项目实现基线，不是《群星》原版参考。
- `assets/ui/white_night_pavilion/` 与 `mod/gfx/event_pictures/` 提供项目自制事件图和角色入口，属于工作源/正式输出，不应混入《群星》参考分类。
- 审计范围内未发现独立整理的原版 UI 或图标参考集。

## 必收参考组

- 科技：普通、稀有、危险、重复科技及不同学科。
- 飞升与传统：树根、节点、完成状态和路径差异。
- 遗珍与特质：单体物件/头像级符号如何在小框内成立。
- 区划、建筑、决议、法令和起源：功能语义与稀有度层级。
- 舰船部件：武器、防御、核心、传感器、推进与战斗电脑。
- 事件窗口：图片安全区、标题/正文/选项关系、锁定与条件提示。

## 可学习内容

- 一级主体占画面的大致比例、边框留白和视觉重心。
- 同系列如何共享框架而靠主体轮廓、光源与色相区分。
- 稀有度、不可用、选中、升级和危险状态如何附着，不破坏主体。
- 图标在深色 UI、鼠标悬停、压缩与不同缩放下的对比。
- 事件图如何为正文和选项保留安静区域。

## 不可直接复制

- 原版图标主体、完整构图、阵营徽记、边框纹样与贴图。
- 将原版阵营色直接定义为本 Mod 中央庭或神器技术色。
- 仅给原版图标换色、叠加星月/卡牌后作为正式资产。
- 把所有科技与部件都套在同一圆环、同一水晶和同一辉光模板中。
- 在小图标中依赖文字或极细线解释语义。

## 本项目的图标层级

- 公共系统层：中央庭、城市、研究、物流与危机协调，结构清楚、发光克制。
- 神器技术层：加入规则核心、悬浮结构和能量纹路，但仍以功能主体为第一阅读层。
- 角色专属层：只在爱缪莎、安托涅瓦等专属玩法中使用个人符号。
- 终局层：允许更高对比和展开结构，但不得让普通设施显得与终局同级。
- 旧世界层：档案、遗物和记忆失真应保持低饱和，与当前生成图标的高亮体系拉开差异。

## 尺寸与验证

- 每个正式图标至少检查母版、实际 UI 尺寸与 DDS 版本。
- 关闭发光或转为灰度时，主体仍应可辨；否则说明语义过度依赖色彩。
- 相邻十个图标并排检查重复轮廓，避免“换色同图”。
- 在色觉差异和低亮度显示下验证危险、可用与锁定状态。
- 事件图需在实际窗口覆盖层下检查安全区，不能只展示无遮挡原画。

## 性能与实现限制

- 图标本身性能压力较小，但不应生成无用的大型二进制副本或大量近似变体。
- 保留可编辑源与导出规则，PNG 用于审阅，DDS 按游戏要求进入正式资产路径。
- UI 动画、粒子或大面积透明层只在确有交互价值时使用；普通列表不使用持续动态效果。

## 登记建议

参考条目必须写明使用位置、原始显示尺寸、截取状态和主要用途。把“《群星》图标”标为技术/构图参考，而不是风格主锚点；任何阵营专属内容都要在 `what_not_to_copy` 中列明。
