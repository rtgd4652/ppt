# 《群星》舰船实现参考

## 文档用途

本页只学习《群星》在战略缩放下的舰船可读性、模块拼接、材质、定位器和性能尺度，不把任何原版阵营的造型直接当成本 Mod 最终风格。

## 当前仓库审计

- `assets/ai_generated/destiny_lord/` 已有旧 Stage 9 舰体从 blockout、LOD、UV、材质到 PDX 导出的完整工作文件和预览。这是项目自制的技术过程；2026-07-22 起不再代表命运之主，等待改作其他舰船。
- `mod/gfx/models/ships/destiny_lord/` 已有三段 `.mesh`、贴图与实体定义，属于正式资产库。
- 模型注册采用舰艏、舰体、舰艉三段拼装并统一缩放；实体定义中已有核心、环形灯和推进器定位器。这些内容可作为当前实现基线，不可作为来源授权证明。
- 源资产 README 记录了 LOD0 22k–30k、LOD1 7k–10k、LOD2 1.5k–3k 三角面目标；仍需以实测与当前导出文件核验，不能只凭计划文档判定达标。
- 当前审计范围内没有独立保存的《群星》普通舰船、泰坦、主宰或巨像截图集。

## 必收参考组

### 普通舰船远景剪影

收集护卫舰、驱逐舰、巡洋舰、战列舰等在相同缩放与相近背景下的截图，重点分析：

- 舰首方向是否一眼可读。
- 主体质量与翼、鳍、环、桅杆等次级轮廓的比例。
- 同一船级家族如何共享特征而保持尺寸差异。
- 战略缩放时哪些细节消失，哪些发光和负空间仍存在。

### 大型与唯一舰船

收集泰坦、主宰、巨像及事件唯一舰等，重点学习：

- 大型舰通过长度、垂直高度、留白和节奏建立尺度，而不只是等比放大。
- 核心装置、主炮和指挥结构如何形成一级、二级、三级视觉焦点。
- 英雄单位与普通舰队同屏时如何保持身份但不遮挡战场信息。

### Section 与模块结构

参考应覆盖舰艏/核心/舰艉或其他 section 的拼接方式、武器槽与实物结构关系、碰撞和定位器布局。学习的是模块边界、接口和技术约束，不能复制某原版阵营的舰体板件、炮塔或引擎形状。

### 材质、贴图与发光

重点记录：

- diffuse/basecolor、normal、specular 与 emissive/粒子各承担什么信息。
- 深色舰体如何在黑色宇宙中用边缘、反射和局部发光保持可读。
- 发光面积和亮度如何随船级变化，而不是所有表面都点亮。
- 贴图分辨率、UV 密度与镜像/复用策略。

### 武器与定位器

需要截取开火前、开火、弹道、命中四个状态，并标记炮口、炮塔、核心、推进器、机库和特效定位器。参考的目标是让游戏效果从正确位置产生，不是复制原版武器外形。

## 转译到本项目

以下是从《群星》实现参考中可学习、但必须重新设计的内容：

- 中央庭普通舰船：公共工程骨架、可靠装甲与有限神器节点为主，个人神器符号为辅。
- 未来命运之主：从零建立剪影候选；月牙、星轨和卡牌只能在新概念中按功能重新论证，不能从旧 Stage 9 直接继承。
- 安托涅瓦路线舰船：强调包覆、空间容纳与安全航道；与爱缪莎的轨迹/干涉路线保持功能性差异。
- 所有专属舰仍要共享必要的中央庭制造、接口和识别元素，避免像来自完全无关的文明。

## 游戏内可读性检查

- 用灰色纯色材质先验证正视、侧视、俯视与常用三分之四视角的轮廓。
- 在近景、中距离、舰队远景和战略缩放四档截图；只在 Blender 近景好看不算通过。
- 舰首、推进方向、主武器方向和舰体重心不能相互矛盾。
- 细部不能依赖 1–2 像素的高频纹路；小尺寸消失的装饰应转为法线或删除。
- 发光不得填平负空间或让多个舰段在远景粘成一团。

## 性能与实现限制

- LOD 预算需按项目实测重新批准；重复炮塔、灯具和装甲节点优先实例化或烘焙。
- 透明环、粒子卡和多层辉光会显著增加过度绘制，只在英雄核心与状态变化处使用。
- locator 数量应服务实际武器、推进与演出，不为不可见细节无限增加。
- section 拼装必须验证原点、比例、姿态、死亡状态与部件缺失情况，避免只在完整舰体下正确。
- 正式贴图、mesh 和 entity 定义只能从正式资产库加载；参考图库不得成为运行时依赖。

## 登记建议

每组《群星》参考至少标明版本、船级/对象、阵营或包、拍摄缩放、视角和用途。`what_to_learn` 应使用“远景轮廓、模块接口、贴图分工、定位器反馈”等技术语言；`what_not_to_copy` 应明确列出阵营专属舰首、装甲纹样、徽记、炮塔和色彩组合。
