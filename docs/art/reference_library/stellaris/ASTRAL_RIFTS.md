# 《群星》星界间隙与异界场景实现参考

## 文档用途

本页学习星界间隙、裂隙入口、异界环境与规则异常在《群星》中的尺度、构图和技术表现，并为黑门与异界生态建立“可比较但不混同”的实现依据。

## 当前仓库审计

- 总设计已规划黑门异常、污染、怪物、灾害与银河级危机，但没有专门的星界间隙截图或视频索引。
- 旧 Stage 9 舰体目前使用冷蓝原版粒子作为实现占位／依赖，不构成星界间隙风格参考，也不构成未来命运之主视觉参考。
- 正式图标中已有黑门观测、黑门护盾和抑制光环等主题，但这些图标不能代替空间场景、生态与动态参考。
- 当前审计未发现独立保存的《群星》星界间隙或虚境视觉资料。

## 必收参考组

- 裂隙入口的星系远景、靠近、穿越和关闭状态。
- 异界内部的地平线、尺度参照、可通行区域与危险边界。
- 空间折叠、透视错位、重复结构、重力异常与规则不连续。
- 异界生态、非生物结构、漂浮物、能量流和环境粒子。
- UI 中的进入提示、风险、阶段、选择与退出反馈。
- 《群星》虚境紫色场景，用作“需要主动区分”的技术比较参考，而非本项目主锚点。

## 可学习内容

- 在远景先提供一个清晰入口轮廓，再用局部畸变提示其内部规则。
- 用尺度参照物、视差和遮挡建立空间，而不是只靠满屏噪声。
- 颜色、几何、运动和声音应共同表达规则差异；单一紫色不足以区分异界类型。
- 路径、危险区和交互目标必须在复杂背景中保持可读。
- 场景可按稳定、扰动、失控和关闭分级，控制视觉强度与玩法状态一致。

## 黑门与星界间隙的关系

- 可共享：入口边界、空间折叠、规则不兼容、环境响应、观测与隔离技术。
- 必须区分：黑门在原作世界观中的灾害语义、污染/怪物关系和城市记忆，不等同于《群星》任意裂隙。
- 黑门不应默认使用虚境式高饱和紫、闪电云和灵能符文。
- 星界间隙参考主要回答“在《群星》里怎样呈现和交互”，原作黑门参考回答“它在本项目中是什么”。

## 外观方向

- 优先尝试空间切面、局部失焦、错位星场、运动方向冲突和材质法则变化。
- 异界生态应有生存逻辑与层级，避免随机触手、眼睛、水晶和碎石混合。
- 工程设施通过锚定框架、观测阵列、隔离层和救援通道与异常形成对比。
- 不同异界区域可改变形状、运动或明暗关系，但仍使用一套可识别的危险信息系统。

## 不可直接复制

- 原版星界间隙、虚境或危机场景的纹理、结构、色彩序列和事件图。
- 其他作品标志性的不可能空间、传送门、异界生物和符文。
- 把画面复杂度本身当作“规则不兼容”，导致玩家找不到入口和目标。
- 让所有黑门、神器、命运和记忆主题共享同一紫色旋涡。

## 性能与实现限制

- 大面积半透明、折射、多层雾和长寿命粒子需要严格预算，并提供减少层数与关闭动态折射的降级方案。
- 动态噪声和空间错位要控制频率，避免镜头移动时产生闪烁、眩晕或压缩噪点。
- 异界背景、入口效果和交互目标分层制作，便于按距离与状态关闭。
- 多个裂隙同星系或舰队大规模进入时必须进行最坏情形测试。
- UI 文字与选择区不能被持续闪光、强对比边缘或随机粒子遮挡。

## 登记建议

参考条目注明场景类型、入口/内部/退出状态、缩放、动态时间点和实现用途。与 `OTHERWORLD_AND_ASTRAL_RIFTS` Moodboard 关联时，应明确“可共享规律”和“必须区别于虚境/其他作品的部分”。

## 参考层与正式资产边界

原版裂隙截图、录屏与技术观察只属于参考层，不能直接复制成黑门背景、粒子或纹理。项目正式场景必须重新设计，并在 `ASSET_REGISTRY.csv` 记录原创重绘/重建、抽象规律提取和授权审核结果。
