# 原作 UI、图标与字体氛围参考

## 文档用途

本页用于分析原作的界面层级、框架、图标语义、字体氛围和动效节奏。原作 UI 参考负责保持世界观辨识，《群星》UI 参考负责保证落地方式；两者不可混为一套直接复制的界面皮肤。

## 当前仓库审计

- `assets/ui/white_night_pavilion/` 包含项目生成的白夜馆背景、势力图标和生成脚本，是项目自制工作源，不是原作 UI 参考。
- `mod/interface/*.gfx`、`mod/gfx/interface/icons/` 与 `mod/gfx/event_pictures/` 已经是游戏正式资源或正式接口定义，不能登记成参考图以规避资产审核。
- `tools/build/icon_generation/` 维护 128×128 图标生成源与预览；当前正式输出还包含 32、48、58、64 和 128 像素等多种尺寸。这些可用于复盘可读性，但不证明原作 UI 的来源。
- 当前审计未发现已整理的原作界面截图、原作图标全集或字体授权记录。

## 必收分类

- 主菜单、角色档案、通讯、战斗、养成与剧情选项界面。
- 角色、神器、技能、属性、状态与机构图标。
- 标题字、正文字、数字、标签、提示与危险警告的层级关系。
- 面板边框、卡片、分页、选中态、锁定态、禁用态和进度反馈。
- 黑门、记忆、危机和觉醒等特殊状态下的界面变化。

## 可学习内容

- 信息优先级：玩家第一眼看到什么、第二步操作在哪里、危险如何被强调。
- 图标语义：主体剪影、内部符号、状态色与背景框分别承担什么信息。
- 角色气质：角色专属页面可借用个人色与符号，但公共系统仍保持中央庭体系。
- 字体氛围：字重、字距、数字风格、标题与正文对比，而不是未经授权复制字体文件。
- 动效节奏：出现、锁定、解锁、警报、选中与技能就绪的持续时间和强弱关系。

## 不可直接复制

- 原作界面的完整布局、按钮图形、纹章、像素级边框和整套图标。
- 无许可的字体文件、字体描边效果或商业字库衍生文件。
- 将原作触屏布局原样移入《群星》桌面界面。
- 把角色专属卡牌、神器或色彩用作所有建筑、科技和舰队的公共导航符号。
- 只为“像原作”而牺牲《群星》事件窗口的正文可读性和交互安全区。

## 登记要求

每个 UI 参考条目应注明：

- 所属界面与版本、分辨率、语言和状态。
- 参考的是布局、图标轮廓、色彩、字体氛围还是动效关键帧。
- 是否包含角色立绘、付费皮肤或第三方联动素材；若包含，需要分别处理来源边界。
- 目标适配位置，例如事件图、法令图标、科技图标、白夜馆卡片或状态徽记。
- 在《群星》目标尺寸下应保留的一级信息，以及必须删除的细节。

## 与现有实现的对齐

- 现有白夜馆生成脚本使用暗紫灯箱、青绿/金/紫等强调色，并为事件正文预留压暗安全区。它应作为待评审的“项目实现样本”，而不是原作锚点。
- 现有图标生成脚本强调高对比剪影和青绿辉光，适合用作小尺寸可读性基线；后续参考选择应检验语义差异，而不是继续为所有主题叠加相同圆环与辉光。
- 原作页面中的色彩与装饰进入项目时，应先经过 `CENTRAL_COURT`、角色 Moodboard 或专题 Moodboard 的约束，防止个人页面风格吞没公共 UI。

## 字体与本地化

- 参考截图只用于分析字体气质，不代表项目拥有字体授权。
- 正式界面必须使用可分发字体或依赖游戏已有字体，并验证简体中文常用字、标点、数字和英文缩写。
- 小尺寸测试至少覆盖 100% 与常见 UI 缩放；不能只在原图尺寸判断笔画清晰度。
- 文字不得烘焙进通用背景图，确需图中文字时必须保留可编辑源与本地化替代方案。

## 从参考到正式资产

从原作 UI 中提取的抽象规律，例如“角色卡上重下轻”“危险用断裂边框”“命运状态使用轨迹动效”，应重新设计为项目组件。任何正式 PNG/DDS、字体、GFX 定义或界面脚本都要进入正式资产/实现流程，不能由参考图库直接被游戏调用。
