# 参考素材来源与权利管理规范

## 1. 文档目的

本规范用于管理参考图库中的来源、版权、许可、下载、审核与正式资产转化边界。

参考图库中的条目只说明“项目曾将该素材作为视觉分析依据”，不代表项目拥有原图版权，也不代表原图可以被公开再分发、修改后再分发或直接放入 Mod。

本项目允许联网检索和下载参考素材，但必须把以下三件事严格区分：

1. **可以在浏览器中查看或下载到本地**；
2. **可以把来源链接、文件名和视觉分析写入 Git**；
3. **可以把图片本体或衍生资产公开提交、打包和再分发**。

第一项成立，不代表第二项或第三项自动成立。

## 2. 目录与 Git 边界

### 2.1 可提交到 Git 的内容

- 公开页面的来源链接与定位信息；
- 图片标题、作者、发布日期、访问日期等事实性元数据；
- 项目成员自行撰写的视觉分析、标签、Moodboard 结论与反面参考说明；
- 已确认可公开再分发的项目原创素材、公共领域素材或有明确许可的素材；
- 不包含受限图片本体的索引、清单和校验报告。

### 2.2 只能保存在本地、不提交到 Git 的内容

以下图片即使已成功下载，也只能存入被 Git 忽略的本地目录 `art/reference_library/`：

- 版权或再分发状态为 `unknown` 的图片；
- 标记为 `external_reference_only` 的外部作品；
- 没有明确公开再分发许可的原作立绘、觉醒立绘、皮肤、剧情 CG、UI 截图与游戏截图；
- 网络搜集的建筑、舰船、材质、天文仪器、工业设计和特效参考；
- 仅获得“可查看、可下载或可用于私人研究”许可，而没有获得公开再分发许可的素材；
- 尚未完成来源和权利审核的临时下载文件。

这些文件不得复制到 `assets/`、`mod/gfx/`、`mod/interface/`、`mod/models/` 或其他会被 Git 跟踪、被 Mod 打包的目录。

### 2.3 下载行为不改变版权状态

- 下载成功不等于获得授权；
- 页面允许右键保存不等于允许再分发；
- 搜索引擎能够显示缩略图不等于缩略图可进入仓库；
- 标注作者或来源不等于取得使用许可；
- 对图片进行裁切、调色、描边、AI 重绘或格式转换，不会自动消除原作品的权利限制；
- 用户提供本地文件只证明项目能够访问该文件，不自动证明项目拥有公开再分发权。

## 3. `copyright_or_license_status` 字段

`REFERENCE_MANIFEST.csv` 中的 `copyright_or_license_status` 必须使用以下状态之一。状态必须由证据支持；无法确认时一律使用 `unknown`。

### `user_owned`

用户明确确认自己拥有该素材的相关权利。

- 仍需单独记录是否允许公开提交和再分发；
- “用户提供了文件”不能自动写为 `user_owned`；
- 如果确认范围只包括项目内部使用，`allowed_usage` 也必须反映这一限制。

### `project_created`

由本项目成员自行绘制、建模、拍摄或生成的素材。

- 必须记录创作方式、作者或生成来源；
- 使用第三方底图、模型、纹理、字体、笔刷、AI 模型或训练服务时，应继续核查其许可；
- `project_created` 不自动等于可以不受限制地公开再分发。

### `official_game_reference`

来自《永远的 7 日之都》《群星》或其他官方游戏内容的参考图、截图、宣传图或界面记录。

- 默认只用于本地视觉研究与来源索引；
- 不得因为是“官方素材”就误标为项目正式资产；
- 除非另有明确许可，图片本体不得提交到公开参考图库或正式 Mod 资产目录。

### `public_domain`

已有可信证据证明素材处于公共领域。

- 必须保存证据链接、声明文本、适用司法辖区或权利到期依据；
- 无法核实的“无版权图片”网站描述不能单独作为充分证据；
- 即使属于公共领域，也应保留作者与来源信息。

### `licensed`

素材附有允许本项目相应使用方式的明确许可。

- 必须记录许可名称、版本、来源页面和必要的署名要求；
- 必须确认许可是否允许修改、商业/非商业使用与再分发；
- 如果许可只允许参考或内部使用，则不得把 `allowed_usage` 写成正式资产可用。

### `external_reference_only`

来自外部作品，只用于学习结构、材质、构图、色彩、光影或动态规律。

- 图片本体默认只保存在本地忽略目录；
- 不得直接复制角色、舰船、标志、独特轮廓或其他可识别设计；
- 该状态本身就是“不作为正式资产来源”的边界声明。

### `unknown`

来源、作者、许可或再分发权限中至少一项无法确认。

- 这是默认保守状态；
- 只允许本地保存和内部分析；
- 不得提交图片本体，不得进入正式资产，不得自动升级为 `licensed`；
- 只有补齐可核验的权利证据后才能变更状态。

## 4. `allowed_usage` 字段

`allowed_usage` 应使用下列值之一；如确有复合用途，可用分号分隔，但每项都必须有证据支持。

### `metadata_only`

只允许在仓库中保存来源定位、事实性元数据和项目分析，不保存图片本体。

### `local_reference_analysis_only`

允许在本地忽略目录保存图片并进行视觉分析，不允许提交、打包或公开再分发。

### `abstract_visual_guidance_only`

只允许提炼抽象规律，例如色彩比例、结构原则、材质关系或构图节奏；不得复制可识别设计。

### `internal_project_use`

允许项目内部使用，但公开提交、发布包和对外分发仍需另行确认。

### `formal_asset_candidate`

权利证据允许进入正式资产候选流程，但尚未通过美术、技术与发布审核。该状态不等于已经可以放入 Mod。

### `redistribution_under_recorded_license`

允许按已登记许可公开再分发。必须同时记录许可条件、署名要求和衍生作品义务。

### `project_release_allowed`

已确认可作为项目正式资产提交和随 Mod 发布。使用此值前必须完成 `ASSET_REGISTRY.csv` 登记与审核。

### 项目内的更严格用途值

为让索引直接表达“这条记录为什么存在”，当前清单还允许以下比正式发布权限更严格的自描述值：

- `not_available_until_source_review`：仅为待补资料空位，来源审核前不可使用；
- `reference_analysis_only_no_asset_reuse`：只分析外部或官方实现方式，不复用图片、模型或图标资产；
- `reference_analysis_only_no_redistribution_claim`：只进行视觉分析，不对既有本地文件作再分发权声明；
- `project_development_reference`：项目自制的建模、材质或概念过程资料，仅用于继续开发；
- `project_review_and_style_audit`：项目现有正式输出的复盘入口，用于检查一致性，不反向充当来源或授权凭证。

这些值均不能代替 `formal_asset_candidate`、`redistribution_under_recorded_license` 或 `project_release_allowed`。如需进入正式资产流程，仍必须完成 `ASSET_REGISTRY.csv` 审核。

## 5. 来源记录最低要求

每个参考条目至少应记录：

- 稳定且唯一的 `reference_id`；
- 清晰标题和内容类别；
- 来源类型；
- 可定位的来源网址、原文件路径、作品名称或页面名称；
- 获取或访问日期；
- 已知作者、发行方或版权主体；
- 当前版权/许可状态；
- 允许用途；
- 本地缓存路径（如有）；
- 值得学习和不得复制的内容；
- 审核状态与审核备注。

如果来源页面失效，应保留原定位信息并把条目标记为 `source_uncertain`，不得自行补写不存在的许可。

## 6. 审核状态与流程

### 6.1 审核状态

- `unreviewed`：已登记，尚未核查来源、价值和边界；
- `source_uncertain`：来源或权利证据不足，只能本地分析；
- `reviewed`：来源和用途边界已核查，但尚未确定为视觉锚点；
- `approved_anchor`：已批准为主要视觉锚点；
- `supporting`：可作为辅助、技术、材质或构图参考；
- `rejected`：不适合项目，或权利风险无法接受，不再作为正向参考。

### 6.2 推荐流程

1. **登记**：先记录来源与状态，再下载；紧急下载后也必须尽快补登记。
2. **本地隔离**：权利不明文件进入 `art/reference_library/`，确认 Git 不会跟踪。
3. **来源审核**：核对作者、官方页面、许可文本和可使用范围。
4. **视觉审核**：判断其是主要锚点、辅助参考、技术参考还是反面参考。
5. **Moodboard 引用**：Moodboard 只引用已登记的 `reference_id`，并写明学习边界。
6. **正式资产候选**：只有权利与来源明确的条目才能进入候选流程。
7. **资产登记**：任何正式化结果都必须另行登记到 `ASSET_REGISTRY.csv`。
8. **发布复核**：在提交 Git 或制作发布包前，重新检查来源、许可、署名和文件路径。

## 7. 从参考图转为正式资产的门槛

参考图不能直接“改名”或“移动”成正式资产。任何候选资产进入 `assets/` 或 `mod/` 前，必须在 `ASSET_REGISTRY.csv` 中至少说明：

- 正式资产唯一编号与名称；
- 对应的 `reference_id`；
- 创作者与创作日期；
- 是原创重绘、重新建模，还是只提取抽象视觉规律；
- 是否使用了第三方底图、纹理、字体、模型、音效或生成服务；
- 原素材和衍生素材的权利状态；
- 是否允许公开提交、修改和再分发；
- 必需的许可文本与署名信息；
- 美术审核状态；
- 游戏规格适配状态；
- 审核人和人工确认事项。

以下任一情况存在时，不得转为正式资产：

- `copyright_or_license_status = unknown`；
- 仅允许 `metadata_only`、`local_reference_analysis_only` 或 `abstract_visual_guidance_only`；
- 无法解释正式资产与参考图之间的创作差异；
- 仍明显复制其他作品的独特角色、标志、舰船轮廓、纹样或构图；
- 缺少许可证据、署名信息或项目发布授权；
- 尚未通过美术与技术审核。

## 8. 各类素材的默认处理

| 素材类型 | 默认状态 | 默认允许用途 | 图片本体是否进 Git |
| --- | --- | --- | --- |
| 原作角色立绘、皮肤、剧情 CG | `official_game_reference` | `local_reference_analysis_only` | 否，除非有明确再分发许可 |
| 《群星》截图与技术观察图 | `official_game_reference` | `local_reference_analysis_only; abstract_visual_guidance_only` | 否，除非有明确再分发许可 |
| 网络建筑、舰船、材质与工业设计图 | `external_reference_only` 或 `unknown` | `metadata_only; local_reference_analysis_only` | 否 |
| 项目原创概念图、模型预览和 UI 草图 | `project_created` | 依作者确认填写 | 通过审核后可提交 |
| 用户提供但未说明权利的文件 | `unknown` | `local_reference_analysis_only` | 否 |
| 有可核验开放许可的素材 | `licensed` | 按许可逐项填写 | 仅在许可允许且完成登记后 |
| 有可靠证据的公共领域素材 | `public_domain` | 按证据和项目规范填写 | 完成来源登记后可考虑 |

## 9. 禁止事项

- 不得编造作者、来源、许可名称或授权范围；
- 不得把 `unknown` 自动改成 `licensed`；
- 不得因用户说“可以联网下载”而推断“可以公开再分发”；
- 不得把参考图自动复制到正式资产目录；
- 不得把搜索引擎缩略图当作原始来源；
- 不得删除来源信息以规避审核；
- 不得把风格分析写成对具体作品设计的复制指令；
- 不得在未经人工确认时批量提交二进制参考图。

## 10. 人工确认清单

在任何参考图或衍生结果进入 Git 前，至少确认：

- [ ] 来源可定位，作者或权利主体已尽可能记录；
- [ ] `copyright_or_license_status` 有证据支持；
- [ ] `allowed_usage` 没有超出许可范围；
- [ ] 权利不明图片只存在于 Git 忽略目录；
- [ ] 没有把官方游戏参考误当作项目原创资产；
- [ ] 正式资产已经登记到 `ASSET_REGISTRY.csv`；
- [ ] 原创重绘、重新建模或抽象规律提取方式已说明；
- [ ] 署名、许可文本和发布义务已落实；
- [ ] 美术和游戏规格审核已完成；
- [ ] 发布包中不存在未经许可的参考图片本体。
