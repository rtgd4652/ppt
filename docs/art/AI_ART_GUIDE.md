# 《神器使》Stellaris Mod AI 绘图规范 v0.1

> 文档状态：正式工作基线。
>
> 适用范围：角色立绘、剧情 CG、舰船概念图、巨构概念图、建筑与区划概念图、UI／图标草案、武器与粒子特效设计图。
>
> 核心边界：AI 输出是**项目创作过程中的候选方案**，不是原作事实、原作设定证据、已授权素材或可直接进入 Mod 的正式资产。

## 1. 使用原则

1. 先确定资产所属层级：中央庭公共文明、神器科技，或某名神器使个人资产。
2. 先确定视觉强度：日常、公共专业、神器稳定、英雄／觉醒、文明终局。
3. 只使用已有 Art Bible、角色风格页和已审核参考条目中明确的结论；资料缺失时写明“待核验”，不得用模型自行补成原作事实。
4. 提示词必须包含本文件的“项目公共风格段”和“公共禁止段”，再追加资产变量。
5. AI 只负责形成可审核候选图；裁切、重绘、建模、贴图和游戏适配仍需独立制作与审核。
6. 外部图、原作图或本地参考图作为输入前，必须遵守 `reference_library/SOURCE_AND_RIGHTS.md`；能查看或下载不等于允许上传到生成服务、训练、公开提交或再分发。

## 2. 固定项目公共风格段

以后生成任何项目图片，提示词都必须引用以下公共段。可以按语法调整句序，但不得删除其核心判断。

```text
《神器使》Stellaris Mod 的统一公共风格：灾后现代幻想星海文明。画面属于一个经历黑门危机与七日轮回、在中央庭治理下完成重建，并把神器超常规则纳入科学研究、刚刚进入银河的人类文明。以现代城市工程、清楚的结构与接口、可维护的机械逻辑为实体基础；以受控悬浮、规则接口、空间错位和高维信息作为神器科技层；保留日系幻想角色设计的清晰辨识与人性。整体表达理性、秩序、精密、重建和克制的希望，而不是宗教神国、传统魔法世界或普通科幻换色。光效服务状态、能量流向和叙事层级，实体结构、负形和功能分区始终清楚。
```


在发出提示词前，先填写以下简报：

| 字段 | 必填内容 |
| --- | --- |
| 资产 ID／临时编号 | 唯一名称；候选图也应可追踪 |
| 资产类型 | 立绘、CG、舰船、巨构、建筑、图标、特效等 |
| 使用位置 | 通讯、事件、科技、星系视图、舰船设计器等 |
| 所属层级 | 公共文明／神器科技／角色个人 |
| 强度等级 | L0 日常至 L4 文明终局 |
| 事实来源 | Art Bible、角色页、已审核 `reference_id` |
| 不确定项 | 明确留白，不让模型自行确定 |
| 输出规格 | 画幅、视角、透明背景、是否需三视图等 |
| 实现方式 | 2D 正式图候选／3D 建模参考／粒子分镜／UI 草案 |
| 权利边界 | 输入图能否上传、输出能否进入正式资产候选流程 |

## 5. 角色变量的使用边界

- 爱缪莎、安托涅瓦等已有角色页时，必须直接引用对应 `characters/*_STYLE.md`；不要仅凭角色名让模型“自由发挥”。
- 司篁的原作视觉锚点按计划延期，只能先做不涉及个人外貌的构图、公共背景或材质实验。
- 埃索林与塞拉菲姆必须分别引用各自角色页和已登记的页面级原作来源锚点；这些锚点不足以支持模型自行补全高清外貌或个人色，不得因师生、继任或世界管理关系互换外貌、符号与配色。
- 里见茜是塞拉菲姆放弃神位、失去相关记忆并进入箱庭后的神器使身份，但其视觉锚点在剧情梳理前延期；不得直接把塞拉菲姆神态换装成里见茜。
- 不同神器使可以共享中央庭接口和制造规范，但不得共享彼此的个人符号。
- 终局形态是原角色的发展，不是可复用的“神明皮肤模板”。

### 5.1 已废弃资产的提示词边界

- 命运观测塔旧案已废弃，禁止把旧太阳冠、多层金白环体和旧 Blockout 作为图生图、ControlNet 或构图参考。
- 旧 Stage 9 舰体已退出命运之主身份，禁止把其预览、深度图、线稿、三视图或模型截图用于“新版命运之主”生成。
- 两个对象重设计时只能从已批准公共风格、角色原作锚点、功能清单和全新灰度候选开始；相似度评审必须主动检查是否无意复现旧案。

## 6. 候选图迭代规则

建议每轮只解决一类问题：

1. **灰度轮廓轮**：确认构图、剪影、负形和视觉焦点；
2. **结构轮**：确认功能块、角色识别、实体／贴图／粒子分工；
3. **配色轮**：按 `COLOR_SYSTEM.md` 确认颜色职责和面积；
4. **材质轮**：按 `MATERIAL_GUIDE.md` 区分装甲、玻璃、规则核心和磨损；
5. **实现轮**：输出三视图、分层、动画阶段或图标小尺寸验证；
6. **发布候选轮**：完成来源、生成服务、模型／版本、提示词、人工修改和权利审核记录。

不要在一轮提示词中同时要求重做角色、舰体、配色、背景和特效；无法判断哪项变化有效的候选图不适合作为锚点。

## 7. 生成记录与权利管理

每个进入项目评审的 AI 候选至少记录：

- 临时资产 ID、日期、操作者和用途；
- 使用的生成服务、模型与版本；
- 完整提示词、公共段版本、随机种子（如可获得）；
- 所有输入图及其 `reference_id`、来源和是否允许上传到第三方服务；
- 后期重绘、合成、裁切和人工修改说明；
- 输出服务条款、发布／再分发状态和待确认事项；
- 美术审核、技术审核与游戏内验证状态。

以下情况不得进入正式资产目录：

- 输入参考无权上传到生成服务；
- 输出权利、再分发范围或第三方元素来源不清；
- 明显复制原作或外部作品的可识别构图、角色、舰船、标志或纹样；
- 只有 AI 候选图，没有人工结构核验和游戏规格适配；
- 尚未在 `docs/art/ASSET_REGISTRY.csv` 登记。

## 8. AI 输出的事实边界

- AI 图不能证明角色原作服装、神器形态、配色或剧情状态；这些事实只能来自经审核资料。
- AI 图不能反向把候选设计写入世界观、角色档案或剧情圣经。
- “项目生成”只说明产生方式，不自动等于原创无争议、已授权或可公开再分发。

- 未通过上述流程的图，只能标记为 `concept_candidate`、`composition_study` 或 `local_reference_analysis_only`，不得称为“官方立绘”“原作形态”或“最终资产”。
