# 开发、测试与交接工作流

生效：2026-10-31，依据用户反馈“测试时间过多”及跨 AI 续接要求。适用于后续工作；历史报告保存事实，旧的逐小包验收顺序不再自动成为继续开发的门槛。

## 内容交付优先

在已确认范围内连续实现相互关联的内容。完成有意义的一组改动后做源码检查，再在可玩阶段集中验收。内部编号用于拆分实现，不意味着每完成一个编号都要重启游戏、补前置、另存和读档。

低风险小包源码检查通过即可继续开发，运行状态如实保留为待验。若下一包依赖尚未证明的关键引擎能力，先验证这个具体依赖，不扩成整包重测。重大剧情变化、正式资产外观和发布范围仍按已有规则与用户讨论。

## 最小检查范围

| 改动 | 开发期通常需要 | 何时进游戏 |
| --- | --- | --- |
| 文档、计划、交接 | 链接、JSON可解析、状态与证据一致、差异检查 | 不需要 |
| 现有结构中的科技、普通组件、建筑数值或文本 | 语法／引用／编码检查；有实际逻辑风险才补定向测试 | 并入阶段试玩，同类抽查，不穷举全部尺寸和重复变体 |
| 新交互流程或共享脚本逻辑 | 针对实际状态变化、费用和重复结算风险的必要检查 | 一条代表正常路径；只有新增保存语义或恢复风险才安排关键读档 |
| 唯一舰恢复、危机推进、结局、奖励持久化 | 关键条件与严重失败点 | 定向验证改动涉及的核心机制；沿用未变化部分的既有证据 |
| 启动崩溃、剧情卡死、无限循环、重复发奖或存档损坏 | 保留错误与起点，修复实际原因 | 修复后一次针对性复查，未解决的阻断问题不能标通过 |

不要为可逆的小改动写重复实现的测试。既有静态和定向检查通过且源码没有变化时直接引用结果；只有新改动、失败或明确未解决的问题才扩大检查。发布前再做一次整体衔接回归。

## 时间预算与退出条件

- 普通阶段试玩以约20分钟为预算，开始前写明目标与结束条件。已得到足够证据就结束，不因为还有时间继续扩测。
- 同一自动操作问题的排障最多10分钟，包括置前、键盘、控件和保存名。到预算后保存具体失败点，将该项列为待验，转回不依赖它的内容开发；不要无限换命令、反复要求用户操作。
- 时间上限不代表测试通过。启动崩溃等阻断问题单列，不能用“预算到了”掩盖；必要的较长专项验收独立安排并说明原因。
- 长期北京时间规则保持：22:30进入收尾，23:00前保存结束。一次临时延长只在用户指定的那次工作有效。

## 测试前置与加速

在当前获准的隔离测试档内，可用控制台补资源（含已授权的 `rr`）、补研究前置、建立所需场景或加速建造。只补本次目标需要的条件，记录实际执行和确认结果；控制台字符串须按本机版本核实。

如果本次要验证的就是排队、付费或等待结算，不能直接写完成标记或用加速跳过该机制后声称正常流程通过。加速来源不构成自然科研、经济平衡或自然战争的证据。切换型作弊需记录最终开关状态，避免污染后续存档。

## 保存、证据与复用

保留起点，阶段结束需要保存时另存一个结果；仅当新增持久状态或严重恢复风险需要时做一次关键读档。普通同类组件不默认逐项读档，不逐窗口存档。

正常日期名可用且未占用时直接另存；不要为了英文自定义档名重复排障。存档位不足时，只无损归档已被完成态取代的自建中间档并记录位置；原始／用户／关键档保留。

报告写实际结果和限制即可：发生了什么、来源是否受控、保存在哪里、还缺什么。文件解析、干净日志与静态通过都不能替代实际运行证明；已通过的运行结果也不因换 AI 自动失效。默认不计算哈希或重复全套审计。

| 状态维度 | 推荐记录 |
| --- | --- |
| 源码 | 未实现／已实现／本次未改 |
| 源码检查 | 未做／通过／失败，并链接结果 |
| 运行 | 待阶段验收／代表范围通过／阻断失败 |
| 来源 | 自然流程／受控前置／加速，说明具体影响 |
| 是否阻塞下一工作 | 是或否；写明真实依赖或严重问题 |

## 额度、上下文与跨 AI 保存

一个自然实现段结束就保存，不把所有记录拖到额度最后。如果能读取剩余额度，约剩15%时停止扩展工作并预留保存；无法读取时明确不知道，依靠工作段、工具警告和用户指令提前收尾。

1. 停止新增操作；对正在运行或结果不明的命令记录真实状态。不要盲目重试、补交旧输入或强杀未保存游戏。
2. 保存实际改动。源码、文档和游戏存档分别说明，不能用“已提交代码”代替“已保存游戏”。
3. 用[交接模板](templates/AI_HANDOFF_TEMPLATE.md)更新根目录 `HANDOFF.md` 的当前摘要；较长证据放在 `reports/`，摘要只保留下一步需要的信息。
4. 同步当前状态、TODO和本次涉及的设计状态。可完成的文档同步在本轮做完，避免同一个功能在不同入口分别写着“通过”和“待验”。
5. 检查差异，只提交本轮文件并使用中文提交信息；不自动包含未跟踪原型、用户改动、缓存、截图或个人配置。不把本地提交说成远端已上传。
6. 最后给用户提交号、保存点和一个明确的下一步。若提交或保存失败，如实记录工作区路径和失败原因。

接手不依赖专属助手记忆、完整聊天或某一家模型的工具名。[HANDOFF](../HANDOFF.md)负责短摘要，[PROJECT_STATUS](PROJECT_STATUS.md)维护当前进度，[AGENT_OPERATIONS](AGENT_OPERATIONS.md)记录已验证入口，历史记录仅在遇到具体问题时查阅。
