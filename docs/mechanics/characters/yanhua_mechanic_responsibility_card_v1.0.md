# 晏华 1.0 态势研判机制责任卡

## 1. 文档目的

本文把已经批准的“行政官／指挥官双职业＋态势研判”转换成 Stellaris 4.4.3 可行性合同。本文不写正式脚本、不设数值，也不重新审核人物设定。

## 2. 上游约束

- 晏华是中央庭战略与情报辅助者，不拥有国家最终决定权。
- 行政官负责收集、整理和核验证据；指挥官负责执行已形成的军事结论。
- 两种职业共享同一人物、同一研判目标、同一证据进度和同一结论。
- 荷鲁斯之眼不是全知、预言、全图侦察或自动正确答案。
- 第一版同时只允许一个主要研判对象和一项主要结论。

## 3. 机制对象与作用域候选

### 3.1 推荐对象

第一版只允许选择一种具有明确持续身份的目标：

- 已接触的外部国家；或
- 由专门事件链登记的重大文明风险。

普通舰船、临时舰队和任意星球不作为第一版主要对象，避免对象频繁销毁、合并或换主造成状态失联。

### 3.2 作用域职责

- 玩家国家：拥有研判账本、阶段、进度、结论和冷却。
- 晏华领袖：拥有唯一人物标记、当前职业与参与资格。
- 研判对象：只承担目标身份和对象仍有效的验证。
- 事件／局势：负责推进流程和显示信息，不成为唯一存档位置。

## 4. 推荐权威账本

采用“国家层权威账本＋领袖层唯一身份＋目标层可清理引用”。

国家账本至少区分：

1. 空闲。
2. 已选择对象。
3. 证据收集中。
4. 证据达到结论门槛。
5. 结论待选择。
6. 对策执行中。
7. 已完成／冷却。
8. 目标失效待清理。

不把进度只保存在晏华当前岗位、舰队或一个全局事件目标中。全局事件目标可用于原型定位，但不得在未验证多国家隔离和失效恢复前成为正式权威账本。

## 5. 职业切换责任

### 5.1 行政官转指挥官

- 切换前安全卸任不兼容岗位。
- 保留当前研判对象、证据进度和已经形成的结论。
- 未形成军事结论时，指挥官可以继续作为人物存在，但不能凭切换直接生成战斗收益。
- 已形成军事结论时，允许进入对应执行阶段。

### 5.2 指挥官转行政官

- 切换前安全离开舰队指挥岗位。
- 保留尚未过期的结论与国家账本。
- 正在执行的舰队对策不得被切换复制；应按已批准规则继续、暂停或终止，具体由隔离原型验证后裁定。

### 5.3 技术候选

优先验证同一领袖实体职业变更。现有 Mod 已对爱缪莎使用职业变更效果，但仍须专项验证：

- 等级和人物标记是否保留。
- 原岗位是否安全释放。
- 职业特质是否合法替换。
- 读档后是否仍为唯一晏华。
- 连续切换是否会刷新或复制结论。

## 6. 推进与结算边界

- 行政记录、外交情报、侦察、异常观测和实际交战只能作为有来源的证据类别，不允许无条件增长。
- 证据达到门槛只开放结论选择，不自动替玩家决定政策、外交或战争。
- 同时只保留一项主要结论；新对象必须等待旧流程结束或按止损规则清理。
- 结论必须有期限或失效条件，不能永久削弱目标。
- 同一证据来源不得因职业切换、读档或重复事件被重复结算。

## 7. 生命周期与失败回退

### 7.1 目标失效

目标国家覆灭、失去接触或不再满足条件时：

- 停止新增证据。
- 取消尚未生效的结论。
- 清理目标引用。
- 保留一条“研判中止”记录，但不退款式复制已消耗成本。

### 7.2 晏华暂时不可用

受伤、被占用或暂时不能任职时，国家账本保留，主动推进暂停；恢复后继续。不能另建第二个晏华绕过暂停。

### 7.3 死亡或解雇

第一版不自动复活或重建晏华。其死亡或合法离队后：

- 停止人物专属推进。
- 清理尚未兑现的个人结论。
- 国家已经通过正常流程获得的历史记录可保留，但不能继续作为晏华能力生效。
- 唯一招募标记仍按角色总规则处理，不因死亡开放无限重复招募。

### 7.4 读档与重复触发

读档后按国家账本恢复阶段，再验证晏华与目标引用。重复入口、重复事件和月度检查只能推进一次，不能重复授予结论或效果。

## 8. 可行性方案

### 8.1 方案 A：国家账本＋同一领袖职业切换（推荐）

优点：最符合已批准的同一人物、共享研判进度和幂等要求；目标或岗位失效时仍可恢复。

风险：需要验证职业变更对岗位、特质、领袖等级、领袖 UI 和存读档的影响。

### 8.2 方案 B：删除并重建不同职业的晏华

优点：每个职业对象结构简单。

风险：容易丢失等级、关系、人物引用和事件状态，也可能绕过唯一招募；不推荐。

### 8.3 方案 C：固定行政官，只用国家模式模拟指挥官

优点：技术风险较低。

风险：无法满足所有神器使都可成为指挥官以及晏华亲自执行军事结论的批准要求；仅可作为原型失败后的降级候选，不能自动采用。

## 9. 最小隔离原型

原型只需要：

1. 创建唯一测试晏华。
2. 在行政官与指挥官之间往返切换。
3. 启动一个虚拟研判对象并推进三个测试阶段。
4. 在每个阶段存档、读档和重复触发。
5. 测试目标失效、晏华受伤／解雇和重复招募。
6. 输出清晰调试提示并检查 `error.log`。

原型不加入正式资源、伤害、情报或外交收益。

## 11. 当前建议

YMR-001～YMR-006 已由用户整体批准。本文允许进入隔离技术原型，但仍不批准正式收益、数值、发布脚本或最终 UI；原型测试结果必须再次提交人工审核。
