# 赛斯 1.0 愿望履责机制责任卡

## 1. 技术目标与硬边界

把“行政官／指挥官双职业＋愿望履责”转换成低频、单目标、可中止的救援状态机。机制处理现实求助及其责任，不实现任意愿望，不复活死亡人口，不恢复已毁灭殖民地或舰船，也不把信仰写成宇宙规律。

## 2. 作用域与目标

- 玩家国家持有唯一求助账本。
- 赛斯领袖保存唯一身份、职业与参与资格。
- 普通求助第一版优先绑定赛斯任职范围内的己方殖民地；没有合适岗位时可由白夜馆／国家入口处理一个事件登记目标。
- 指挥官状态可处理由事件登记的己方舰队救援或灾区护航，但不常驻扫描全银河求救信号。
- 同时只允许一个主要事项；紧急救援是该事项的危机状态，不建立第二套并行机制。

## 3. 权威账本

国家层记录：事项类型、目标、调查阶段、已识别需求、选择路径、已支付成本、责任结果、暂停原因和冷却。

建议阶段：空闲 → 收到求助 → 调查中 → 路径待选 → 履责中 → 完成／次生问题／放弃结算 → 冷却。紧急救援可以把普通事项置为暂停，但救援结束后必须恢复或正式结算原事项。

目标对象只保存参与标记；对象失效后由国家账本执行清理。不得只依赖舰队、星球修正或全局事件目标保存完整流程。

## 4. 双职业切换

- 优先使用同一领袖实体切换行政官／指挥官。
- 切换前安全卸任，保留事项、调查结果、成本与责任记录。
- 行政官状态开放调查、公共资源和长期恢复路径。
- 指挥官状态开放护航、撤离、防护和直接救援路径。
- 切换不能免费完成调查、取消成本、刷新紧急救援或复制完成奖励。
- 若当前事项没有新职业可执行的路径，则事项保留并暂停，不自动改写成另一类任务。

## 5. 紧急救援

- 只由明确灾害或受袭条件触发，不由月度随机扫描无限生成。
- 若已有普通事项，紧急救援暂时占用同一队列并记录原事项暂停状态。
- 救援效果只保护仍存在的对象并改善后续恢复条件，不重建已经毁灭的对象。
- 羽蛇神杖、公共资源与赛斯亲自行动必须保持互补；神器不能替代全部医疗、工程和制度成本。
- 救援结束后进入独立冷却，避免反复切换职业或重开事件连续触发。

## 6. 生命周期与失败回退

- 目标失效：停止推进，结算已付成本和已发生后果，清理目标引用。
- 赛斯暂时不可用：账本保留，普通事项暂停；已经开始的公共救援可由制度完成非神器部分，但不得继续触发赛斯专属效果。
- 死亡或解雇：停止人物专属推进，不自动重建；已投入的公共资源与现实后果保留。
- 主动放弃：必须形成一次明确结算，不能通过放弃重新抽取更便宜任务。
- 读档：恢复国家阶段后验证赛斯、目标和暂停事项；无效引用进入清理。
- 重复事件／月结：每阶段只结算一次，不重复支付或奖励。

## 7. 可行性方案

### 方案 A：国家单队列＋事件目标＋同一领袖切换（推荐）

普通事项和紧急救援共享一套账本，状态可恢复，也能限制高频弹窗与重复结算。

### 方案 B：每颗殖民地各自运行愿望链

容易产生大量并发事项、弹窗和状态清理负担，不符合 1.0 单目标边界。

### 方案 C：把愿望履责压缩成常驻治疗修正

实现简单，但失去调查、选择和承担后果的核心，不采用。

## 8. 最小隔离原型

只验证：唯一赛斯、双职业切换、一个虚拟殖民地求助、调查与路径选择、一次紧急救援暂停／恢复、目标失效、主动放弃、死亡／解雇、存读档和重复触发。原型不提供正式资源、人口、舰队或生态收益。

| 编号 | 审核内容 | 当前建议 | 状态 |
| --- | --- | --- | --- |
| SFM-001 | 作用域与并发 | 国家持有账本；一次一个事项；普通求助优先己方殖民地，救援目标由事件登记 | 已批准 |
| SFM-002 | 权威状态 | 国家保存调查、路径、成本、结果和冷却；目标只保存参与标记 | 已批准 |
| SFM-003 | 职业切换 | 同一赛斯切换，保留事项；职业只改变可执行路径，不复制进度或收益 | 已批准 |
| SFM-004 | 紧急救援 | 与普通事项共享队列；可暂停后恢复；只保护现存对象，不复原毁灭结果 | 已批准 |
| SFM-005 | 生命周期 | 暂时不可用则暂停；死亡／解雇停止专属推进；放弃和失效都必须结算 | 已批准 |
| SFM-006 | 原型范围 | 只验证单队列、调查、切换、救援暂停、失效、读档与幂等 | 已批准 |

## 10. 当前建议

SFM-001～SFM-006 已整体人工批准，允许进入无正式收益的隔离技术原型。原型通过后，调查来源、正式路径、代价、收益和事件文本仍需单独审核，不能因责任卡获批而自动进入正式实现。
