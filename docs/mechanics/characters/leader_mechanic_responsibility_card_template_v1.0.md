# 1.0 神器使领袖机制责任卡模板

## 1. 用途

本模板把已批准的角色叙事设计转换成可验证的 Stellaris 4.4.3 技术合同。责任卡不包含正式数值、最终事件文本、美术或可发布脚本。

适用角色：晏华、安、赛斯、幽桐、拉比、格蕾莎、雯梓、丽。

安托涅瓦使用多职责专项原型；爱缪莎继续使用既有主线、危机、旗舰与锚点专项蓝图，不套用本模板。

## 2. 上游锁定项

- 固定身份与权力边界。
- 已批准职业结构。
- 唯一人物核心机制。
- 1.0 进入范围与明确排除项。
- 角色死亡、解雇、唯一招募与叙事连续性边界。

责任卡不得修改这些上游决定。

## 3. 最小机制合同

每张卡必须回答：

1. 谁发起机制，谁拥有状态？
2. 机制作用于国家、领袖、舰队、星球、外交对象还是事件／局势？
3. 同时允许多少目标与多少进行中项目？
4. 哪一层数据是权威账本？
5. 职业切换、换岗位、受伤、死亡、解雇、失联、读档时怎样处理？
6. 重复触发和重复对象怎样保持幂等？
7. 机制失败、对象消失或条件失效时怎样回退？
8. 哪些内容必须进入隔离原型，哪些仍禁止编码？

## 4. 推荐状态分层

### 4.1 国家层权威账本

保存唯一角色存在状态、机制阶段、当前项目类别、进度、冷却、已获得结论和恢复请求。国家层数据是判定依据，不能把所有状态只绑在易失效的岗位或舰队对象上。

### 4.2 领袖层身份与表现

保存唯一人物标记、职业、人物专属表现和仅随人物存在的临时状态。领袖对象不得成为国家机制唯一的恢复依据。

### 4.3 目标层临时标记

只在确有目标对象时记录项目参与或效果归属。对象销毁、合并、所有权变化或离开作用域时，必须能回到国家账本完成清理。

## 5. 职业切换合同

- 优先验证同一领袖实体执行职业变更，避免通过删除并重建角色实现切换。
- 切换前后必须保留唯一身份、等级、人物关系、核心机制阶段和国家账本。
- 不兼容岗位必须先安全卸任，再变更职业，最后由玩家重新指派。
- 职业专属特质必须验证合法性；不得留下重复、失效或跨职业错误特质。
- 切换不得复制奖励、刷新冷却、清空风险或绕过失败结果。

## 6. 生命周期与失败回退

每张卡必须分别定义：

- 正常完成。
- 玩家主动取消。
- 目标不再有效。
- 领袖切换职业或岗位。
- 领袖受伤、失联、死亡或被解雇。
- 国家覆灭或所有权变化。
- 保存并读取游戏。
- 重复事件、重复点击和月度脉冲。

## 7. 隔离原型门禁

原型只能验证：

- 作用域能否稳定定位。
- 状态能否保存和恢复。
- 职业切换是否保留同一人物。
- 失败和重复触发是否幂等。
- UI 入口是否能够准确显示当前阶段。

原型不得决定正式数值、最终文本、图标、美术、完整平衡或未经批准的新机制。

## 8. 最低测试矩阵

- 新开局首次招募。
- 重复招募阻止。
- 两种职业来回切换。
- 在有效与无效岗位上切换。
- 机制启动、推进、完成、取消和失败。
- 目标消失、换所有者或进入不可用状态。
- 机制各阶段存档并读档。
- 领袖死亡／解雇后的清理。
- 重复事件和月结不重复结算。
- `error.log` 不出现本角色的作用域、无效对象或重复定义错误。

## 9. 审核输出

每张角色责任卡至少产生四项人工决定：

1. 作用域与目标。
2. 权威状态账本。
3. 职业切换与生命周期。
4. 失败回退与原型验收。

四项全部批准后，才能建立隔离技术原型；原型通过后仍需再次审核，才允许进入正式实现。
