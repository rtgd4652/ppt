# 安 1.0 时序学习机制责任卡

## 1. 技术目标与硬边界

把已批准的“行政官／指挥官双职业＋时序学习”转换成可验证状态机。机制记录短时间片带来的经验，不读取旧存档、不复原已销毁对象、不撤销战争、死亡、外交或星球毁灭。

## 2. 作用域与单对象规则

- 玩家国家持有时序学习权威账本。
- 安的领袖对象保存唯一人格标记、职业与参与资格。
- 同时只允许一个记录类别：行政任务或战术目标。
- 第一版不持续绑定易销毁的具体舰船；战术记录优先绑定敌对国家／事件登记目标，行政记录优先绑定事件项目类别。
- 具体对象只作有效性验证，失效后由国家账本清理。

## 3. 状态账本

建议阶段：空闲 → 记录中 → 经验形成 → 经验可应用 → 已应用／冷却；另设目标失效与紧急脱离恢复状态。

- 进度、记录类别、已形成经验、紧急能力可用性与冷却保存在国家层。
- 领袖层只保存安的唯一身份和必要临时表现。
- 经验必须有对象或类别边界，不能变成永久全局克制。
- 重复事件、职业切换和读档不得重复形成经验或刷新冷却。

## 4. 双职业切换

- 优先使用同一领袖实体变更职业。
- 切换前安全卸任不兼容岗位；切换后由玩家重新指派。
- 保留等级、人物标记、记录阶段、经验和冷却。
- 行政记录不能因切换成指挥官自动转化为战斗增益；战术记录也不能自动变成治理收益。
- 切换只改变可执行的应用方式，不复制或重置同一份经验。

## 5. 紧急回溯的可实现表达

第一版采用“事前登记的有限紧急脱离／修正”，不采用对象毁灭后复原：

1. 安或其直接负责对象进入明确危险状态前，必须已有有效时序记录。
2. 满足触发条件时消耗当前记录，进入长恢复期。
3. 技术表现优先使用引擎可稳定支持的脱离、撤退、暂时保护或经验保留。
4. 若对象已经被引擎销毁，不创建无代价复制品，不伪造历史回滚。
5. 正式采用哪一种效果必须由隔离原型和后续数值审核决定。

## 6. 生命周期与失败回退

- 安暂时不可用：保留账本，暂停主动推进。
- 目标失效：中止记录、清理引用；已合法形成且仍适用的类别经验可按审核规则保留一次。
- 安死亡或被解雇：停止人物专属推进，清理未应用记录；不自动复活或重建安。
- 外部控制风险：不得以机制实现恢复任何人对安的所有权；异常控制只可作为需要解除的负面状态。
- 读档：先恢复国家阶段，再验证安与目标；验证失败进入清理状态。
- 重复入口／月结：同一阶段最多结算一次。

## 7. 可行性方案

### 方案 A：国家账本＋同一领袖切换＋事前紧急保护（推荐）

符合人格连续性，避免对象销毁后复制，也能稳定处理存读档。

### 方案 B：为对象创建快照，失败后恢复

需要复制复杂舰队、领袖、设计和状态，容易形成重复对象并违背历史不回滚边界，不采用。

### 方案 C：仅提供普通常驻修正

技术简单，但丢失“记录—学习—修正”的角色闭环，只可作为原型完全失败后的重新设计起点，不能自动采用。

## 8. 最小隔离原型

只验证：唯一安、双职业往返切换、单一虚拟记录、经验形成与一次应用、紧急保护消耗、目标失效、死亡／解雇、存读档和重复触发。原型不提供正式资源、战斗或治理数值。

## 10. 当前建议

ATM-001～ATM-006 已由用户整体批准，允许进入无正式收益的隔离原型。本文编号仅属于安的机制责任卡；后续脚本也应使用独立命名空间与内部前缀。原型测试结果仍须再次提交人工审核。
