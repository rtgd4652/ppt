## 1. 审核目的

本文逐项记录爱缪莎 1.0 主线章节总纲的人工审核结果。

审核完成前：

- 不把总纲状态改为 `approved_for_implementation_design`。
- 不编写事件、危机、局势、特殊项目或机制代码。
- 不创建专属终局天灾的正式身份、国家、舰队或数值。
- 不设计命运主宰的具体游戏效果。
- 不以旧舰船、旧巨构或现有脚本反向决定主线。

## 2. 审核状态

| 状态 | 含义 |
| --- | --- |
| `pending` | 尚未进行人工裁定 |
| `approved` | 按当前内容批准 |
| `approved_with_revision` | 方向批准，但必须完成记录中的文字修订 |
| `rejected` | 当前方案不采用，必须重新提出 |
| `deferred` | 当前保持开放，并记录在决定前禁止写死的边界 |

只有用户的明确回复可以把审核项从 `pending` 改为其他状态。助手的分析、建议和静态检查不能代替人工批准。

## 4. 逐项审核记录

### AMR-001：“序幕 + 六幕”结构及章节数量

**当前状态：**`approved`

**审核范围：**

- 一个序幕。
- 六个正式幕。
- 序章加第一至第十六章。
- 四个原版天灾作为插入第三幕的同级模块，不另占固定编号。

**本项不审核：**

- 失落帝国与四大天灾的固定先后。
- 四大天灾内部顺序。
- 专属终局天灾身份与表现。
- 埃索林和里见茜是否登场。
- 结局分支和具体能力。

**结构摘要：**

1. 序幕：未翻开的牌。
2. 第一幕：文明进入因果。
3. 第二幕：旧日权威的战争。
4. 第三幕：四种终局。
5. 第四幕：终局异常调查。
6. 第五幕：未命名的专属终局天灾。
7. 第六幕：与你谈论未来。

**审核建议：**`approved_with_revision`

建议保留该结构，同时在总纲中统一写成：

> 序幕 + 六幕；序章 + 十六个编号章节；四个顺序待审的原版天灾模块。

这样可以避免把“四个危机模块”误算成四个额外固定章节，也避免把“序幕”误算为六幕之一。

**人工决定：**批准“序幕 + 六幕”总体结构；结构计数统一为“序章 + 十六个编号章节”，四个原版天灾作为第三幕插入模块，不另占固定编号。

**决定日期：**2026-07-25。

**所需修订：**在主线总纲总体结构处补充统一计数说明。

### AMR-002：失落帝国战争是否固定在四大天灾之前

**当前状态：**`approved`

**审核范围：**

- 第二幕是否固定为失落帝国觉醒与战争。
- 第三幕四个原版天灾模块是否只能在第二幕完成后开始。
- 这一顺序是否作为爱缪莎从局部干涉进入文明级共同选择的叙事阶梯。

**本项不审核：**

- 具体是哪一种失落帝国。
- 失落帝国的要求、宣战理由和战争目标。
- 天堂之战是否并入本路线。
- 四大天灾内部顺序。
- 游戏触发条件、存档兼容和后备生成方式。

**方案 A：固定在四大天灾之前。**

- 优点：先用古老文明对年轻文明的政治压迫检验自主选择，再进入灭绝级危机，压力升级清楚。
- 优点：爱缪莎可以先学习把观测纳入外交、战争与公共制度，再在四大天灾中进行银河尺度压力测试。
- 风险：后续实现必须处理失落帝国已被提前消灭、天堂之战以及塞塔娜原版入口兼容。
- 边界：爱缪莎和神器科学只能影响失落帝国如何评估人类，不能成为觉醒或宣战的唯一原因。

**方案 B：只要求发生，不固定在四大天灾之前。**

- 优点：更容易尊重不同存档和《群星》沙盒中的实际发生顺序。
- 风险：第二幕到第三幕的叙事递进会变得不稳定，部分章节必须能够延后或回插。
- 风险：爱缪莎的阶段成长需要额外重排，避免已经经历终局天灾后再回到较低强度的政治压力。

**审核建议：**`approved`

建议采用方案 A，将失落帝国战争固定在四大天灾之前。这里固定的是本主线的叙事门槛，不预设具体失落帝国类型，也不允许用“命运阻挠”覆盖其原有政治和意识形态动机。

**人工决定：**采用方案 A。失落帝国战争固定在四大天灾之前。

**决定日期：**2026-07-25。

**所需修订：**将主线总纲中的该顺序从待审建议改为已批准结构；保留失落帝国原有政治动机以及后续实现兼容问题。

### AMR-003：四大天灾是否采用同级模块、顺序可变

**当前状态：**`pending`

**审核范围：**

- 索林原虫、异次元入侵者、肃正协议与塞塔娜是否作为四个同级模块。
- 四个模块的实际发生顺序是否允许变化。
- 爱缪莎的阶段深化是否按照“已完成危机数量”推进，而不是绑定某一种天灾名称。

**本项不审核：**

- 四个模块各自承担的具体主题。
- 每种天灾的事件接入和触发方式。
- 是否允许并发、间隔多久或如何检测完成。
- 天灾失败、银河被其他势力拯救或玩家未取得最后一击时的机制。

**方案 A：同级模块，顺序可变。**

- 优点：符合《群星》沙盒存档与危机顺序的不确定性。
- 优点：不把某一种原版天灾写成其他天灾的上位版本。
- 优点：爱缪莎的成长由四次银河级压力测试共同形成，而不是按敌人名称领取固定升级。
- 要求：每个模块只提出独立问题和证据；完整阶段结论必须放在四灾全部完成后的共同复盘。

**方案 B：固定四大天灾顺序。**

- 优点：可以为每场危机安排严格递进的角色弧和难度表现。
- 风险：需要选择一条项目正史顺序，并对《群星》实际危机出场逻辑做更强控制。
- 风险：容易把危机顺序误写成宇宙论因果或强弱排名。

**方案 C：部分固定。**

- 例如只规定塞塔娜最后出现，其余三灾顺序可变。
- 优点：能够把最接近终局伦理问题的模块放在最后。
- 风险：仍需额外控制原版顺序，也会削弱四个模块的同级地位。

**审核建议：**`approved`

建议采用方案 A。总纲已经把危机模块改成互相正交的伦理问题与模型压力，并把阶段性完整认识放在第七章，因此顺序变化不会再让爱缪莎提前完成终局成长。

**人工决定：**待填写。

**决定日期：**待填写。

**所需修订：**待填写。

## 5. 审核完成闸门

全部阻塞项完成后，仍需进行一次最终一致性复核：

1. 将人工决定登记到 [`project_editorial_decisions_v0.1.md`](../decisions/project_editorial_decisions_v0.1.md)。
2. 同步修改主线总纲。
3. 同步修改 [`v1.0_narrative_constraints.md`](../../../docs/design/v1.0_narrative_constraints.md)。
4. 检查事实矩阵、宇宙论、详细时间线和角色状态档案。
5. 确认所有拟关闭的开放谜团都有来源或明确的 `mod_design_decision`。
6. 完成相对链接、编码、术语和跨文档一致性检查。
7. 最后才可以把总纲标记为 `approved_for_implementation_design`。

总纲批准只允许进入下一阶段的叙事设计，并不自动批准事件、危机或机制代码。

## 6. 后续阶段顺序

总纲审核完成后，按以下顺序继续：

1. 补齐十名神器使的标准档案和角色职责矩阵。
2. 锁定灾后至 T9 的最低人物连续性与里见茜身份时序。
3. 设计专属终局天灾叙事定义卡。
4. 建立 1.0 真相揭示矩阵。
5. 建立命运主宰能力边界文档。
6. 完成上述设计审核后，才进入事件、危机和机制实现。
