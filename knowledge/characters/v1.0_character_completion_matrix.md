# 1.0 十名神器使完成矩阵

## 1. 文档用途

本文把十名锁定神器使从资料证据到发布验收的工作拆成可独立核验的关卡。它只记录当前状态与下一步，不替代角色 Clean 资料、Mod Ready 摘要、标准角色档案、角色状态档案或游戏内测试报告。

名单由 [`character_roster_v1.0.md`](character_roster_v1.0.md) 与项目编辑决定 `ED-009` 锁定。任何名单变化都必须先形成新的人工决定。

## 2. 状态判定

| 标记 | 含义 |
| --- | --- |
| `完成` | 文件存在，且内容足以支持下一关 |
| `部分` | 已有证据或实现，但仍存在明确缺口 |
| `缺失` | 对应成果尚未建立 |
| `延期` | 已明确不在当前工作阶段完成 |
| `可用` | 已能在游戏内使用，但不代表通过 1.0 全项验收 |
| `未开始` | 尚未进入对应制作或测试 |

## 4. 可直接推进组

以下角色已有 Clean、Mod Ready 与标准角色档案，可以进入职业和单一核心机制的人工审核：

1. 安。
2. 赛斯。
3. 幽桐。
4. 拉比。
5. 格蕾莎。

后续审核必须遵守：

- 每人只批准一个核心机制，不做数值膨胀。
- 职业必须服务角色核心，不能仅按原作战斗分类机械映射。
- 拉比必须额外审核未成年人及阿米特监护／共生关系边界。
- 安的有限回溯、赛斯的微小愿望、幽桐的责任、格蕾莎的生命力量均不得越过标准档案限定。
- 未完成视觉锚点前，不开始正式立绘和个人图标制作。

## 5. 资料阻塞组

### 5.1 雯梓

她已完成独立角色采集、Clean、图片索引、Mod Ready 与标准档案草案。关闭资料阻塞前仍须完成：

1. 人工校订 Clean Markdown 中的基础资料、称号、神器、个人经历和同伴评价。
2. 审核并批准标准角色档案草案。
3. 核对东方古街、地区治理和文化延续在灾后至星际时代的连续性。

### 5.2 里见茜

当前已确认“塞拉菲姆放弃神位并失去相关记忆后，以里见茜身份生活”的项目身份链。里见茜独立采集、Clean、图片索引、Mod Ready 与标准档案草案已经完成；角色页同时明确她并非通常意义上的神器使，而是在实验中获得不完整能力。关闭资料阻塞前必须完成：

1. 人工校订里见茜 Clean 与 Mod Ready 资料，并批准标准档案草案。
2. 审核“异常能力者纳入神器使管理／白夜馆分类”的项目解释，不能抹去原作边界。
3. 明确哪些信息可被里见茜本人、中央庭和玩家在 1.0 开局时知晓。
4. 确认身份转换相对 Stellaris 开局的最低时间顺序。

塞拉菲姆阶段不得作为独立招募角色，也不得把神位权限、完整记忆或原作视觉符号自动继承给里见茜。

## 6. 1.0 共通发布关卡

每名角色都必须依次通过：

1. **证据关**：有可追溯原作资料和人工校订结论。
2. **转化关**：有 Mod Ready 摘要。
3. **设定关**：有标准角色档案，明确历史、神器、叙事与美术边界。
4. **设计关**：人工批准领袖职业与一个核心机制。
5. **美术关**：批准原作视觉锚点和星海时代转译边界。
6. **实现关**：完成白夜馆招募、唯一性、职业、特质、立绘与本地化。
7. **测试关**：通过新开局、读档、重复招募、通讯、等级和 `error.log` 专项测试。

只有七关全部通过，才能把角色标记为“1.0 完成”。“游戏内可用”不能替代前置设定与后续测试。

## 7. 当前执行顺序

1. 人工校订雯梓 Clean 与标准角色档案草案。
2. 人工校订并审核里见茜身份阶段资料与标准档案草案。
3. 审核 [`十人时间连续性草案`](../timeline/v1.0_character_continuity_review_v0.1.md)，关闭雯梓与里见茜的最后两个资料阻塞；其余八人最低连续性已形成可闭合结论。
4. 审核五名新建档案角色的职业与单一核心机制。
5. 完成十人时间连续性终审，并依据 [`1.0 背景准备验收清单`](../../docs/project/v1.0_background_readiness_checklist.md) 关闭背景准备阶段。
6. 背景终审通过后，再进入十人职业与单一核心机制审核，以及爱缪莎主线实现设计。

本顺序不授权提前编写角色脚本、危机机制、舰船数值或巨构代码。
