# 1.0 十名神器使完成矩阵

## 1. 文档用途

本文把十名锁定神器使从资料证据到发布验收的工作拆成可独立核验的关卡。它只记录当前状态与下一步，不替代角色 Clean 资料、Mod Ready 摘要、标准角色档案、角色状态档案或游戏内测试报告。

名单由 [`character_roster_v1.0.md`](character_roster_v1.0.md) 与项目编辑决定 `ED-009`、`ED-064` 锁定。任何名单变化都必须先形成新的人工决定。

## 2. 状态判定

| 标记 | 含义 |
| --- | --- |
| `完成` | 文件存在，且内容足以支持下一关 |
| `部分` | 已有证据或实现，但仍存在明确缺口 |
| `缺失` | 对应成果尚未建立 |
| `延期` | 已明确不在当前工作阶段完成 |
| `可用` | 已能在游戏内使用，但不代表通过 1.0 全项验收 |
| `未开始` | 尚未进入对应制作或测试 |

## 6. 1.0 共通发布关卡

每名角色都必须依次通过：

1. **证据关**：有可追溯原作资料和人工校订结论。
2. **转化关**：有 Mod Ready 摘要。
3. **设定关**：有标准角色档案，明确历史、神器、叙事与美术边界。
4. **设计关**：人工批准领袖职业与一个核心机制。
5. **美术关**：批准原作视觉锚点和星海时代转译边界。
6. **实现关**：完成白夜馆招募、唯一性、职业、特质、立绘与本地化。
7. **测试关**：通过新开局、读档、重复招募、通讯、等级和 `error.log` 专项测试。

只有七关全部通过，才能把角色标记为“1.0 完成”。“游戏内可用”不能替代前置设定与后续测试。

## 7. 当前执行顺序

1. 审核 [`十人时间连续性草案`](../timeline/v1.0_character_continuity_review_v0.1.md)，关闭雯梓与丽的最后两个连续性阻塞；其余八人最低连续性已形成可闭合结论。
2. 审核五名新建档案角色的职业与单一核心机制。
3. 完成十人时间连续性终审，并依据 [`1.0 背景准备验收清单`](../../docs/project/v1.0_background_readiness_checklist.md) 关闭背景准备阶段。
4. 背景终审通过后，再进入十人职业与单一核心机制审核，以及爱缪莎主线实现设计。

本顺序不授权提前编写角色脚本、危机机制、舰船数值或巨构代码。
