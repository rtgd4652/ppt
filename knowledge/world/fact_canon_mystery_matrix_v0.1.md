# 原作事实／项目正史／开放谜团矩阵 v0.1

## 1. 文档目的

本文档用于区分三类容易被混写的知识：

1. **原作事实**：由当前已采集、已整理的原作资料直接支持；
2. **项目正史**：本 Mod 为连接“轮回结束”与 Stellaris 开局而正式采纳的延展；
3. **开放谜团**：来源尚未解释、当前证据不足，或项目有意保留的未知。

本文不是新的终极设定，也不替代 Raw、Clean、人工剧情整理、术语库或各专题圣经。它只回答：“当前能确认到哪一层，哪些内容属于 Mod 决定，哪些地方必须停下推断。”

## 2. 层级、状态与证据规则

### 2.1 知识层级

| 层级 | 含义 | 使用边界 |
| --- | --- | --- |
| `original_fact` | 原作正文、系统文字、角色档案或直接场景明确支持的事实 | 必须保留路线、时代、场景和说话者范围；角色主张不能自动升级为宇宙规律 |
| `project_interpretation` | 项目为整理原作结构而形成的解释 | 必须说明是整理结论；不得伪装成原作术语或原句 |
| `mod_design_decision` | 本 Mod 为后轮回与星际时代正式采用的正史设定 | 只约束本项目；不得反向宣称原作已经发生 |
| `open_mystery` | 尚无充分证据或有意保留的未知 | 只能提出问题、登记假说边界，不得选择唯一答案 |

### 2.2 审核状态

| 状态 | 含义 |
| --- | --- |
| `human_confirmed` | 已完成当前范围内的人工校订，可稳定使用 |
| `under_review` | 已有直接或间接来源，但定义、范围或因果仍需核验 |
| `pending_source_review` | 当前缺少足够直接来源，不能建立稳定定义 |
| `project_defined` | 已由项目明确采纳，只属于 Mod 正史或系统边界 |
| `not_applicable` | 该项在对应层级不存在，例如白夜馆没有世界观谜团 |

### 2.3 证据优先级

1. 已人工校订的系统文字、直接场景和剧情结构；
2. 原作角色资料及具有明确说话者的角色陈述；
3. 项目核心术语库对来源的分层整理；
4. 世界观、神器、组织、时间线和剧情圣经中的 Mod 延展；
5. 设计候选、玩法映射和未来构想。

同一主题出现差异时，上一级证据不自动否定下一级内容，但必须阻止下一级内容冒充原作事实。旧版圣经中的宽泛表述若与新近人工校订的来源边界冲突，以人工校订和核心术语库为准。

## 5. 项目正史的最小闭包

在上述谜团仍开放时，当前 Mod 只需要以下最小正史即可稳定成立：

1. 黑门危机和七日轮回已经发生；
2. 七日轮回已经结束，世界重构不再作为当前日常机制运行；
3. 人类幸存并重新获得连续历史；
4. 中央庭从危机协调结构发展为灾后文明治理核心；
5. 神器使仍是人类，神器现象被纳入科学研究；
6. 人类通过普通科技、神器科学和黑门研究走向星海；
7. Stellaris 开局的人类仍是年轻文明，不掌握黑门、箱庭、世界之主或命运规则的终极答案；
8. 白夜馆只负责玩家功能访问，不进入世界观权力结构。

这一最小闭包可以支撑当前开局，同时为后续主线保留发现、修正和推翻假说的空间。

## 6. 使用与维护规则

### 6.1 新事实进入矩阵

新增原作事实时必须同时记录：

- 来源页面或人工整理文件；
- 场景、路线或角色范围；
- 知识层级；
- 审核状态；
- 能确认什么；
- 不能推出什么。

### 6.2 项目正史发生变化

任何会改变“轮回已经结束”“中央庭治理核心”“人类刚入星海”等基础前提的决定，都必须先登记项目编辑决定，再同步更新本矩阵、相关圣经和核心术语库。

### 6.3 谜团转为答案

开放谜团只有在以下任一条件满足后才能升级：

1. 新的原作直接来源完成采集与人工校订；
2. 项目明确选择一个 Mod 正史答案，并清楚标记为 `mod_design_decision`；
3. 新结论与现有术语、时间线和组织设定完成交叉复核。

“剧情需要”“玩法方便”或“某个假说很合理”不能单独作为升级依据。
